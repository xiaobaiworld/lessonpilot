## 0. 文档定位与权威边界

本文件是学生端的**单一导航与决策入口**，用于在转向老师端平台设计前汇总已经确认的边界。它不复制详细规格，也不把产品化预案误写成当前需求。

来源文档各自负责不同层级：

| 文档 | 权威范围 |
|---|---|
| `doc/requirements.md` | 当前单视频、单老师、本地 Demo 的正式功能与验收标准 |
| `doc/learning-window-standard.md` | 一级学习窗口：尺寸、呈现方式、生命周期、键盘、习题本、AI 问答、证据 |
| `doc/node-content-standard.md` | 装进窗口的节点字段与内容 |
| `doc/design.md` | 当前 Demo 的运行时组件、数据契约与技术边界 |
| `doc/multi-creator-platform.md` | 多创作者、联网分发、授权和 AI 计费的 P2 产品化预案 |

若发生冲突：

1. 当前已实现的 Demo 行为以 `doc/requirements.md` 为准；
2. 学生界面怎么显示、怎么交互以 `doc/learning-window-standard.md` 为准；显示什么内容以 `doc/node-content-standard.md` 为准；
3. 产品化阶段以届时确认后的需求为准，不能直接把预案当实现指令；
4. 本文件只负责指出差异和入口，不创建另一份详细规格。

## 1. 三层范围，不能混在一起

### 1.1 当前第一期 Demo

范围是 `doc/requirements.md` 6.1 节的 S01–S09 与 D01，仍然是：

- 单个指定 B 站视频；
- 单老师、单课程配置；
- 本地配置与 `chrome.storage.local` 会话；
- 不含账号、远程分发、支付和多创作者。

### 1.2 学生宿主边界（2026-08-14 更新，取代原网页优先边界）

学生宿主只有一个：**装了插件的 B 站原页面，PC 浏览器**。content script 与 `<video>` 同文档，因此能读时间、能暂停、能在页面上挂学习窗口。

原 `student-web/` 网页学生入口已删除，不再保留任何形式的网页学生端。理由是定时触发是五类节点的共同前提，不是其中一项能力：重点标注要在那句话出现时标出、老师补充要在那个语境里插入、三种题型要在讲完对应段落时问。跨源 iframe 永远读不到播放时间，所以网页学生端只能演示产品不出售的那个版本。不要以「更轻」「免安装」为理由重新引入。

跨站 B 站 iframe 不是 `PlayerAdapter`。教师端网页里的嵌入播放器只是确认内容的取景器，节点定位的时间真源是导入的字幕文件。不提供 HTML5 文件选择、Object URL、上传或托管来绕过这个问题。

对平台播放器的干预保持最小：只做暂停加自己的 DOM 层，不改倍速、不阻止跳过、不降原声、不改播放器 UI。这是合规底线，不是偏好。

只要课程视频留在 B 站，手机端就不可能。完整排查见 `doc/lessons.md` 2026-08-14 条目。

**L1 网络能力不属于第一期。** 授权码、视频索引、课程包更新和联网报告导出都属于产品化预案。

### 1.3 产品化学生端基线

这是 `doc/multi-creator-platform.md` 中已经形成方案、但尚未进入正式需求和实现的部分：

- 一个学生加入多个老师的课程；
- 授权码兑换为隐藏的设备绑定 token；
- 本地视频索引、课程包缓存与版本更新；
- 会话锁定 `packId`、`authorId`、`version`；
- AI 额度账户与服务端调用；
- 学习报告导出或回传。

### 1.3 后续研究候选

学生个人工具、更多组件属性、语音和词典等能力只进入调研池。没有真实课程或竞品证据前，不进入第一期。

## 2. 四个老师可配置的内容组件族

老师可配置的教学节点是四族：重点提醒、老师补充、互动练习、点评追问。字段、学生展示内容和跨宿主降级以 `doc/node-content-standard.md` 为准。

下面四项是宿主可以施加的**效果与能力**，不是第四套老师可见的节点类型。暂停、遮挡字幕、降原声写在节点的 `effects` 里；题卡作答方式写在 `interaction` 里。

| 宿主能力 | 当前事实 | 可收敛的同族能力 |
|---|---|---|
| 定时覆盖层 | S09 字幕遮挡已实现并有测试 | 遮挡字幕、画面局部、答案或板书 |
| 定时播放行为 | 现有代码只有播放控制 spike；可复用 S03 状态机尚待 Phase 1 实现 | 暂停、区间循环、禁止跳过、变速、自动跳过 |
| 互动题卡 | S04/S05/S06 已定义，渲染器尚未实现 | 判断题、听写题、排序题、匹配题 |
| 定时文本标注 | 候选，由重点提醒 / 老师补充的 `display` 承载 | 补充说明、生词浮层、老师注释、双语字幕 |

历史记录中的「三个组件族已实现」不准确：需求已定义不等于代码已实现。当前可确认已落地的是播放控制 spike 和 S09；题卡、可复用时间节点与会话闭环仍按 `doc/dev-plan.md` Phase 1–4 推进。

架构红线保持不变：

- 课程包只提供经过 schema 校验的数据，宿主提供全部行为；
- 组件类型是平台维护的封闭枚举；
- 不允许创作者注入 HTML、JavaScript 或自由 CSS；
- 新需求先判断能否表达为现有节点族的属性；
- 插件、网页、本地视频 App 可以换播放控制和挂载面，不能各写一套展示内容。

## 4. 产品化学生端的访问与更新

### 4.1 多老师授权

- 学生界面只出现「授权码」，不暴露 token 概念；
- 每位老师一个授权码，兑换后形成按作者隔离的 token；
- 插件提供「我的课程」，用于查看、添加或移除已加入的老师；
- 每次请求只发送当前课程对应的 token；
- token 与 `installId` 绑定，必须同时提供设备解绑或少量设备额度。

同一视频若命中多位老师的课程包，第一版不做选择器，但必须使用稳定规则选定一个包，并记录实际归属。

### 4.2 取数与更新

学生打开视频时按以下顺序处理：

```text
本地视频索引
  -> 当前老师授权状态
  -> 本地课程包缓存与新鲜度
  -> 必要时带 version / ETag 条件请求
  -> 校验课程包
  -> 创建会话并锁定版本
```

三种状态不能混淆：

- 不在索引：零网络、零挂载、零提示；
- 授权有效：正常加载；
- 授权过期：明确提示续期或联系老师，不能伪装成插件故障。

「实时更新」只表示**下次进入视频时获得最新已发布版本**。正在进行的会话不热切换内容。

### 4.3 本地与服务端

本地保存课程包缓存、视频索引、token、`installId`、学习会话和额度显示缓存。服务端保存权威课程版本、授权状态、AI 额度账本、prompt、密钥和用量。

客户端内容无法真正防拷。既定策略是设备绑定、按需下发、可追溯水印和异常检测，不做本地加密、代码混淆或自建 DRM。

## 5. AI 在学生端的位置

### 5.1 AI 只进入需要开放判断的环节

- 选择题、填空题、时间触发、进度计算：本地确定性处理；
- 自由回答：调用 AI；
- 学生总结中的语言建议和老师报告建议：同一会话的一次调用共同产出并缓存。

因此，老师是否加入 AI，等价于是否配置自由回答节点。这是教学选择；老师默认不因启用节点承担用量费用。

### 5.2 调用与安全

```text
插件
  -> 自有后端：鉴权、查额度、限流、组装 prompt、校验结构
  -> 兼容接口层
  -> AI 供应商
```

额度必须在调用前检查。API 密钥和 prompt 模板只放服务端，课程包与页面都不能接触。

### 5.3 统一额度模型

访问授权和 AI 额度是两套账本：

- 授权码：决定学生能访问哪位老师的课程；
- 额度账户码：标识学生跨老师通用的 AI 余额。

额度分三种：

| 类型 | 来源 | 使用范围 |
|---|---|---|
| 试用额度 | 平台在授权码首次兑换时发放 | 跨老师通用 |
| 定向额度 | 老师可选地为自己的课程购买 | 仅该老师课程 |
| 通用额度 | 学生自行充值 | 跨所有老师 |

扣减顺序固定为：**试用额度 → 当前课程定向额度 → 学生通用额度。**

老师的推广动力主要来自「本课包含 AI 反馈」带来的课程溢价，而不是学生充值分成。首充推荐奖励只保留为待验证备选，不按后续消耗返佣。

### 5.4 额度耗尽与 AI 失败

- 保存学生原始回答；
- 明确说明未生成 AI 反馈；
- 允许重试或继续播放；
- 不用固定模板冒充个性化反馈；
- 充值入口是自愿加购，不是阻断课程的付费墙。

学生不充值也必须能看完课程并完成确定性题型。

## 6. 学习证据与学生数据

会话至少需要保留：

- 课程、节点、尝试、原始答案和时间；
- 完成、跳过、客户端不支持三种不同状态；
- `packId`、`authorId`、`version`；
- AI 是否成功、反馈与修改稿。

产品化后的反向数据流仍有一项未决策：

- L1：学生主动导出或发送报告，默认建议；
- L2：自动回传给老师，需要身份、明示同意、删除机制和隐私责任。

L2 未确认前，不能把自动上传写进学生端冻结范围。

## 7. 学生个人学习工具

这类能力由平台统一提供、跨课程使用，不由老师在课程包里配置。

| 候选 | 学习价值 | 当前处理 |
|---|---|---|
| 手工区间复听与快捷键 | 立刻改善视频学习效率 | 产品化优先候选 |
| 生词与表达收藏 | 形成可复习材料和学习证据 | 产品化优先候选 |
| 错题重练 | 基于真实错误再次练习 | 优先调研 |
| 复习本 / 间隔重复 | 抵抗遗忘，形成跨课程积累 | 产品化优先候选 |
| 课程对照资料架 | 把课程、书目、个人笔记放进同一复习上下文 | 调研 |
| 学习记录导出 | 跨课程汇总学习证据 | 产品化候选 |
| 笔记、时间点书签 | 支持复听与复习本闭环 | 产品化候选 |
| 个人学习计划 | 将收藏和错题排入待复习队列 | 复习本稳定后再做 |
| 连续打卡、经验值、排行榜 | B2C 留存机制 | 不直接照搬 |

### 7.1 新增候选：学生自主复听与个人复习空间

学生可以在不依赖老师配置的前提下，对当前视频做轻量的个人学习操作：

- 手工选择当前视频的一段时间区间，重复播放这句话或这一小段；
- 使用快捷键快速回到上一句、重播当前区间、暂停/继续；
- 给时间点加个人书签、笔记或表达收藏；
- 把收藏的句子加入个人复习本，跨课程复习；
- 把自己的错题、收藏和复听片段整理成个人学习计划；
- 可选的徽章、完成记录和复习提醒，但不把它们作为课程访问门槛。

这类功能的关键边界是：平台不替学生猜选哪一句，学生通过时间点和快捷键主动选择；平台只负责低成本地保存、重播和整理。这样它是学习工具，不是未经授权的内容分析。

学生个人复听记录默认只属于学生当前设备或个人空间，不自动进入老师报告。只有学生明确提交某个练习结果或学习报告时，老师才能看到对应证据。

**归属按作者判断，不按功能划分。** 题目、提醒、解释这些是老师或系统提供的内容，不是学生数据，可见性不构成隐私问题。需要学生决定的只有学生自己产生的内容：

| 内容 | 作者 | 老师可见 |
|---|---|---|
| 题目、提醒、文稿、解释、评价方向 | 老师 / 系统 | 是，与隐私无关 |
| 按节点提交的作答 | 学生 | 是。提交本身就是交给老师 |
| 笔记、标签、批注、向 AI 提的问题 | 学生 | 默认否，可主动分享 |
| 书签、复听片段、跨课程收藏 | 学生 | 否 |

完整规则见 `doc/learning-window-standard.md` 12.3。学生用不用习题本，都不改变个人复听和收藏的归属。

### 7.2 免费层与教师付费层

建议采用“学生工具免费、老师交付能力付费”的 B2B2C 结构：

| 层级 | 免费学生工具 | 老师/课程付费能力 |
|---|---|---|
| 观看与复听 | 手工区间复听、快捷键、变速、书签 | 课程节点的自动暂停、区间循环和老师指定重点 |
| 个人积累 | 收藏、复习本、笔记、个人计划、基础徽章 | 课程专属练习、发布版本和模板复用 |
| 互动与反馈 | 完成确定性题目、查看本地反馈 | 题卡编排、老师语音、注意力事件、受控 AI 模板 |
| 学习证据 | 学生自己查看、导出个人记录 | 老师报告、节点完成事实、班级交付与课程分析 |

学生免费工具不应被设计成故意制造依赖的锁定机制。它的商业价值来自三个正向结果：

1. 学生在多个课程中持续使用同一个熟悉的学习工具；
2. 老师购买 LessonPilot 后，自己的课程能进入这套工具并留下学习证据；
3. 学生已经形成个人收藏和复习习惯后，更愿意继续使用接入 LessonPilot 的老师课程。

因此真正的网络效应是“学生工具越有用，老师的课程交付价值越高”，而不是“学生没有付费就不能学习”。

### 7.3 留存机制的安全边界

- 不限制学生复制、导出自己的笔记和复习内容；
- 不用连续打卡中断、羞辱性提示或强制通知制造留存；
- 徽章只做进度反馈，不代表掌握程度；
- 不默认收集学生姓名、观看历史或跨课程身份；
- 需要跨设备同步时，再单独设计账号、同意和删除机制；
- 个人复听数据和老师教学证据分开保存，不能混成通用遥测；
- 学生产生的内容默认私有，提交作答除外；老师看不到浏览行为、停留明细和收藏流水。

### 7.4 免费学生工具的建议顺序

第一批只建立一个可重复使用的最小闭环：

```text
手工选择时间区间
  -> 快捷键重复播放
  -> 收藏句子 / 添加书签
  -> 进入个人复习本
  -> 下次重新听或重新练
```

复习本稳定后，再增加个人学习计划和课程对照资料。徽章最后加入，并且只能对应可验证行为，例如“本周完成 10 次复听”或“按计划复习 3 天”，不能把登录天数包装成学习效果。排行榜默认不做，因为它容易把私人学习行为变成无意义竞争。

优先级首先看能否产出可交付给老师的学习证据。任何长期积累工具进入实现前，都必须同时定义数据保留和淘汰策略。

这些能力不能作为普通题卡属性直接加入。它们会改变权限、隐私和成本模型，必须单独立项。

## 9. 性能、兼容与降级要求

以下是冻结既有范围时必须保留的质量要求，不算新增功能：

- 无关视频尽早退出，不注册 DOM 和时间监听；
- 重量级组件与 CSS 只在课程命中后加载；
- 高频时间回调只做 O(1) 数值判断；
- SPA 跳转彻底清理节点和监听器；
- 课程缓存和会话数据有保留期限与淘汰策略；
- 未知组件类型跳过并继续播放，记录为「客户端不支持」，不能记成学生跳过或完成；
- 网络与 AI 失败都不能破坏原视频播放。

这些要求目前多数只有设计推断，没有完整性能基线，实测清单见 `doc/multi-creator-platform.md` 12.3 节。

## 10. 深入调研计划

### 10.1 判断框架

对每项竞品能力依次判断：

1. 能否用四个组件族的属性表达？
2. 它是老师配置内容、学生个人工具，还是系统基础能力？
3. 是否引入新权限、外部服务、个人数据或持续成本？
4. 是否产生老师可用的学习证据？

调研产出必须是分类后的结论和取舍，不是功能清单。

### 10.2 调研对象

1. **同形态产品优先**：浏览器插件 + 在线视频 + 语言学习，例如 Language Reactor 类产品；
2. **录播课交付平台其次**：关注作业、批改、答疑和报告；
3. **多邻国、新东方等作为跨形态参照**：研究学习机制，但不直接复制其功能。

需要重点回答：

- 是否出现四族无法表达、且确有教学价值的新内容组件？
- 是否出现本文件未覆盖、且能产出学习证据的学生工具？
- 同形态插件如何处理播放器兼容、字幕、查词、收藏和平台升级？
- 哪些能力只在 B2C 或自制内容模式下成立？

## 11. To C 预留与行为数据

### 11.1 产品定位：小 B 优先的 B2B2C

LessonPilot 当前不走独立 To C 产品路线。更准确的定位是：

> 老师是购买者、配置者和交付者；学生是使用者，但不是现阶段的主要获客对象。

相较于直接面向个人学习者的浏览器扩展，这条路径的优势是：

- 老师已有课程、学生和交付关系，平台不需要从零购买学生流量；
- 老师存在课程差异化、批改、答疑和学习证据等明确痛点；
- 老师承担督促和服务，学习效果不完全依赖学生自觉；
- 学生行为可以回到老师的交付流程，形成可收费的商业结果。

To C 能力只做架构预留：跨老师 AI 额度、错题重练、生词收藏和学习档案将来可以成为学生公共能力，但当前不建立独立产品线，不设计免费版 / Pro 版，也不改变现有排期。若以后要开放 To C，必须依据真实的自然使用、留存和付费证据重新立项。

竞争优势也不能建立在「功能想得更全」上。题卡、字幕和 AI 按钮容易复制，真正需要加速积累的是课程改造 SOP、稳定组件 schema、老师交付闭环、真实案例、教学 prompt 与质量基线，以及授权、分发和学习证据体系。

### 11.2 行为数据的两条数据流

行为记录用于回答产品决策，不做无目的的数据囤积。

| 数据流 | 目的 | 典型数据 |
|---|---|---|
| 平台运行分析 | 判断插件是否稳定、哪些能力被使用 | 挂载成功率、节点触发、加载耗时、AI 成功率、插件版本、错误码 |
| 老师学习证据 | 判断学生是否真实观看、理解和练习 | 提交、正确结果、重试、跳过、答题时长、课程完成、报告导出 |

两者必须隔离：平台只分析必要的聚合运行事件；老师只能查看自己课程的数据；原始自由回答属于学习会话内容，不进入通用行为分析事件。

### 11.3 分阶段采集方案

采用已经确认的三阶段方案：

1. **当前 Demo：** 本地记录结构化事件，人工测试时由测试者主动导出；
2. **产品化试用：** 明确告知并取得同意后，匿名上传课程内事件；
3. **机构与跨设备阶段：** 只有 L2 自动回传或学习档案确实需要身份时，才绑定学生账号。

当前不建设遥测平台、统计后台或 BI 系统，但事件结构应从第一期保持稳定，避免以后无法对比历史数据。

第一批事件控制在最小集合：

```text
lesson_started
node_triggered
activity_opened
answer_submitted
activity_retried
activity_skipped
activity_completed
ai_requested
ai_failed
lesson_completed
summary_viewed
report_exported
```

事件公共字段只包含：

- `eventName`、`occurredAt`、`sessionId`；
- `lessonId`、`packId`、`authorId`、`version`；
- `nodeId`、组件类型、耗时与结果；
- 插件版本、视频平台和结构化错误码。

隐私边界：

- 只记录已授权课程内的会话，不记录学生在 B 站的完整观看历史；
- 无课程包的视频不产生远程事件；
- 原始回答、姓名、联系方式和页面内容不放入通用埋点；
- 自动上传必须提供告知、同意、保留期限和删除机制；
- 任何事件在加入前都必须说明它将支持哪一项产品决策。

## 12. 冻结结论与老师端交接

**第一期学生端范围现在可以冻结，不需要等待深入竞品调研完成。**

冻结内容：

- 当前 Demo 仍为 S01–S09 与 D01；
- 四个组件族作为后续需求的归类框架；
- 第一阶段不新增学生个人工具，不引入语音、词典或 TTS；
- 产品化访问、更新、AI 和计费设计作为 P2 预案保留，不提前进入 Phase 1；
- 平台只做 B 站；YouTube 排在 D1 之后；多语言与多地区完全延后，不加 locale/region schema；
- 学生宿主只有装了插件的 B 站原页面（PC 浏览器），无网页学生端、无手机端，见 1.2 节。

深入调研是冻结后的验证工作。新发现默认进入 P1/P2 候选，只有真实课程证据表明 P0 闭环无法成立时，才重新打开第一期范围。

因此，学生端的**范围设计可以视为阶段性固定**，接下来可以开始老师端平台设计；学生端代码实现仍继续按 `doc/dev-plan.md` Phase 1–4 推进，两者不能混为一谈。
