## 0. 实施前置确认

开发前必须把以下真实信息写入实施任务或配置，不得在页面里留下假链接：

1. KnownMap 开发者希望展示的称呼；
2. B 站私信场景下的联系动作：回复当前私信；
3. 微信场景下的联系动作：回复当前微信，或开发者微信号/二维码；
4. 飞书表单公开 URL；
5. 飞书表单是否允许匿名提交，以及提交后由谁查看和回复。

2026-08-19 实施记录：

- 表单标题、说明和 8 个字段已按第 3 节创建；
- 网页入口已拆到 `teacher-web/trial-intake.js`，销售页只保留挂载点；

若第 4 项尚未提供，先完成私信 CTA，表单入口暂不显示；禁止写一个不可用的占位 URL。

## 1. 统一销售承诺与目标老师

文件：

- 修改：`teacher-web/forsales.html`

- 测试：`tests/page-information-architecture.test.js` 或新增 `tests/sales-page-copy.test.js`

文案要求：

- 首屏主标题上方的品牌主张固定为 `让用心抵达，让理解更深。`；
- 统一称呼为“KnownMap 开发者”，移除无定义的“我们”；
- 把“互动改造示例”改为“真实、可运行的智能互动课程试用”；
- 明确老师不必已经在 B 站发布视频，但需要有一节愿意上传到 B 站或已经在 B 站的视频；
- 明确第一阶段是一位老师、一节课程、本机预览，不把多学生报告写成已完成能力；
- 保留“无需重录”的核心价值，但不承诺 AI 评价、正式报告、账号或规模化交付。

建议核心段落：

```text
让用心抵达，让理解更深。

我是 KnownMap 的开发者。
如果你有一节正在使用或准备上传到 B 站的英语录播课，我可以和你一起把它做成一次真实、可运行的智能互动课程试用。
第一次可以由我协助准备字幕、完成配置和安装学生端免费插件；如果你愿意，也可以自己操作工作台。
```

验收：测试能找到身份、真实试用承诺、目标视频条件、PC Chrome 和人工协助说明；页面不得出现“发给我们”或不定义接收人的泛化表达。

## 2. 重做 CTA 与复制话术

文件：

- 修改：`teacher-web/forsales.html`
- 可能修改：页面内联脚本或提取出的销售页脚本
- 测试：`tests/sales-page-copy.test.js`

主 CTA：

- 视觉主按钮文案：`回复我，试一节真实课`；
- 旁文明确：B 站看到页面就回复当前 B 站私信，微信看到页面就回复当前微信；
- 不把按钮伪装成自动发送消息，页面不能代替用户向 B 站或微信发消息。

复制话术：

- 按钮文案改为 `复制试用话术`，明确它只是复制，不是提交；
- 复制内容：

```text
你好，我想用一节真实的英语录播课，做一次可以实际运行的智能互动课程试用。视频目前在 B 站/准备上传到 B 站，我最想解决的教学问题是：____。
```

- 复制成功提示必须说明“已复制，请粘贴到当前 B 站私信或微信”；
- 剪贴板 API 失败时显示同一段可手动复制的文字；
- 不复制个人联系方式、学生信息或完整课程内容。

## 3. 增加飞书极简表单入口

文件：

- 修改：`teacher-web/forsales.html`
- 新增：`teacher-web/trial-intake.js`
- 新增：`doc/trial-intake-form-design.md`
- 测试：`tests/sales-page-copy.test.js` 或页面信息架构测试

表单作为次 CTA，文案建议：

- 按钮：`填写 1 分钟试用信息`；
- 说明：`不方便私信？留下课程情况，我会联系你。`

飞书表单只收集：

1. 怎么称呼；
2. 联系方式（微信优先，可提供其它方式）；
3. 视频状态：已在 B 站 / 准备上传到 B 站 / 需要协助；
4. B 站视频链接（可选）；
5. 最想解决的一个教学问题；
6. 字幕情况：有字幕 / 没有字幕 / 不确定。

在基础信息之后增加一个非必填的产品方向验证问题：

```text
如果课程能根据学生的不同回答，调整后续问题和反馈，这项能力对您有多重要？
```

选项固定为：

- 没有它也可以试用；
- 有帮助，但不是必要条件；
- 非常重要；
- 没有这项能力，我不会使用。

再增加一个非必填开放问题：

```text
您最希望系统根据学生的哪些差异调整教学？
```

这两个问题只用于验证未来需求。表单说明和销售页不得把个性化问题、动态反馈或自适应学习写成当前已经提供的功能；需要提及时必须明确“正在验证，当前试用暂不包含”。

不要在页面内再造一套本地表单，不新增账号、登录、数据库或自建后端。按钮只跳转到开发者提供的真实飞书 URL，并用 `target="_blank"` 或明确返回路径，避免老师丢失销售页。

验收：飞书 URL 缺失时不显示死链接；真实 URL 存在时按钮可访问；页面明确表单用于联系，不声称提交后自动生成课程。

## 4. 解释插件而不制造安全恐惧

文件：

- 修改：`teacher-web/forsales.html`
- 测试：销售文案测试

新增一个短的“试用方式”说明，必须包含：

- 学生端使用 PC Chrome；
- KnownMap 学生端插件免费；
- 插件只用于 KnownMap 工作台和 B 站课程页面；
- 未匹配当前课程的 B 站视频不启动互动；
- 课程和回答保存在本机第一阶段环境，不上传完整字幕；
- 首次安装由 KnownMap 开发者协助；
- 代码可以公开查看（若页面提供代码链接，链接必须指向真实仓库）。

禁止文案：

- “绝对安全”；
- “经过安全认证/审计”（当前没有证据）；
- “不会读取任何浏览器信息”（当前扩展至少有 B 站页面和 storage 权限，不能这样绝对表述）；
- “安装后所有视频都自动支持互动”。

## 6. 目标视频和交付条件说明

文件：

- 修改：`teacher-web/forsales.html`
- 测试：销售页文案测试

在 CTA 附近写清：

- 老师不需要已经在 B 站发布视频；
- 可以提供已经在 B 站的视频，或提供愿意上传到 B 站的一节视频；
- 需要一条视频和对应字幕，字幕可以由 KnownMap 协助准备；
- 第一次试用需要 PC Chrome；
- 老师可以自己配置，也可以由开发者协助。

不要写成“上传视频后立即自动生成课程”，因为字幕取得、核对和首次配置仍允许人工完成。

## 7. 浏览器验证与验收

文件：

- 更新：`tests/page-information-architecture.test.js` 或 `tests/sales-page-copy.test.js`
- 记录：`tests/manual/sales-page-revision-20260816.md`

自动化检查：

- 页面有唯一明确的主 CTA；
- 页面不包含“发给我们”；
- 页面包含开发者身份、B 站/微信联系说明、飞书入口条件和安全边界；
- 页面包含四种正式节点，不出现“老师补充”；
- 学习结果明确为示例、未完成开发；
- 页面不把插件、报告或多学生数据写成已上线能力；
- `navigator.clipboard` 成功和失败提示都包含后续粘贴位置；
- 飞书链接存在时可访问，不存在时无死链接。

人工检查：

1. 在桌面宽度打开页面，首屏能理解目标老师、价值和主动作；
2. 滚到示例区，确认四种节点和视频/B 站关系不产生错误预期；
3. 滚到 CTA，确认只需回复私信或填写极简表单，不要求注册；
4. 点击复制话术，确认文本进入剪贴板且提示明确；
5. 在 375px 宽度检查 CTA、说明和表格没有遮挡或横向溢出；
6. 检查 iframe、外链和控制台错误，记录 B 站播放器自身错误与页面错误的区别。
