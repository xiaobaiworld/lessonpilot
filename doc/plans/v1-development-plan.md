## 1. 实施原则

- 先建立 v1 真源、契约和空库初始化，再写业务代码；不从旧页面或旧数据库表反向设计；
- 每个阶段只交付一个可验证切片，代码、测试、文档、changelog 和 lessons 同步；
- 前端只负责展示状态、收集确认和调用业务端点；课程身份、版本关系、授权绑定、事务、幂等和权限由后端应用服务负责，前端不通过多次接口调用拼装跨对象事务；
- 先审计现有端点能否组合满足已确认需求；若业务语义无法由现有端点安全表达，先冻结实现并取得端点变更批准，再补充契约、服务和数据库设计；
- 新系统在 `v1/` 独立建立，旧系统冻结功能和结构变更；旧代码只按 01 现状评估、04–09 设计和测试证据行为保持式迁入；
- 当前无价值服务端数据和学生本机数据不迁移；旧数据只用于拒绝/隔离测试；
- 每个阶段结束执行自动化测试、必要人工验收、三问复盘、提交并推送，再进入下一阶段。

## 2. 提交和阶段门禁

提交格式继续使用：`feat` / `fix` / `test` / `doc` / `refactor`。一个提交只包含一个明确目标和必要的测试/文档。

每阶段完成前必须检查：

1. 需求/设计编号已回链；
2. 失败、权限、原子性和恢复测试已补齐；
3. 无秘密、真实个人数据或未经批准的外部内容；
4. 仓库总门禁、旧系统回归基线、v1 Node/TypeScript 测试及 `cd v1/backend && uv run pytest` 在适用范围通过；
5. 人工验收记录和未验证项已写入 `tests/manual/v1/`；
6. `changelog.md`、`doc/lessons.md`、`next.md` 与实际状态一致；
7. 提交已推送，发布/回退信息可追溯。

## 4. 阶段 0：工程基线与干净初始化

### 目标

在 `v1/` 建立代码布局、配置加载、OpenAPI/JSON Schema 真源、测试夹具和新的空数据库/本机存储 Schema。旧生产数据、
旧学生数据和旧插件响应不被读取或覆盖。

### 任务

- 建立 `v1/backend/`、`v1/web/`、`v1/extension/`、`v1/contracts/`、测试夹具和版本清单的职责边界；
- 将课程包和插件消息从手工对象提升为版本化 JSON Schema；HTTP 由 OpenAPI 生成/校验；
- 建立空库 migration、seed 和初始化检查；不导入旧数据库业务数据；
- 建立插件新的 `storage_schema_version`、`LocalIdentity` 和本机证明的安全存储接口；
- 建立匿名课程夹具，覆盖重复课节、同视频多课节、多发布版本和多授权来源；
- 改造仓库总测试入口与秘密、依赖、端点、模块、契约检查，使其显式覆盖 legacy/v1，并用违规夹具证明不会假绿。

### 完成条件

空库能启动，未知旧数据被拒绝/隔离，最小契约能被 Python 与 TypeScript 双端校验；自动化测试能在干净环境运行。

## 5. 阶段 1：服务端身份与课程领域

### 任务顺序

1. 管理员/教师认证、会话、停用/恢复和工作空间归属；
2. 课程、课节、视频引用和顺序；
3. 聚合 JSON 草稿、修订冲突、字幕/课程文件 staging；
4. 四类节点共同契约和服务端校验；
5. 操作审计最小字段和安全错误。

### 门禁

先写两教师交叉权限、草稿冲突、输入畸形和失败不覆盖测试，再实现页面和服务层。管理员不默认读取课程正文，
学生不进入服务端教师 API。

## 6. 阶段 2：发布、授权与课程包

### 任务顺序

1. 课程级原子 `CourseRelease + ReleaseLessonSnapshot`；
2. 权利确认和 `ReleaseAvailability`；
3. `AccessCode`、`GrantItem`、`Redemption` 和有效资格并集；
4. 首次兑换、幂等重试、免输授权码更新和本机证明校验；
5. 版本化课程包生成、范围裁剪、摘要和禁止字段；
6. OpenAPI、包 Schema、错误码和契约测试。

### 门禁

发布必须先确认课程至少有一节课节再写入，当前不把测试预览作为发布门槛；授权码原文只显示一次；课程包只返回有效范围；失效授权不返回正文；失败不生成部分
关系或包；同一课程更新必须原子替换。

## 7. 阶段 3：教师应用

### 任务顺序

- 登录/工作空间和课程列表；
- 多课程、多课节编辑和显式顺序；
- 字幕导入、时间依据、节点编辑和保存冲突；
- 真实预览握手和预览数据隔离；
- 发布确认、课程级授权范围和授权码一次显示；授权码按 `course_id` 自动解析最新可交付版本；
- 教师工作台课程标题点击进入修改页；独立课程版本、“修改本版本”和“增加版本”后置；
- 归档/终止影响说明和失败恢复。

### 门禁

教师能用真实课程从制作走到发布和授权；同内容课节不被去重；预览不产生学生数据；所有高影响操作有影响
说明和确认；旧单课程 UI 不作为隐式默认。

## 9. `D-V1-018`/`D-V1-019` 课程版本方向与当前课程级授权切片

状态：当前课程级授权规则已确认；版本操作和授权码管理端点已获批准并进入本轮开发，跨独立课程升级仍后置。详细决策见
[`D-V1-018`](../decisions/2026-08-27-course-version-and-access-code-management.md) 和 [`D-V1-019`](../decisions/2026-08-27-course-access-latest-release.md)。

本轮实现顺序：

1. 先冻结 `version-drafts`、授权码批量创建和授权码管理查询契约；
2. 后端增加课程版本来源字段与版本操作幂等事实，实现 `modify`/`add` 单事务；
3. 后端复用现有授权模型实现单个/批量创建、完整码安全重建和领取使用摘要；
4. 前端把已发布卡片改为与草稿同尺寸，并接入三个固定操作与独立授权码管理页；
5. 覆盖迁移、事务、幂等、权限、API 和页面回归，最后同步文档、变更记录与阶段经验。

当前授权仍保持 `course_id -> latest deliverable release`，不引入 `release_id` 授权。课程族跨课程升级、本机学习状态迁移和旧授权码跨独立课程兼容继续后置。

### 9.1 现有后端端点可组合性审计（2026-08-27）

审计依据：`v1/backend/app/modules/*/routes.py`、对应 application service/model/schema、
`v1/backend/tests/test_authoring_release_api.py` 和 `test_entitlement_delivery_api.py`，并以当前 OpenAPI 路径清单复核。

| 需求切片 | 可复用的现有端点/服务 | 审计结论 | 实现门禁 |
| --- | --- | --- | --- |
| 工作台标题、说明文字、草稿标题点击 | `GET /api/v1/teacher/courses`、现有教师路由 | 可以由前端独立完成 | 可在端点契约不变时实现；点击只导航到已有课程编辑入口 |
| 草稿发布 | `POST /api/v1/teacher/courses/{course_id}/releases`、发布校验、预览和幂等服务 | 只能部分复用：当前仍在同一 `course_id` 下递增 `release_number`，且 `ScriptDraft` 不被消费 | 不能只改前端；需要后端定义独立课程身份和草稿消费的原子业务操作 |
| 已发布区域按课程版本展示 | `GET /api/v1/teacher/courses`、`GET /api/v1/teacher/courses/{course_id}/releases`、`GET /api/v1/teacher/releases/{release_id}` | 不能直接组合：课程列表只聚合每个 `course_id` 的最新发布信息，不能把每个独立课程版本作为课程卡片返回 | 需要调整列表投影/端点契约或新增版本列表业务端点，并明确 `courseId`/`releaseId` |
| “修改本版本”与“增加版本” | `GET /api/v1/teacher/courses/{course_id}/course-file`、课程文件导入、`archive` | 不能作为正式业务组合：导出+导入会绕过版本操作事务；没有按选中版本回退草稿/保留发布版本的原子服务，也没有删除指定发布身份的端点 | 需要后端版本操作业务服务；前端不得用多个普通端点模拟这两个动作 |
| 当前课程级生成授权码 | `POST /api/v1/teacher/access-codes`、授权码安全生成/一次显示/幂等逻辑、`latest_deliverable_release(course_id)` | 可以复用：当前 `GrantItem` 和有效资格按 `course_id` 聚合，正好满足自动解析最新可交付版本 | 不新增端点；前端只传课程级授权参数，不自行决定 `release_id` |
| 学生使用旧授权码升级新版本 | `POST /api/v1/student/course-updates` | 当前实现按 `course_id` 找最新可交付版本，且没有课程族/升级关系 | 本切片明确不开发；另立后续需求、端点、数据迁移和本机状态迁移设计 |

#### 9.1.1 已批准并冻结的后端变更范围

产品负责人已批准本轮新增业务服务和端点：

1. `POST /api/v1/teacher/courses/{course_id}/version-drafts`：按 `mode=modify|add` 原子完成版本退回或复制，并处理权限、快照选择、幂等和回滚；
2. `POST /api/v1/teacher/access-codes/batch`：一次生成 1–100 个课程级授权码，批次整体提交并可幂等重放；
3. `GET /api/v1/teacher/access-codes`/明细：仅向所属教师返回完整码和领取使用摘要；数据库不保存明文；
4. `GET /api/v1/teacher/courses`：增加课程版本族、来源和业务版本号投影，继续由后端区分草稿/已发布事实；
5. 前端只消费业务 DTO 和错误码，不了解数据库表、不承担跨请求回滚。

发布仍使用既有 `/releases` 端点且只要求至少一节课节。版本级 `release_id` 授权、课程族升级关系和学生本机跨课程迁移不在本轮范围。

## 8. 阶段 4：学生插件课程库

### 任务顺序

1. background 网络/存储唯一边界和内部消息；
2. 新本机身份、私有证明、课程库根和授权来源缓存；
3. 授权码输入、结果摘要、学生确认和课程包校验；
4. staging、原子安装、同课程更新和局部隔离；
5. 离线课程库、删除、资格失效和更新状态；
6. 旧存储/旧响应拒绝，不迁移无价值旧本机数据。

### 门禁

popup/content 不旁路 background；空/旧/畸形响应安全失败；取消不写库；损坏包不覆盖旧课程；本机学习数据不上传；
多门课程相互隔离。

## 9. 阶段 5：B 站运行时

### 任务顺序

- 精确视频引用匹配和无匹配静默；
- 多课节候选展示、学生选择和会话锁定；
- 播放器 adapter、节点调度、唯一学习窗口和四类渲染器；
- 播放/窗口/提交/完成事实分离和本机状态；
- SPA 切换、播放器重建、全屏、seek、刷新和离线恢复；
- 清理旧监听、旧窗口和旧课程上下文。

### 门禁

在指定桌面 Chrome/B 站上真实验证：节点到点暂停、反馈、继续、错误/跳过、刷新、切换视频和多个课节；无匹配
页面不显示课程 UI；当前会话不热切换课程版本。

## 10. 阶段 6：安全运维与切换

### 任务

- 完成 Argon2、会话 Cookie、授权码/本机证明摘要和环境密钥门禁；
- 完成消息、课程包、文件、日志和导出禁入扫描；
- 建立精确提交构建、依赖锁、产物摘要、健康检查和固定 ZIP 发布记录；
- 建立服务端空库初始化、代表性副本检查、隔离恢复、回退和故障记录；
- 旧数据库、旧插件、旧存储和旧入口只读/拒绝/隔离，不被 v1 运行时读取，也不在首次切换时物理删除；
- 销售页/飞书公开表单和人工恢复入口纳入发布候选验证。

### 门禁

所有适用 `SEC-*`、`OPS-*`、`MIG-*` 和 `D-V1-012` 测试通过；任何秘密、本机学习数据或旧业务对象误入 v1 都阻止切换。

## 11. 阶段 7：真实验收与发布

按 [v1-test-plan.md](v1-test-plan.md) 执行：

1. 自动化、契约、秘密、依赖和文档同步检查；
2. 管理员/教师/学生核心路径；
3. 真实老师和真实学生闭环；
4. 第二门课程或第二位老师重复交付；
5. 本机重启、更新、失败恢复、备份恢复和回退；
6. 需求级追踪矩阵 276 个编号更新为真实状态；
7. 发布候选固定提交、产物、环境、恢复点、风险和发布后探针。

任一 P0 待验证、阻塞或证据不可重复，都不能标记 v1 发布完成。

阶段 7 只完成 v1 生产切换并保留上一套完整发布组合、旧源码和恢复入口，不在同一提交删除旧系统。

## 12. 阶段 8：观察与旧系统退役

只有完成预先记录的观察期和至少一个完整真实交付周期后，才开始退役：

1. 清点旧 API、页面、插件消息、存储键、书签、发布脚本、文档和人工支持消费者；
2. 确认消费者均为零或已有明确拒绝/重定向；
3. 确认旧系统不再承担回退、恢复、追溯或安全处置责任；
4. 用独立 PR/MR 删除旧代码、旧专用工具和旧回归测试，更新索引、规则、发布清单和 changelog；
5. 删除前后执行仓库总门禁、v1 构建、发布探针和恢复验证。

首次 v1 切换与旧系统删除不得位于同一提交或同一发布动作。

## 13. 文档与代码同步清单

每个阶段结束更新：

- 对应设计/需求/决策链接和追踪矩阵；
- 代码和测试文件；
- `tests/manual/v1/` 证据；
- `doc/lessons.md` 的新坑/验证/效率三问；
- `changelog.md`、`next.md` 和必要索引；
- Git 提交、推送和可回退版本。

没有新经验时可以明确记录“本阶段无新增 lessons”，不为凑字数编写总结。
