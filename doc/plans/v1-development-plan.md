文档版本：`1.0.0`

状态：已建立，待按阶段执行；本计划不提前承诺代码复用比例，先按冻结设计重构目标边界

需求真源：[`../requirements/v1/README.md`](../requirements/v1/README.md)

设计真源：[`../design/v1/README.md`](../design/v1/README.md)

测试门禁：[`v1-test-plan.md`](v1-test-plan.md)

代码级执行拆解：[`v1-code-refactor-execution-plan.md`](v1-code-refactor-execution-plan.md)

本文件定义阶段目标和产品门禁；代码目录、现状保留/替换矩阵、工作包顺序、失败模式、测试路径和提交边界以代码级执行计划为准。两者冲突时先回到冻结需求和设计判断，不由更细的计划覆盖上级边界。

## 1. 实施原则

- 先建立 v1 真源、契约和空库初始化，再写业务代码；不从旧页面或旧数据库表反向设计；
- 每个阶段只交付一个可验证切片，代码、测试、文档、changelog 和 lessons 同步；
- 旧代码只按 01 现状评估、04–09 设计和测试证据逐项复用，不按目录整体保留或整体推倒；
- 当前无价值服务端数据和学生本机数据不迁移；旧数据只用于拒绝/隔离测试；
- 每个阶段结束执行自动化测试、必要人工验收、三问复盘、提交并推送，再进入下一阶段。

## 2. 提交和阶段门禁

提交格式继续使用：`feat` / `fix` / `test` / `doc` / `refactor`。一个提交只包含一个明确目标和必要的测试/文档。

每阶段完成前必须检查：

1. 需求/设计编号已回链；
2. 失败、权限、原子性和恢复测试已补齐；
3. 无秘密、真实个人数据或未经批准的外部内容；
4. `npm test` 和 `cd backend && uv run pytest` 在适用范围通过；
5. 人工验收记录和未验证项已写入 `tests/manual/v1/`；
6. `changelog.md`、`doc/lessons.md`、`next.md` 与实际状态一致；
7. 提交已推送，发布/回退信息可追溯。

## 4. 阶段 0：工程基线与干净初始化

### 目标

建立 v1 代码布局、配置加载、OpenAPI/JSON Schema 真源、测试夹具和新的空数据库/本机存储 Schema。旧生产数据、
旧学生数据和旧插件响应不被读取或覆盖。

### 任务

- 建立 `src/`、`backend/`、共享契约、测试夹具和版本清单的职责边界；
- 将课程包和插件消息从手工对象提升为版本化 JSON Schema；HTTP 由 OpenAPI 生成/校验；
- 建立空库 migration、seed 和初始化检查；不导入旧数据库业务数据；
- 建立插件新的 `storage_schema_version`、`LocalIdentity` 和本机证明的安全存储接口；
- 建立匿名课程夹具，覆盖重复课节、同视频多课节、多发布版本和多授权来源；
- 建立秘密扫描、依赖锁、契约版本和文档链接检查。

### 完成条件

空库能启动，未知旧数据被拒绝/隔离，最小契约能被 Python 与 TypeScript 双端校验；自动化测试能在干净环境运行。

## 5. 阶段 1：服务端身份与课程领域

### 任务顺序

1. 管理员/教师认证、会话、停用/恢复和工作空间归属；
2. 课程、课节、视频引用和顺序；
3. 聚合 JSON 草稿、修订冲突、字幕/课程文件 staging；
4. 四类节点共同契约和服务端校验；
5. 操作审计最小字段和安全错误。

### 门禁

先写两教师交叉权限、草稿冲突、输入畸形和失败不覆盖测试，再实现页面和服务层。管理员不默认读取课程正文，
学生不进入服务端教师 API。

## 6. 阶段 2：发布、授权与课程包

### 任务顺序

1. 课程级原子 `CourseRelease + ReleaseLessonSnapshot`；
2. 权利确认和 `ReleaseAvailability`；
3. `AccessCode`、`GrantItem`、`Redemption` 和有效资格并集；
4. 首次兑换、幂等重试、免输授权码更新和本机证明校验；
5. 版本化课程包生成、范围裁剪、摘要和禁止字段；
6. OpenAPI、包 Schema、错误码和契约测试。

### 门禁

发布必须先完整校验再写入；授权码原文只显示一次；课程包只返回有效范围；失效授权不返回正文；失败不生成部分
关系或包；同一课程更新必须原子替换。

## 7. 阶段 3：教师应用

### 任务顺序

- 登录/工作空间和课程列表；
- 多课程、多课节编辑和显式顺序；
- 字幕导入、时间依据、节点编辑和保存冲突；
- 真实预览握手和预览数据隔离；
- 发布确认、版本显示、授权范围和授权码一次显示；
- 归档/终止影响说明和失败恢复。

### 门禁

教师能用真实课程从制作走到发布和授权；同内容课节不被去重；预览不产生学生数据；所有高影响操作有影响
说明和确认；旧单课程 UI 不作为隐式默认。

## 8. 阶段 4：学生插件课程库

### 任务顺序

1. background 网络/存储唯一边界和内部消息；
2. 新本机身份、私有证明、课程库根和授权来源缓存；
3. 授权码输入、结果摘要、学生确认和课程包校验；
4. staging、原子安装、同课程更新和局部隔离；
5. 离线课程库、删除、资格失效和更新状态；
6. 旧存储/旧响应拒绝，不迁移无价值旧本机数据。

### 门禁

popup/content 不旁路 background；空/旧/畸形响应安全失败；取消不写库；损坏包不覆盖旧课程；本机学习数据不上传；
多门课程相互隔离。

## 9. 阶段 5：B 站运行时

### 任务顺序

- 精确视频引用匹配和无匹配静默；
- 多课节候选展示、学生选择和会话锁定；
- 播放器 adapter、节点调度、唯一学习窗口和四类渲染器；
- 播放/窗口/提交/完成事实分离和本机状态；
- SPA 切换、播放器重建、全屏、seek、刷新和离线恢复；
- 清理旧监听、旧窗口和旧课程上下文。

### 门禁

在指定桌面 Chrome/B 站上真实验证：节点到点暂停、反馈、继续、错误/跳过、刷新、切换视频和多个课节；无匹配
页面不显示课程 UI；当前会话不热切换课程版本。

## 10. 阶段 6：安全运维与切换

### 任务

- 完成 Argon2、会话 Cookie、授权码/本机证明摘要和环境密钥门禁；
- 完成消息、课程包、文件、日志和导出禁入扫描；
- 建立精确提交构建、依赖锁、产物摘要、健康检查和固定 ZIP 发布记录；
- 建立服务端空库初始化、代表性副本检查、隔离恢复、回退和故障记录；
- 旧数据库、旧插件、旧存储和旧入口只读/拒绝/隔离，不被 v1 运行时读取；
- 销售页/飞书公开表单和人工恢复入口纳入发布候选验证。

### 门禁

所有适用 `SEC-*`、`OPS-*`、`MIG-*` 和 `D-V1-012` 测试通过；任何秘密、本机学习数据或旧业务对象误入 v1 都阻止切换。

## 11. 阶段 7：真实验收与发布

按 [v1-test-plan.md](v1-test-plan.md) 执行：

1. 自动化、契约、秘密、依赖和文档同步检查；
2. 管理员/教师/学生核心路径；
3. 真实老师和真实学生闭环；
4. 第二门课程或第二位老师重复交付；
5. 本机重启、更新、失败恢复、备份恢复和回退；
6. 需求级追踪矩阵 256 个编号更新为真实状态；
7. 发布候选固定提交、产物、环境、恢复点、风险和发布后探针。

任一 P0 待验证、阻塞或证据不可重复，都不能标记 v1 发布完成。

## 12. 文档与代码同步清单

每个阶段结束更新：

- 对应设计/需求/决策链接和追踪矩阵；
- 代码和测试文件；
- `tests/manual/v1/` 证据；
- `doc/lessons.md` 的新坑/验证/效率三问；
- `changelog.md`、`next.md` 和必要索引；
- Git 提交、推送和可回退版本。

没有新经验时可以明确记录“本阶段无新增 lessons”，不为凑字数编写总结。
