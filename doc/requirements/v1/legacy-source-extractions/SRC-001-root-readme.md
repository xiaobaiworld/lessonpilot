## 4. 冲突、过期内容与否决项

### 4.1 生产数据是否存在

README 同时声称“当前没有正式发布的旧课程数据”，而已接受的 `CONSTRAINT-03` 以生产环境已有教师账号、课程、发布和授权相关数据为保护前提。两者口径不同，且 README 自身也描述了已发布课程 API 和生产数据库。

处理结论：不采用“没有旧课程数据”作为迁移依据。按 `MIG-SOURCE-001`、`MIG-SERVER-001` 对生产数据库和发布记录做实际盘点后，再区分测试数据、正式数据、空发布内容和真实用户数据；盘点前一律按需要保护处理。

### 4.2 插件格式和实际分发物

README 声称 `0.9.1` 只支持新的多课程格式，但 11 仍要求确认是否存在同版本号不同内容、旧单课程存储或不同已安装产物。

处理结论：README 只能证明某次代码状态，不能证明所有已分发和已安装实例。实际 ZIP、发布记录、manifest 和代表性本机存储完成清点前，`MIG-CLIENT-*` 保持未验证。

### 4.3 生产版本信息已经过期

README 固定记录 2026-08-20 的 release ID 和提交，而项目后续记录显示生产与代码仍发生变化。动态版本信息会自然过期。

处理结论：该段保留为历史线索，不作为“当前生产”真源。v1 应由可查询的版本端点、发布记录和 `ACC-GATE-002` 固定实际发布状态，README 只链接权威入口。

### 4.4 更换视频时清除旧课程

README 的旧核心边界要求“更换课程 URL 时确认后清除旧课程”。这来自单课程原型，会把视频引用变化与课程身份、结构和本机状态删除混为一体。

处理结论：不迁入 v1，并由 `FR-COURSE-006`、`FR-COURSE-010`、`DATA-CONTENT-002`、`DATA-LOCAL-005` 明确替代。更换视频引用不得改变课程或课节身份，也不得静默删除课程结构或学习状态；不兼容状态按版本迁移规则单独处理。

### 4.5 固定本地测试密码

README 公开展示本地 seed 测试账号密码 `password`。它被描述为开发环境固定测试值，不是生产凭证，但容易被复制到错误环境。

处理结论：不进入 v1 需求或生产配置。后续开发指南应使用显式测试占位值或运行时生成值，并继续遵守 `SEC-SECRET-*`、`DEV-CONFIG-*` 和环境隔离要求；生产迁移时确认不存在同值真实凭证。
