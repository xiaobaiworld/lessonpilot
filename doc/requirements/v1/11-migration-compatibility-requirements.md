## 1. 迁移基线与目标

v1 的迁移源不是一套抽象的“旧系统”，而是三类必须分开处理的事实：

1. `main@0e503a4` 以及之后已进入生产的服务端账号、工作空间、课程、课节、草稿、发布和授权数据；
2. 已发布插件基线 `v0.9.1` 及用户机器上可能存在的课程和学习状态；
3. 历史原型、测试数据和已被替代的单课程契约、存储键及页面路径。

迁移目标是保护真实服务端权威数据和可证明兼容的学生本机状态，同时不为已否决原型承担永久兼容成本。
“版本号相同”不足以证明两份产物或两组本机数据兼容；还必须核对产物内容、Schema、存储版本和稳定身份。

本文件建立五类 `MIG-*` 要求：

| 编号域 | 迁移责任 |
| --- | --- |
| `MIG-SOURCE-*` | 精确清点迁移源、产物和实际使用状态 |
| `MIG-SERVER-*` | 保护服务端归属、历史、凭证与业务关系 |
| `MIG-LOCAL-*` | 区分可兼容学生本机数据与已否决旧结构 |
| `MIG-CONTRACT-*` | 协调 API、课程包、插件消息和用户升级顺序 |
| `MIG-CUTOVER-*` | 演练、对账、切换、回退和弃用有明确门禁 |

## 2. 单条需求格式

每条正式 `MIG-*` 要求使用以下字段：

1. 状态；
2. 优先级；
3. 来源；
4. 迁移要求；
5. 失败边界；
6. 验收证据；
7. 关联需求。

## 3. 迁移源清点

#### MIG-SOURCE-001：每个旧对象和用户路径都有唯一处理结论

- 状态：已接受
- 优先级：P0
- 来源：现有仓库同时包含已运行生产能力、多课程实现、历史单课程原型、旧品牌命名和已替代文档
- 迁移要求：在设计迁移前，按精确代码提交、发布产物摘要、数据库版本、插件文件内容、存储版本和真实用户路径清点迁移源；每项分类为保留、转换、重新生成、明确拒绝或弃用
- 失败边界：找不到真实使用证据时标记未知，不把文档中的历史版本号、演示数据或当前工作区默认当作已分发事实
- 验收证据：迁移源清单、产物哈希、数据库轮廓、存储样例、用户路径及每项处理结论
- 关联需求：`CONSTRAINT-03`、`DEV-DOC-001`、`OPS-ENV-001`

## 4. 服务端权威数据

#### MIG-SERVER-001：账号、工作空间和业务对象保留稳定归属

- 状态：已接受
- 优先级：P0
- 来源：生产已有管理员、教师、工作空间、课程、课节、草稿、发布和授权数据
- 迁移要求：迁移保留或建立可追溯的旧新身份映射，保持教师与唯一工作空间、课程层级、草稿来源、不可变发布版本、授权范围及审计对象的真实关系；不从标题、顺序、BVID 或创建时间猜测身份
- 失败边界：归属、身份、引用或版本存在重复、缺失或冲突时停止受影响范围迁移，不自动合并课程、改换工作空间或生成伪历史
- 验收证据：迁移前后数量、身份映射、归属、层级、发布版本、授权范围和审计关联对账
- 关联需求：`FR-WS-007`、`FR-WS-008`、`DATA-ID-003`、`DATA-DELIVERY-001` 至 `DATA-DELIVERY-005`、`DATA-OPS-001`

#### MIG-SERVER-002：凭证只在可安全验证时继续有效

- 状态：已接受
- 优先级：P0
- 来源：密码验证值、授权码验证值和系统密钥分别决定账号登录、课程领取和历史凭证可用性
- 迁移要求：密码验证值只在目标系统能按原算法安全验证时原样保留；授权码验证值与必要密钥、授权来源和范围一起核对；无法安全继续时采用受控重置、重新发放或明确失效流程
- 失败边界：不导出、记录或伪造明文密码和授权码；不自动生成新密钥后宣称旧凭证已成功迁移
- 验收证据：迁移前后登录与领取探针、算法及密钥来源检查、无法兼容凭证的受控处置记录
- 关联需求：`DATA-ID-002`、`DATA-DELIVERY-003`、`SEC-SECRET-001` 至 `SEC-SECRET-003`、`OPS-DATA-002`

## 5. 学生本机课程与学习状态

#### MIG-LOCAL-001：只迁移可证明兼容的本机课程库和学习状态

- 状态：已接受
- 优先级：P0
- 来源：当前多课程实现使用 `studentCourseStore`、存储版本 2 和课程包 Schema 2；学生可能已有本机课程与学习结果
- 迁移要求：v1 升级先识别本机存储版本、课程包 Schema、课程、课节、节点稳定身份和完成语义；只保留完整通过目标契约校验的课程及可证明兼容的继续位置、草稿、尝试和完成状态
- 失败边界：本机数据损坏、版本未知、身份冲突或完成语义无法证明兼容时，不猜测、不迁移到其它对象且不清空整个课程库
- 验收证据：当前多课程存储、损坏存储、未知版本、节点语义变更及局部不兼容样例的迁移与恢复测试
- 关联需求：`FR-LIB-009`、`FR-LIB-010`、`FR-LIB-013`、`FR-LEARN-013`、`DATA-LOCAL-005`

#### MIG-LOCAL-002：已否决单课程键不伪装成可兼容数据

- 状态：已接受
- 优先级：P0
- 来源：`D-025` 及已完成的多课程实现明确不再使用 `{ "course": ... }`、`installedCourse` 和 `learningState`
- 迁移要求：历史单课程键和无稳定课程、课节身份的测试数据不自动转换为 v1 课程库；检测到这些数据时明确说明不支持及重新下载课程的路径，在用户确认前不自动删除原键
- 失败边界：不从 BVID、标题、安装时间或节点顺序生成伪稳定身份；不把无法证明语义的旧完成状态带入 v1
- 验收证据：历史单课程键检测、无自动删除、无伪身份、明确不兼容提示及重新下载路径测试
- 关联需求：`FR-LIB-001`、`FR-LIB-005`、`FR-RUNTIME-001`、`DATA-ID-004`、`SEC-TRUST-003`

## 6. 契约与用户升级路径

#### MIG-CONTRACT-001：不兼容契约切换不产生新旧组件混用

- 状态：已接受
- 优先级：P0
- 来源：服务端下载响应、课程包、插件存储、插件消息和教师预览协议可以独立变化
- 迁移要求：每个契约声明支持的源版本、目标版本和不兼容结果；发布顺序保证 Web、API 和插件不会在无识别能力时混用新旧契约；不支持的组合显示更新或重试动作并保留当前数据
- 失败边界：不支持的 Schema、协议或插件版本默认拒绝，不猜测字段、静默丢弃内容或产生部分写入
- 验收证据：支持矩阵、新旧 Web/API/插件交叉测试、升级顺序演练、不兼容错误及原数据不变证据
- 关联需求：`INT-EXT-002`、`INT-PACKAGE-001`、`INT-PACKAGE-002`、`DEV-STRUCT-002`、`OPS-RELEASE-001`、`OPS-RELEASE-002`

#### MIG-CONTRACT-002：历史单课程下载响应不建立长期兼容层

- 状态：已接受
- 优先级：P0
- 来源：`D-025` 已确认历史 `{ "course": ... }` 响应未作为正式课程交付，当前真源为 `{ "courses": [...] }`
- 迁移要求：v1 不为历史单课程响应、按 BVID 派生的身份或已否决存储键建立运行时适配层；相关样例只用于证明旧格式被明确拒绝且不破坏当前数据
- 失败边界：拒绝旧契约时返回可识别的版本错误，不返回伪成功、空课程或部分转换结果
- 验收证据：历史单课程响应、BVID 身份和旧存储样例的拒绝、无写入和可恢复提示测试
- 关联需求：`DATA-CONTENT-001`、`DATA-DELIVERY-002`、`INT-PACKAGE-001`、`SEC-TRUST-002`

## 7. 演练、切换与弃用

#### MIG-CUTOVER-001：迁移经过代表性演练、对账和受控切换

- 状态：已接受
- 优先级：P0
- 来源：v1 切换可能同时影响服务端数据、Web、API、插件和真实用户路径
- 迁移要求：正式切换前在代表性服务端副本和本机存储样例上执行完整迁移，对账数量、身份、归属、版本、授权范围和可兼容学习状态；切换时先建立恢复点，执行确定迁移版本并验证教师登录、课程发布、授权领取、插件升级和学生运行
- 失败边界：任一 P0 对账或核心路径失败时不完成切换；中断、重试或回退不得产生重复对象、部分关系或新代码配旧结构
- 验收证据：演练记录、迁移前后对账、核心业务探针、中断与重试、回退或恢复结果及未迁移项清单
- 关联需求：`OPS-DATA-001` 至 `OPS-DATA-003`、`OPS-RELEASE-002`、`DEV-TEST-002`、`DEV-DOC-002`

#### MIG-CUTOVER-002：旧入口和兼容标识只在无活跃责任后弃用

- 状态：已接受
- 优先级：P0
- 来源：旧品牌名、页面路径、存储键、协议标识和历史文档可能仍承担重定向、识别、迁移或追溯职责
- 迁移要求：每个拟删除入口或标识在 `13-legacy-source-register.md` 记录消费者、替代项、用户迁移动作、证据和删除条件；仍承担兼容或追溯职责的旧名称和键保留明确标记，不再扩展新功能
- 失败边界：不为了统一命名、清理仓库或减少代码直接删除仍被生产、用户书签、插件、数据或文档引用的入口
- 验收证据：旧入口消费者搜索、重定向与升级路径、无活跃调用证据、删除前后链接和回归检查
- 关联需求：`CONSTRAINT-06`、`DEV-DOC-001`、`OPS-RELEASE-001`

## 8. 第一阶段完成条件

本文件只在以下条件全部成立时完成：

1. 全部 `MIG-*` 通过人工审核，且每个迁移源都有保留、转换、重新生成、拒绝或弃用结论；
2. 实际生产数据库、已分发插件产物和代表性本机存储已按精确版本与内容清点；
3. 服务端迁移和可支持本机升级通过代表性演练、对账、中断、重试和恢复测试；
4. 历史原型契约、单课程键和旧入口不被静默冒充成 v1 兼容路径，也不在有活跃责任时被直接删除。
