## 1. 第一阶段运行目标

第一阶段的部署与运维目标是：把通过验证的确定版本安全放入真实使用环境，能确认当前运行什么，
能及时发现核心路径失败，并在不破坏账号、课程、发布和授权数据的前提下回滚或恢复。

当前 `knownmap.com`、阿里云 ECS、Nginx、FastAPI 和 SQLite 已由 `D-V1-007` 确认为 v1 测试及小规模交付目标；本文件不因此承诺规模化能力。

本阶段只建立五类 `OPS-*` 底线：

| 编号域 | 当前必要结果 |
| --- | --- |
| `OPS-ENV-*` | 运行环境、网络暴露、权限和秘密边界明确 |
| `OPS-RELEASE-*` | 发布来自确定版本，组件一致且切换可回退 |
| `OPS-DATA-*` | 迁移、备份和恢复保护服务端权威数据 |
| `OPS-HEALTH-*` | 能识别当前版本、健康结果和主要失败 |
| `OPS-INCIDENT-*` | 故障处置保留证据、限制影响并留下恢复记录 |

## 2. 单条需求格式

每条正式 `OPS-*` 要求使用以下字段：

1. 状态；
2. 优先级；
3. 来源；
4. 运行要求；
5. 失败边界；
6. 验收证据；
7. 关联需求。

## 3. 环境、暴露与运行权限

#### OPS-ENV-001：每个运行环境具有明确用途和独立状态

- 状态：已接受
- 优先级：P0
- 来源：开发、测试、发布验证和正式使用对数据、配置、秘密和外部可见性有不同责任
- 运行要求：每个环境明确记录用途、入口、数据范围、配置来源、秘密来源、当前版本和责任人；测试数据与生产权威数据分离，发布目标必须显式选择
- 失败边界：目标环境、当前版本或数据身份无法确认时不执行写入、迁移、发布、回滚或恢复
- 验收证据：环境清单、配置模板、发布前目标确认、非生产数据隔离和误选目标拒绝测试
- 关联需求：`DATA-LIFE-001`、`DEV-DEP-002`、`SEC-SECRET-003`

#### OPS-ENV-002：生产只暴露必要能力并使用最小运行权限

- 状态：已接受
- 优先级：P0
- 来源：Web、API、运行进程、数据库、备份和管理入口的暴露面与账号、课程和授权风险直接相关
- 运行要求：公网通信使用有效加密传输；运行进程、数据库、备份和发布账号只拥有完成职责所需的读写权限；内部端口、文件、调试入口和健康细节默认不公开
- 失败边界：加密、秘密、文件权限或运行账号边界不符要求时不对外开放新版本；不以调试方便为由放宽生产访问
- 验收证据：公网端口与 TLS 检查、运行账号和文件权限检查、未认证探针及秘密泄露扫描
- 关联需求：`SEC-ACCESS-001` 至 `SEC-ACCESS-003`、`SEC-SECRET-001` 至 `SEC-SECRET-003`、`DEV-DEP-002`

## 4. 发布、切换与回退

#### OPS-RELEASE-001：发布结果可追溯到唯一远程代码版本

- 状态：已接受
- 优先级：P0
- 来源：Web、API、数据库迁移和学生插件需要共同实现同一套已接受契约
- 运行要求：每次发布从已推送、已通过适用门禁的唯一代码版本构建；同次发布的各组件、契约、迁移和依赖具有可识别版本，发布记录保留来源、产物、时间、目标和验证结果
- 失败边界：未推送工作区、来源不明产物或版本不一致的组件不进入生产；失败发布不记录为已完成版本
- 验收证据：精确代码版本构建、产物身份、组件契约一致性、发布记录和未推送版本拒绝测试
- 关联需求：`DEV-STRUCT-002`、`DEV-DEP-001`、`DEV-DOC-002`、`DATA-OPS-002`

#### OPS-RELEASE-002：新版本原子切换并在对外完成前验证

- 状态：已接受
- 优先级：P0
- 来源：页面、API、依赖和数据库可能分别成功或失败，造成版本混用和部分上线
- 运行要求：新版本在独立候选位置完成构建、配置验证、依赖安装、必要迁移和核心探针后才整体切换；切换后再验证公开页面、受保护接口、版本和关键业务路径
- 失败边界：切换前失败不改变当前版本；切换后核心探针失败时停止继续发布，保留证据并执行已验证回退或故障处置
- 验收证据：候选版本检查、切换前后探针、模拟中断、当前版本识别、回退演练及发布记录
- 关联需求：`SUCCESS-05`、`DATA-QUALITY-002`、`DEV-TEST-002`、`DEV-DOC-002`

## 5. 迁移、备份与恢复

#### OPS-DATA-001：风险变更前建立可识别的服务端恢复点

- 状态：已接受
- 优先级：P0
- 来源：当前生产已有教师账号、课程、发布和授权数据，重构不得直接清库或覆盖
- 运行要求：数据库迁移、大范围配置变更、发布或恢复前，对受影响的服务端权威数据建立带时间、版本、范围和完整性结果的备份或等价恢复点；学生本机课程和学习状态不进入平台备份
- 失败边界：无法确认备份范围、版本、访问权限或完整性时不执行风险变更；备份失败不因发布时间压力被忽略
- 验收证据：备份范围清单、访问权限、完整性检查、风险变更前置门禁及无学生本机数据证据
- 关联需求：`CONSTRAINT-03`、`DATA-LIFE-003`、`SEC-PRIV-001`

#### OPS-DATA-002：数据迁移先在代表性副本验证

- 状态：已接受
- 优先级：P0
- 来源：v1 可能改变当前账号、课程、课节、发布、授权和插件契约
- 运行要求：迁移必须有明确来源版本、目标版本、转换规则、不可迁移数据处置、重复执行行为和失败恢复方式；正式执行前在脱敏或受控的代表性副本上验证对象数量、归属、引用、版本和关键业务路径
- 失败边界：迁移规则、源数据范围或验证结果不清时不改变生产；不可迁移数据不被静默丢弃或伪造默认值
- 验收证据：迁移计划、代表性数据清单、演练前后对账、重复执行、中断与恢复测试
- 关联需求：`CONSTRAINT-03`、`DATA-ID-003`、`DATA-DELIVERY-001`、`DATA-DELIVERY-003`、`DATA-QUALITY-001` 至 `DATA-QUALITY-003`

#### OPS-DATA-003：备份只有通过恢复验证才算可用

- 状态：已接受
- 优先级：P0
- 来源：已生成备份不能证明它能恢复账号、工作空间、课程、发布和授权的一致关系
- 运行要求：按明确周期在隔离目标上恢复代表性备份，验证对象归属、引用、版本、权限和核心业务路径；恢复记录保留备份身份、目标、范围、执行者、结果及未恢复项
- 失败边界：不在未确认范围的生产真源上演练恢复；部分恢复、版本不符或归属错乱时不把备份标记为已验证
- 验收证：隔离恢复演练、业务与归属对账、失败备份样例、恢复记录及原生产不变证据
- 关联需求：`SCOPE-09`、`DATA-LIFE-003`、`DATA-OPS-002`、`DATA-QUALITY-003`

## 6. 健康、诊断与故障处理

#### OPS-HEALTH-001：运行环境显示当前版本和核心健康结果

- 状态：已接受
- 优先级：P0
- 来源：运营和支持人员需要区分部署失败、服务故障、契约不符和宿主环境问题
- 运行要求：运行环境可识别当前发布版本、检查时间及 Web、API、数据库连接和关键依赖的安全健康结果；关键动作失败通过脱敏关联标识进入可检索日志
- 失败边界：无法确认的项目显示未知而非正常；对外健康响应不泄露秘密、路径、数据库细节、课程正文或学生本机数据
- 验收证据：版本查询、正常与依赖失败健康探针、日志关联、未知状态及响应脱敏测试
- 关联需求：`FR-ADMIN-004`、`FR-ADMIN-005`、`DATA-OPS-002`、`DEV-LOG-001`、`SEC-PRIV-002`

#### OPS-HEALTH-002：公开试用入口在发布前验证可提交和可接收

- 状态：已接受
- 优先级：P0
- 来源：`D-V1-001`、`SCN-PUB-01`；公开销售页和飞书表单属于 v1 P0
- 运行要求：发布候选验证销售页申请入口使用当前批准的公开表单地址、无需登录可打开、提交结果可辨认，并由获准运营人员确认能够取得一份虚构或专用测试申请；同时验证人工联系恢复入口
- 失败边界：表单地址无效、外部服务不可达、提交结果未知、授权人员无法取得申请或页面仍宣称入口可用时阻止 v1 发布；探针不得提交真实个人信息或在生产积累无法识别的测试线索
- 验收证据：公开页面与地址检查、无登录打开、标记清楚的测试提交、授权读取、测试记录清理或隔离、失败入口和人工恢复路径记录
- 关联需求：`FR-INTAKE-001` 至 `FR-INTAKE-003`、`DATA-INTAKE-001`、`INT-TRIAL-001`、`INT-TRIAL-002`、`SEC-PRIV-003`

#### OPS-INCIDENT-001：故障处理优先限制影响并保留可恢复证据

- 状态：已接受
- 优先级：P0
- 来源：发布、迁移、外部依赖、宿主页面和数据故障可能同时影响教师与学生核心路径
- 运行要求：确认核心故障后停止继续发布或风险写入，记录当前版本、时间、影响范围、脱敏日志、已采取动作和恢复检查点；使用已验证回退或恢复路径后重新验证受影响业务和数据一致性
- 失败边界：根因不明时不连续叠加未验证修复；不为恢复一个对象覆盖无关工作空间或使较旧数据静默成为当前真源
- 验收证据：发布中断、依赖失败和数据恢复演练，故障证据包、回退或恢复结果及数据对账
- 关联需求：`SCN-ERR-02`、`FR-ADMIN-004` 至 `FR-ADMIN-006`、`DATA-QUALITY-003`、`DEV-CODE-002`

第一阶段不在没有真实基线时承诺固定可用率、恢复时间、恢复点、告警阈值或值班响应时限。核心故障必须可见、
可限制影响并有受控恢复路径；进入规模化经营后再根据真实故障和业务责任设置数值目标。

## 7. 第一阶段完成条件

本文件只在以下条件全部成立时完成：

1. 五类 `OPS-*` 均通过人工审核，并能回链数据、安全和开发质量需求；
2. `D-V1-007` 已确认 `knownmap.com`、阿里云 ECS、Nginx、FastAPI 和 SQLite 作为 v1 测试及小规模交付目标；规模化前重开架构；
3. 目标环境具有可重复发布、安全配置、版本识别、核心探针、回退、备份和隔离恢复证据；
4. v1 发布候选不会清空、覆盖、降级或静默替换现有服务端权威数据。

## 8. 当前暂缓与待决项

- `OPEN-02`：已由 `D-V1-004` 决定 v1 使用固定 ZIP、哈希校验、手动更新和回退；签名、商店分发、自动升级和下架留待后续版本；
- `D-V1-006`：账号、授权、审计、备份及其它服务端数据的保留期限；
- `D-V1-007`：v1 目标域名、主机、数据库和运行方式；
- `D-V1-009`：正式支持的桌面 Chrome、操作系统和 B 站页面组合；暂不设固定响应时限；
- 规模化环境的高可用、多节点、异地容灾、自动扩容、全量指标、复杂告警和轮值体系。

暂缓事项不影响当前必要的加密传输、最小权限、确定版本发布、健康验证、受控回退、备份和恢复演练。
