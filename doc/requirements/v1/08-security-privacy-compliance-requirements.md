## 1. 第一阶段安全目标

第一阶段是测试原型和业务闭环验证。安全工作的目标是让管理员、教师和学生能够正常完成业务，同时守住一旦
破坏就会导致账号、课程、授权或本机学习数据不可接受风险的底线。

本阶段只建立四类 `SEC-*`：

| 编号域 | 必须守住的底线 |
| --- | --- |
| `SEC-ACCESS-*` | 管理员、教师、学生和不同教师工作空间不能互相越权 |
| `SEC-SECRET-*` | 密码、会话、授权码及系统密钥不能被普通查询、日志或导出泄露 |
| `SEC-TRUST-*` | 网页消息、课程包、字幕和课程文件不能绕过校验执行行为或破坏已有数据 |
| `SEC-PRIV-*` | 学生本机数据保持单机边界；公开试用联系方式只按明确用途最小处理 |

本阶段不追求企业级安全治理体系，不建立复杂风控、集中安全事件平台、专业渗透测试认证、跨地区合规体系、
细粒度组织权限或大规模滥用防护。它们只有在真实用户、正式经营范围或风险规模出现后再单独立项。

## 2. 文档边界

已经由功能、数据和接口需求明确的安全行为不在这里逐字重复。本文件只补充会影响原型能否安全运行的保护对象、
主要误用、失败处置和验收证据。

常规安全实现细节不建立独立需求编号：

- 密码算法、Cookie 属性、Header、限流阈值及密钥文件位置进入安全设计；
- 依赖检查、代码扫描、测试和提交门禁进入 `09-development-quality-requirements.md`；
- 服务器、TLS、网络、备份、监控、回滚和事故操作进入 `10-deployment-operations-requirements.md`。

但实现细节属于常规做法，不等于可以省略。设计和开发仍必须选择与风险相称的安全实现，并通过测试证明四类
底线没有被突破。

## 3. 单条需求格式

每条正式 `SEC-*` 要求使用以下字段：

1. 状态；
2. 优先级；
3. 来源；
4. 保护对象；
5. 主要误用；
6. 安全要求；
7. 失败处置；
8. 验收证据；
9. 关联需求。

## 4. 计划审核顺序

1. 角色与工作空间访问隔离；
2. 密码、会话、授权码和系统密钥；
3. 插件消息、课程包、字幕及课程文件；
4. 学生本机数据、日志和测试数据；
5. 第一阶段完成条件与后续重开范围。

每一段只保留少量会改变安全结果的要求，不为覆盖通用检查表增加内容。

## 5. 角色与工作空间访问隔离

#### SEC-ACCESS-001：管理员与教师认证边界不能互换

- 状态：已接受
- 优先级：P0
- 来源：管理员与教师承担不同职责并使用独立业务入口
- 保护对象：管理员能力、教师工作空间及双方会话
- 主要误用：复用另一角色的会话、提交伪造角色字段或直接调用另一角色接口
- 安全要求：服务端独立验证管理员和教师会话，并从可信会话确定角色；任何客户端角色声明都不能提升权限
- 失败处置：角色不符或会话无效时拒绝操作，不建立另一角色会话，也不改变账号或业务数据
- 验收证据：管理员、教师、无会话及篡改角色四类请求的交叉权限测试
- 关联需求：`FR-AUTH-001`、`FR-AUTH-004`、`FR-AUTH-010`、`DATA-ID-001`、`INT-WEB-001`

#### SEC-ACCESS-002：教师业务对象始终受工作空间归属约束

- 状态：已接受
- 优先级：P0
- 来源：每名教师只管理自己的课程、发布和授权
- 保护对象：工作空间、课程、课节、草稿、发布版本、授权及课程文件
- 主要误用：篡改对象标识、导入来源或请求参数，读取或修改另一教师的数据
- 安全要求：所有读取、写入、发布、授权、导入和导出均依据当前教师会话验证对象归属，不能仅凭对象标识取得权限
- 失败处置：归属不符、缺失或冲突时拒绝整个操作，不返回对象正文，不产生部分写入或跨空间引用
- 验收证据：两个教师使用真实对象标识完成交叉读写、发布、授权和导出测试，均不能越权
- 关联需求：`FR-WS-003`、`FR-WS-004`、`FR-WS-007`、`FR-WS-008`、`DATA-ID-003`

#### SEC-ACCESS-003：学生与支持角色不能扩大业务权限

- 状态：已接受
- 优先级：P0
- 来源：学生当前没有服务端账号，支持职责也不拥有教师课程或学生本机数据
- 保护对象：教师业务能力、授权范围、课程正文及学生本机课程和学习状态
- 主要误用：把本机学习标识当登录凭证、绕过授权范围下载内容，或以排障为由读取业务正文和学生本机数据
- 安全要求：本机学习标识只用于当前机器的领取关系；学生只能取得有效资格允许的发布内容；管理员和支持人员只使用职责需要的最小摘要与诊断信息
- 失败处置：身份或授权范围无法确认时不返回受保护内容；支持失败不能转为读取学生设备或无边界查看课程正文
- 验收证据：验证本机标识不能访问教师或管理员接口、越范围领取失败、支持接口和日志不含受保护正文或本机学习数据
- 关联需求：`FR-AUTH-007`、`FR-WS-002`、`FR-WS-006`、`FR-GRANT-009`、`FR-ADMIN-006`、`DATA-ID-004`

## 6. 密码、会话、授权码和系统密钥

#### SEC-SECRET-001：密码原文只用于当次认证或设置

- 状态：已接受
- 优先级：P0
- 来源：管理员和教师通过密码建立各自会话
- 保护对象：管理员密码、教师密码及临时重置结果
- 主要误用：明文保存、回显、记录或通过普通查询取回密码
- 安全要求：服务端只保存不可还原的密码验证值；创建或重置得到的临时密码只在当次受控结果中显示，之后不能查回
- 失败处置：密码设置或验证失败时不建立会话，不返回可用于推断密码的内部细节
- 验收证据：存储、登录、创建、重置、查询、日志和错误响应的凭证泄露测试
- 关联需求：`FR-AUTH-001` 至 `FR-AUTH-004`、`FR-AUTH-011`、`DATA-ID-002`

#### SEC-SECRET-002：会话只代表当前已验证身份

- 状态：已接受
- 优先级：P0
- 来源：管理员和教师需要恢复、过期和主动结束会话
- 保护对象：账号身份、会话凭证及会话对应的业务权限
- 主要误用：伪造、固定、泄露或在退出、过期、账号停用后继续使用会话
- 安全要求：会话由服务端安全生成、验证和结束，具有明确有效边界；会话凭证不进入页面正文、普通日志、导出文件或课程包
- 失败处置：会话无效、过期、已退出或账号已停用时拒绝受保护操作，不因会话失效删除已保存业务数据
- 验收证据：会话恢复、过期、退出、账号停用、角色交叉和日志脱敏测试
- 关联需求：`FR-AUTH-003`、`FR-AUTH-005`、`FR-AUTH-006`、`FR-AUTH-010`、`DATA-ID-002`

#### SEC-SECRET-003：授权码原文和系统密钥不进入普通数据流

- 状态：已接受
- 优先级：P0
- 来源：授权码用于建立领取来源，系统密钥用于保护会话或验证值
- 保护对象：授权码原文、会话密钥、授权码验证密钥及其它系统秘密
- 主要误用：通过数据库、代码、版本库、日志、管理页面、课程包或导出文件取得可用秘密
- 安全要求：授权码原文只在创建结果中显示一次，持久化可安全比对但不可还原的验证值；系统密钥与业务数据、代码和发布包分离并受限注入
- 失败处置：缺失、无效或无法读取必要密钥时拒绝依赖它的操作，不自动产生新密钥掩盖问题或记录原值
- 验收证据：授权码创建与查询、密钥缺失启动、日志、导出、发布包和仓库秘密扫描测试
- 关联需求：`FR-GRANT-003`、`FR-GRANT-004`、`FR-GRANT-012`、`DATA-DELIVERY-003`

## 7. 插件消息、课程包、字幕及课程文件

#### SEC-TRUST-001：插件消息只能调用允许的能力

- 状态：已接受
- 优先级：P0
- 来源：教师预览、插件页面、后台脚本和 B 站内容脚本需要跨边界通信
- 保护对象：插件联网、本机存储、教师预览及学生运行时能力
- 主要误用：伪造来源、操作名、请求标识、业务对象或响应，让网页调用未授权能力
- 安全要求：每个消息边界都校验来源、协议版本、操作白名单、请求与响应配对及有效载荷；消息发送者不能自行声明更高权限或任意联网目标
- 失败处置：来源、版本、操作、配对或载荷无效时拒绝整个消息，不联网、不写入且不执行部分操作
- 验收证据：合法消息以及伪造来源、未知操作、版本不符、重复、失配和畸形响应的边界测试
- 关联需求：`INT-EXT-001`、`INT-EXT-002`、`INT-EXT-003`、`FR-RUNTIME-013`

#### SEC-TRUST-002：外部内容只作为数据解析和展示

- 状态：已接受
- 优先级：P0
- 来源：系统需要接收课程发布包、字幕文件和教师课程文件
- 保护对象：教师工作空间、学生课程库、插件运行环境及已保存数据
- 主要误用：通过脚本、HTML、可执行字段、路径、超大内容或伪造引用执行行为或越界读写
- 安全要求：所有文件和课程包在使用前校验类型、大小、格式版本、结构、引用和允许值；文本内容按数据安全展示，不作为代码、HTML、命令、模板或文件路径执行
- 失败处置：任一必要校验失败时拒绝整个输入，只返回可理解的问题摘要，不执行其中内容
- 验收证据：合法样例与超大、损坏、未知版本、越界引用、脚本和注入样例的导入及渲染测试
- 关联需求：`FR-AUTHOR-002`、`FR-AUTHOR-010`、`FR-LIB-005`、`FR-RUNTIME-009`、`FR-PORT-004`、`INT-PACKAGE-002`、`INT-FILE-001`、`INT-FILE-002`

#### SEC-TRUST-003：验证失败不破坏最后有效数据

- 状态：已接受
- 优先级：P0
- 来源：课程安装、更新、导入和消息写入都可能遇到畸形、中断或不兼容输入
- 保护对象：已安装课程、本机学习状态、教师课程草稿及其它工作空间对象
- 主要误用：边验证边覆盖、部分导入、失败后清空或用未验证默认值取代原数据
- 安全要求：外部输入在完整验证并确定影响范围后才能原子写入；新输入不能默认覆盖无关对象或无法安全迁移的学习状态
- 失败处置：验证、迁移或写入失败时保留最后有效数据，清理未完成中间结果并允许用户重试
- 验收证据：损坏包、版本不兼容、存储失败、重复、并发和迁移失败下的原子性与恢复测试
- 关联需求：`FR-LIB-006`、`FR-LIB-010`、`FR-LIB-013`、`FR-PORT-003`、`FR-PORT-004`、`DATA-QUALITY-002`、`DATA-QUALITY-003`

## 8. 学生本机数据、日志和测试数据

#### SEC-PRIV-001：学生课程和学习状态不自动离开本机

- 状态：已接受
- 优先级：P0
- 来源：`D-026` 已确定当前阶段只使用单机本地学习标识和学习状态
- 保护对象：本机学习标识、已安装课程、继续位置、草稿、尝试、节点结果及进度
- 主要误用：在领取、学习、预览、诊断或排障时自动上传学生本机数据
- 安全要求：学生课程库和学习状态只保存在当前机器；在独立需求重开且用户明确知情前，不上传正文、回答、结果、进度或可用于还原这些内容的数据
- 失败处置：联网、授权或支持服务失败时不上传本机学习数据，不以上传换取本机课程的继续使用
- 验收证据：领取、预览、学习、更新、错误与支持路径的网络请求和持久化边界测试
- 关联需求：`FR-AUTH-007`、`FR-LIB-001`、`FR-LEARN-011`、`FR-ADMIN-006`、`DATA-ID-004`、`DATA-LOCAL-001` 至 `DATA-LOCAL-005`

#### SEC-PRIV-002：日志、错误证据和测试数据使用最小必要内容

- 状态：已接受
- 优先级：P0
- 来源：原型仍需要诊断、排障和可重复测试，但不需要收集学生业务正文或秘密
- 保护对象：密码、会话、授权码、系统密钥、课程正文、学生回答和学习状态
- 主要误用：为方便调试记录完整请求、响应、课程包、回答、本机存储或使用真实敏感数据做测试固定项
- 安全要求：日志和错误证据只保留定位所需的状态、类型、版本、安全关联标识和脱敏摘要；自动化测试、样例、截图和手工验收材料使用虚构或匿名数据
- 失败处置：无法安全脱敏时不记录原内容；发现秘密或学生本机数据进入日志、测试产物或仓库时停止分发并清理、轮换或更换相关数据
- 验收证据：登录、授权、课程导入、学习、故障和支持路径的日志检查，以及仓库和测试产物秘密扫描
- 关联需求：`FR-AUTH-011`、`FR-GRANT-012`、`FR-ADMIN-003` 至 `FR-ADMIN-006`、`DATA-OPS-001`、`DATA-OPS-002`

#### SEC-PRIV-003：公开试用申请的联系方式只用于受控接入

- 状态：已接受
- 优先级：P0
- 来源：`D-V1-001`、`SCN-PUB-01`；公开表单会收集联系方式和课程准备信息
- 保护对象：称呼、联系方式、视频链接、教学问题、字幕情况、提交来源及跟进结果
- 主要误用：未说明用途即收集、把可选项变成强制、公开申请记录、把联系方式用于无关营销、复制正文到日志，或以申请自动授予教师权限
- 安全要求：销售页和表单明确用途、第三方处理、必填与可选范围；只有获准运营人员可读取申请；数据只用于试用接入和必要跟进，不进入公开页面、普通日志、课程正文或学生数据；申请与教师认证严格分离
- 失败处置：外部表单配置、权限或提交状态不明时停止把入口标记为可用；发现越权访问或公开暴露时关闭受影响入口、限制访问并保留脱敏处置证据
- 验收证据：公开页面信息检查、必填/可选字段检查、授权与未授权访问、日志检查、失败入口及申请后不能登录的负向测试
- 关联需求：`FR-INTAKE-001` 至 `FR-INTAKE-004`、`DATA-INTAKE-001`、`DATA-INTAKE-002`、`INT-TRIAL-001`、`INT-TRIAL-002`

## 9. 第一阶段完成条件

本文件只在以下条件全部成立时完成：

1. 四类 `SEC-*` 均通过人工审核，并能回链已接受的功能、数据和接口需求；
2. 设计阶段明确每条 P0 要求的信任边界、校验点、失败结果和密钥来源；
3. 实现阶段为访问隔离、秘密泄露、不可信输入和本机数据边界建立自动化或可重复的手工验收证据；
4. 负向用例中的拒绝、失败和恢复不会泄露秘密、扩大权限、自动上传本机数据或破坏最后有效业务数据。

## 10. 当前暂缓事项

- `D-V1-006` 中不同数据和备份的正式保留期限；
- `D-V1-008` 中内容权利声明及争议暂停处置；第一阶段仍遵守“教师应拥有必要内容权利”的产品边界；
- `D-V1-004` 已明确 v1 插件固定 ZIP、哈希校验、手动更新和回滚责任；签名、商店分发、自动升级和下架责任留待后续版本；
- 教师学习证据上线后的学生知情、选择、上传、退出和教师访问规则；
- 面向规模化经营的合规评估、专业安全测试、集中审计和安全响应体系。

暂缓事项不得被原型实现默认为已经解决，也不能反向突破当前数据最小化、角色隔离和内容使用边界。
