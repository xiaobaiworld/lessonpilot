# 课节字幕持久化设计

状态：已接受，按 `D-V1-014`、`D-V1-017` 实施
日期：2026-08-27
范围：教师端课节草稿、课程发布快照、教师课程导入导出文件

## 1. 文档目的

本设计定义老师主动选择的 SRT/VTT 字幕文件如何与一节课建立稳定关联，并随该节课的草稿保存、
课程发布持久化到服务端。字幕原文止步于教师侧（草稿、发布快照和教师 `.kmcourse`），不进入学生课程包，
不进入学生插件。学生端运行互动课程只依赖节点自身已经携带的 `anchor.timeSeconds`，这条链路已经
存在，不属于本次改动范围。

这份字幕由老师单独提供，不读取、抓取或复用 B 站等视频平台的字幕。字幕与视频引用分别管理：
视频引用决定学生在哪个视频页面运行课程，字幕负责教师制作时的时间定位，并作为教师侧的原始内容
随草稿和发布快照保存，也随教师课程导入导出文件流转。

本文是 `D-V1-014`、`D-V1-017` 的实施基准：字幕上传先经过服务端临时检查和可确定修复，修复结果只返回教师端；字幕文本只在教师明确保存草稿后进入服务端草稿和发布快照，课程包与插件契约保持不变。

## 2. 背景与现状

当前教师端在浏览器中读取字幕文件，并先调用服务端临时检查/修复接口；返回文本再解析为 `Caption[]` 后用于生成时间线和定位互动节点。字幕列表、
文件名和课程时长原先只存在于 React 内存中；本设计实施后，已保存字幕可随课节草稿恢复。

保存草稿时，前端只提交：

```json
{
  "nodes": [],
  "assets": [],
  "subtitle": null
}
```

节点可以保存 `anchor.captionId` 和复制到节点正文中的某句字幕文本；保存后的完整字幕由服务端草稿和发布快照恢复，
学生交付包不携带该字段，教师 `.kmcourse` 可携带已保存字幕。

教师页面当前没有自动保存功能。它使用"保存草稿"按钮，并在存在未保存节点修改时阻止无提示离开。

创建互动节点当前只有一条入口：教师端 `Timeline` 组件在没有字幕时不渲染（时长恒为 0），
`SubtitlePicker` 是唯一可以触发创建节点的组件。也就是说，没有字幕时教师本来就无法创建节点——
这是本设计确定不需要为发布单独加一道"字幕存在性校验"的依据（见第 5.4 节）。

## 3. 目标

1. 一份字幕只属于一个课节，以稳定 `lesson_id` 建立关联。
2. 字幕与节点组成同一个课节草稿聚合，一次保存全部成功或全部失败。
3. 无论保存由当前手动按钮还是未来自动保存触发，提交的数据结构和结果一致。
4. 刷新或重新进入课节后，教师端可以从已保存草稿恢复字幕和时间线。
5. 发布时将字幕原样写入不可变课节快照；后续修改草稿不改变旧发布版本。
6. 教师课程导入导出文件（`TeacherCourseFile`）携带字幕原文，方便教师更换设备或备份工作区。

## 4. 非目标

- 不抓取视频平台字幕，也不判断老师上传的字幕是否来自视频平台。
- 不新增独立对象存储、分片上传、下载地址或字幕 CDN。
- 不在本次设计中增加页面自动保存功能。
- 不要求学生运行时展示、搜索或控制字幕；学生端不接收字幕原文，只依赖节点既有的 `timeSeconds`。
- 不保存字幕文件的原始二进制字节、文件系统路径或浏览器 `File` 对象。
- 不处理视频文件上传、托管或转码。
- **不升级课程包契约**：字幕不进入 `CoursePackage`，课程包 JSON Schema 版本保持 v3。
- **不改动插件**：`InstalledLesson`、`checkCoursePackage` 不涉及字幕，插件行为不变。
- 不新增发布时的字幕存在性校验或专用错误码（原因见第 5.4 节）。

## 5. 核心决策

### 5.1 字幕属于课节草稿聚合

字幕不建立独立持久化实体。教师端在保存前调用临时检查接口：

```text
POST /api/v1/teacher/subtitles/repair
```

接口不写数据库；教师端随后继续使用现有草稿接口：

```text
PUT /api/v1/teacher/lessons/{lesson_id}/draft
```

请求中的 `config` 扩展为：

```json
{
  "nodes": [],
  "assets": [],
  "subtitle": {
    "schemaVersion": 1,
    "filename": "第一课.srt",
    "format": "srt",
    "content": "1\n00:00:01,000 --> 00:00:03,000\n欢迎学习\n"
  }
}
```

`lesson_id` 是字幕归属的唯一依据。请求体不重复携带课程 ID 或视频 ID，避免出现多个互相冲突的归属
字段。

### 5.2 保存的是原始字幕文本，不是解析结果

服务端和发布快照保存服务端检查/修复后、由教师确认保存的字幕文本以及文件名、格式。`Caption[]`、课程时长、字幕索引等
数据继续由共享解析器根据 `content` 生成，不建立第二份可漂移的持久化结果。

这里的“文本内容”表示修复后的 SRT/VTT 文本语义；自动修复只调整可确定的时间重叠，不承诺逐字节保存原文件。浏览器使用文本方式读取文件，
未来下载时可以统一输出 UTF-8。如果以后需要保留 BOM、原始编码或逐字节哈希，应改用通用文件资源系统，
不在当前 JSON 草稿中加入 Base64 二进制副本。

### 5.3 字幕使用与节点相同的保存时机

当前页面继续由“保存草稿”按钮触发持久化。选择文件后先调用服务端检查/修复接口；成功后页面展示返回字幕并标记为未保存。保存按钮一次提交
字幕和全部节点。

未来若页面增加自动保存，自动保存必须调用同一草稿保存动作并提交完整聚合，不得为字幕另建后台保存
定时器或并发请求。这样可以保持一个 revision、一套冲突处理和一个成功状态。

### 5.4 发布时原样复制草稿字幕，不新增存在性校验

发布不新增"课节必须有字幕才能发布"的校验，也不返回专用错误码。依据：教师端创建互动节点的唯一
入口是字幕时间轴（`SubtitlePicker`/`Timeline`，见第 2 节），没有字幕时无法创建节点；因此任何
包含节点的草稿在字幕字段上必然已经合法，发布时只需要把草稿里已有的 `subtitle` 字段原样复制进
`ReleaseLessonSnapshot`，草稿没有字幕字段时快照对应字段也留空，不额外拒绝发布。

发布成功后，字幕与节点一起进入 `ReleaseLessonSnapshot`。发布快照不可变，后续替换草稿字幕不会修改
已经交付的发布记录。发布快照本身不下发给插件，只作为服务端留档和课程包生成的原始数据来源。

### 5.5 课程包契约不变

字幕不进入学生课程包。学生课程包（`TERM-030`）JSON Schema 版本保持 `v3`，字段定义、`lessons[]` 结构和
`required` 列表都不需要修改。插件 `checkCoursePackage`、`InstalledLesson` 不需要任何改动。

### 5.6 教师课程导入导出文件携带字幕

`TeacherCourseFile`（`FR-PORT-*`/`DATA-PORT-*`）导出内容增加字幕原文字段，结构与草稿中的
`subtitle` 一致。这份文件只在教师之间流转（导出到本机、导入到另一个工作区），不发给学生或插件，
因此携带字幕原文不影响第 5.5 节的课程包边界。

## 6. 数据流

```text
老师选择 SRT/VTT
        |
        v
浏览器读取文本并调用服务端检查/修复
        |
        +-- 不可修复 --> 保留当前已保存字幕和草稿
        |
        v
页面内存：修复后的 subtitle + captions + nodes
        |
        v
保存草稿（当前手动，未来可由自动保存触发）
        |
        v
ScriptDraft.content：subtitle + nodes + assets
        |
        +-- 预览锁定同一草稿 revision 和 digest
        |
        v
ReleaseLessonSnapshot：subtitle + nodes + assets   <-- 字幕原文止步于此
        |
        v
学生交付课程包（不含字幕，字段不变）
        |
        v
插件安装（不含字幕，字段不变）

教师课程导入导出文件（TeacherCourseFile）：subtitle + nodes + assets  <-- 与草稿并行，教师之间流转
```

授权范围裁剪课节和节点时，不涉及字幕字段的裁剪逻辑，因为字幕不出现在学生交付课程包中；教师 `.kmcourse` 是完整课程迁移边界，不走授权范围裁剪。

## 7. 组件与职责

### 7.1 教师端

`SubtitlePicker`：

- 读取老师选择的 `.srt` 或 `.vtt`；
- 调用服务端临时检查/修复接口，再在本地解析返回文本并展示；
- 成功后同时上报字幕元数据、修复后的文本和解析后的 `Caption[]`；
- 替换或移除字幕时通知课节页面产生未保存修改。

`LessonPage`：

- 从草稿读取 `subtitle`；
- 使用共享解析器恢复 `Caption[]`、时间线和时长；
- 将字幕变化纳入 `dirty` 状态；
- 保存时提交 `subtitle + nodes + assets`；
- 保存失败或 revision 冲突时保留页面内未保存内容，不显示假成功。

`TeacherAPI`：

- 提供字幕临时检查/修复接口；
- 扩展 `ScriptDraft.config` 和 `saveDraft` 参数；

### 7.2 后端制作与发布模块

草稿校验：

- 字幕上传检查接口不写数据库，只返回修复后的字幕文档和变更说明；
- 仅对可确定的时间重叠做最小修复，无法安全判断的错误直接拒绝；
- `subtitle` 缺失时允许保存未完成草稿；
- 存在时要求对象字段封闭、版本为 `1`、文件名非空、格式为 `srt` 或 `vtt`、内容非空；
- 格式必须与文件名扩展名一致；
- 按 UTF-8 字节数限制请求大小；
- 后端至少验证文本能被对应格式识别，不能只相信扩展名；
- 字幕和节点任一不合法时不写入任何草稿字段。

草稿摘要：

- `content_digest` 覆盖字幕、节点和 assets；
- 替换字幕会产生新 revision，使旧预览失效；
- 相同保存请求仍遵守现有乐观并发规则。

发布快照：

- `ReleaseLessonSnapshot` 增加可为空的 JSON 字幕字段（草稿没有字幕时快照也留空，见第 5.4 节）；
- 发布不新增字幕存在性校验，只原样复制草稿字段；
- 发布快照只是服务端留档，不下发给插件。

### 7.3 教师课程导入导出文件

- `TeacherCourseFile` 导出增加字幕原文字段；
- 导入时校验结构与草稿相同的字幕字段规则；
- 这份文件的消费端只有教师端，不涉及插件或课程包代码。

## 8. 限制与可靠性边界

老师主动提供字幕，因此本设计不增加"字幕是否来自原视频"的来源核验，也不把它与视频平台字幕权利
绑定。

字幕仍然是跨浏览器和服务端边界的文件输入。为防止误选、损坏文件和超大请求影响保存，实施时至少需要：

- 只接受 `.srt` 和 `.vtt`；
- 文件名和格式一致；
- 内容非空且能解析出有效字幕句；
- 设置一个明确、可测试的 UTF-8 字节上限；
- 日志和普通错误信息不记录字幕正文。

当前实现将 UTF-8 字节上限确定为 5 MiB，服务端和前端共用同一数值并在导入时提前提示；若真实课程样本证明
该上限不足，应通过新的决策和兼容评估调整，而不是静默放宽请求。

## 9. 状态与失败处理

### 9.1 首次导入

1. 老师选择文件。
2. 浏览器解析成功后更新页面内字幕并标记未保存。
3. 保存成功后更新 revision，清除未保存标记。
4. 刷新页面后从服务端草稿恢复字幕。

### 9.2 替换字幕

替换只修改当前页面草稿。新字幕解析失败时继续保留当前字幕；解析成功但尚未保存时，离开页面沿用现有
未保存提醒。保存成功后，新字幕成为该课节当前草稿的一部分。

已存在的 `captionId` 可能不再指向新字幕中的同一句。实施时必须重新解析并检查引用：

- 能找到相同 `captionId` 且时间一致时保留；
- 找不到时保留节点的 `timeSeconds` 和正文，但将 `captionId` 设为 `null`；
- 不因替换字幕自动删除或改写节点正文。

### 9.3 移除字幕

移除字幕是显式草稿修改。由于创建节点强制要求字幕存在（第 2 节），移除字幕后教师无法继续新建节点，
但已有节点仍可编辑；保存不会因此被拒绝。

### 9.4 并发冲突

字幕和节点共享草稿 revision。发生 `REVISION_CONFLICT` 时不做字段级自动合并；页面重新读取最新草稿后，
由老师决定是否重新选择文件或重做未保存修改。

### 9.5 发布失败

- 快照字段不完整或写入失败：不生成发布记录；
- 课程包和插件行为不受本设计影响，继续按现有 v3 契约运行。

## 10. 兼容与迁移

本变更以 `D-V1-014` 接受为切换点，部署顺序为：

1. 部署支持 `subtitle` 草稿字段和发布快照字段的后端；
2. 同步发布支持该字段的教师端；
3. 已有草稿可以继续读取，草稿里没有字幕字段时按空值处理，不强制立即重新导入；
4. 学生课程包和插件不需要任何版本切换，因为字幕不进入学生交付包；教师 `.kmcourse` 使用独立的 v2 格式，详见 `12-course-package-format.md`。

不涉及课程包契约版本变化，因此不需要第三方（插件）配合发布节奏。

## 11. 测试与验收

### 11.1 教师端

- 上传真实字幕后先调用修复接口，修复说明显示且页面使用修复后的内容；
- 导入合法 SRT/VTT 后，保存请求包含对应 `subtitle`；
- 仅更换字幕也会进入未保存状态；
- 保存后刷新，字幕列表、文件名、时长和时间线恢复；
- 非法文件不替换当前字幕；
- 替换字幕后失效的 `captionId` 被清空，节点时间和正文保留；
- 保存冲突和网络失败不显示成功；
- 没有字幕时时间轴不可用、无法创建节点（回归验证 `FR-AUTHOR-012`）。

### 11.2 后端

- 修复接口对实际文件的重叠时间返回修复结果，不写入数据库；
- 修复后的字幕通过草稿接口保存并可重新读取；
- 不可修复输入返回稳定错误且不创建草稿；
- 字幕与节点能够在草稿中原子保存和读取；
- 非法版本、格式、扩展名、空内容、不可解析内容和超限内容整体拒绝；
- 替换字幕会改变 revision 和 `content_digest`；
- 旧 revision 的成功预览不能用于发布新字幕；
- 发布快照原样复制草稿字幕字段，草稿没有字幕时快照对应字段也留空；
- 发布快照在草稿字幕变更后保持不变。

### 11.3 教师课程导入导出文件

- 导出文件包含字幕原文，字段规则与草稿一致；
- 导入合法文件后新建草稿包含字幕；
- 非法字幕结构整体拒绝导入。

### 11.4 契约不变的回归覆盖

- 学生交付课程包生成结果不含字幕字段，`schemaVersion` 仍为 `3`；教师 `.kmcourse` 使用独立的 v2 ZIP 格式；
- 插件 `checkCoursePackage`、`InstalledLesson` 行为与改动前一致；
- 现有课程包契约测试和插件安装测试全部保持通过，不需要修改。

### 11.5 核心验收场景

老师创建课程和课节，选择字幕，添加节点并保存。关闭页面后重新进入，字幕和节点均恢复。老师完成预览并
发布，发布快照包含字幕。学生兑换课程后，插件本机安装记录中的该课节按现有 v3 课程包字段安装（不含
字幕），互动节点的触发时间点来自节点自身 `timeSeconds`，运行正常。老师之后替换草稿字幕，不改变已
交付的发布快照，也不影响学生已安装的课程。

## 12. 预计改动范围

本轮实施涉及：

- 教师端：`SubtitlePicker.tsx`、`LessonPage.tsx`、`api.ts` 及测试；
- 共享类型：字幕持久化类型和解析入口；
- 后端：草稿校验、路由映射、`ReleaseLessonSnapshot` 增加字幕字段、迁移、API 测试；
- 教师课程导入导出：`TeacherCourseFile` 导出/导入逻辑与测试；
- 文档：需求、领域模型、数据流、接口契约、测试计划和追踪矩阵。

**不涉及**：课程包 JSON Schema、插件校验代码、插件存储类型、示例课程包、契约版本清单、跨端安装测试。

## 13. 已替代的旧条款

本文不能只改代码。已在本轮审查中同步完成的需求文本修订：

- `FR-AUTHOR-001` → 由 `FR-AUTHOR-012` 替代：删除"无字幕时使用已确认视频时间创建节点"的从未实现分支，
  改为准确描述字幕是创建节点的强制前置条件；
- `FR-AUTHOR-002` → 由 `FR-AUTHOR-013` 替代：字幕全文默认只在教师本机用于制作，改为经保存草稿动作

## 14. 已确认事项

已在本轮审查中确认，不再是开放问题：

1. 每个发布课节是否必须有字幕——已确认不强制单独校验，发布只原样复制草稿字段；
