## 1. 目的与适用范围

本文件规定“在真实课程中增加一个节点”必须完成的设计、接口、存储、运行和验收工作。
它把一个节点视为从教师制作到学生学习的完整业务对象，而不是只在教师页面增加一个按钮或
只增加一个前端分支。

本标准适用于：

- 新增一种节点类型；
- 为已有节点增加会改变显示、输入、返回值、完成条件或本地记录语义的能力；
- 将一个已有节点拆成新的教学行为；
- 修改节点导致已发布课程或学生本机状态需要重新解释的情况。

只修改文案、颜色、图标或不改变数据与行为的布局调整，可以沿用原节点契约，不必创建新的节点类型。
但仍需通过对应页面和回归测试。

## 2. 统一原则

1. **先定义教学行为，再定义界面字段**：节点类型由学生和课程实际发生的行为决定，不由按钮名称决定。
2. **公共生命周期只有一套**：节点必须经过同一套身份、权限、草稿、保存、预览、发布、课程包、运行、
   本地记录和版本兼容流程。
3. **返回值、完成状态和本地记录分开**：学生提交的输入、系统判断结果、节点完成状态和进度统计不是同一个字段。
4. **服务端参与必须有明确理由**：当前 v1 的学生回答和学习状态只保存在本机；节点不因“以后可能需要”
   就新增服务端数据或接口。
5. **不静默猜测教学意图**：字段缺失、答案规则不完整、返回值无法判断或显示能力不足时，拒绝发布或
   显式降级，不用默认文案、默认答案或相邻节点替代。
6. **身份和语义一起考虑兼容**：节点 ID 不变不代表状态一定可以沿用；完成语义改变时必须改变
   `stateCompatibilityKey`。
7. **真实预览是发布前置条件**：节点必须在学生正式运行路径中验证，静态编辑器预览不能代替真实预览。

## 3. 新增节点必须回答的问题

设计评审前，以下问题必须全部有明确答案；任何一项仍为空，节点只能处于“设计中”，不能进入开发或发布。

| 方面 | 必须确认的内容 |
| --- | --- |
| 类型 | 节点的稳定 `interaction` 标识、教学目的、所属能力族、Schema 版本 |
| 触发 | 触发时机、触发依据、是否允许重复触发、前后跳转如何处理 |
| 显示 | 学生看到的标题、正文、选项、输入控件、反馈和不支持提示 |
| 学生动作 | 学生需要确认、选择、填写、提交、重试、跳过还是关闭 |
| 播放器 | 是否暂停、何时暂停、何时恢复、学生原本暂停时是否保持暂停 |
| 返回值 | 学生提交什么、系统返回什么、返回值是否可重试、是否幂等 |
| 完成 | 什么条件算完成、什么条件算进行中、跳过、关闭或不支持 |
| 本地记录 | 是否保存输入草稿、正式尝试、判断结果、反馈、节点结果和继续位置 |
| 服务端 | 后端只做结构校验，还是还要做计算、查询、持久化或权限判断 |
| 发布 | 节点是否进入草稿、真实预览、课程发布包和授权范围 |
| 兼容 | 新旧课程包能否互读，旧本机状态能否迁移，运行时不支持如何降级 |
| 安全 | 内容是否只作为文本处理，是否涉及敏感信息、外部请求或可执行数据 |
| 验收 | 如何验证教师制作、后端接口、发布、学生运行、本地恢复和异常路径 |

## 4. 节点定义卡

每个新增或语义发生变化的节点都必须建立一张定义卡。定义卡可以写入设计评审、需求变更或实现计划，
但必须在对应代码和测试完成前成为可检索的项目记录。

```markdown
### <节点名称>

- 节点 ID：
- 节点类型：
- 类型版本：
- 能力族：
- 教学目的：
- 触发条件：
- 是否暂停视频：
- 学生端显示：
- 学生操作：
- 输入字段：
- 返回值：
- 判断规则：
- 完成条件：
- 失败、重试和退出：
- 本地输入草稿：
- 本地正式尝试：
- 本地节点结果：
- 服务端职责：
- 草稿字段：
- 发布包字段：
- 是否需要节点专用接口：
- stateCompatibilityKey：
- 未知类型或不支持时的降级：
- 测试与真实预览要求：
```

### 4.1 类型身份

节点类型必须拥有稳定、封闭、可检索的标识。显示名称、颜色和图标不构成类型身份。

类型定义至少包括：

- `interaction`：运行时分派和 Schema 判别使用的稳定标识；
- `family`：教学能力族，用于共同能力和编辑器组织；
- 类型 Schema 版本；
- 类型专属 `display`、`evaluation` 和必要的 `effects` 结构；
- `stateCompatibilityKey` 生成规则；
- 当前支持的教师端、服务端、课程包和学生运行时版本。

类型标识一旦进入已发布课程，不得复用给另一种教学行为。若行为发生不兼容变化，应创建新类型或升级
类型版本，并明确旧版本的读取和运行策略。

### 4.2 触发与播放器行为

当前 v1 的共同触发基线是可信主播放器时间穿越节点的 `time_cross` 触发。节点定义必须说明：

- 触发时间的来源和允许范围；
- 播放倒退、拖动、刷新、单页导航和播放器重建时的处理；
- 已完成节点是否再次显示；
- 同一时刻多个节点的确定顺序；
- 节点开始前是否暂停；
- 提交成功、明确退出、保存失败和恢复播放失败时的播放器状态。

新增节点不得自行创建第二套播放器监听、时间计算或页面生命周期清理逻辑。节点运行时只接收公共运行时
提供的触发事件和播放器能力。

### 4.3 显示与学生动作

显示契约必须把“内容”和“动作”分开定义。至少说明：

- 静态内容：标题、正文、说明、选项、引用或反馈；
- 动态内容：当前输入、校验消息、提交结果和重试提示；
- 学生动作：确认、选择、填写、提交、重试、跳过、关闭；
- 每个动作之后的状态变化；
- 无障碍名称、焦点顺序和键盘可完成路径；
- 内容只作为安全文本或受控数据渲染，不执行 HTML、脚本、事件处理器或外部资源。

学生端窗口必须能够在页面内播放、全屏、页面滚动和宿主 DOM 重建后安全挂载或退出。

### 4.4 返回值与完成规则

返回值至少分成三层：

1. **学生输入**：学生实际提交的内容或确认动作；
2. **节点判断结果**：根据已发布规则得到的结构化结果，例如正确、错误、已提交或无需判断；
3. **节点结果**：本机学习状态中的 `NodeOutcome`，例如未开始、进行中、已完成、已跳过、
   已关闭未完成或运行时不支持。

节点定义必须说明：

- 返回值字段及其类型；
- 判断是否由客户端确定性完成；
- 重复提交是否返回相同结果；
- 判断失败时是否允许重试；
- 返回值是否需要服务端参与；
- 任何结果是否会影响课程进度。

“有返回值”不等于“节点完成”。例如，错误选择可以有完整判断结果，但节点仍然是进行中；
问答题可以有学生回答和教师参考反馈，但不产生自动正确率。

### 4.5 本地学习记录

节点应按实际需要声明以下记录，不得用一个 `completed` 字段代替全部事实：

| 记录 | 适用条件 | 说明 |
| --- | --- | --- |
| `NodeInputDraft` | 学生可能中途输入后离开 | 只保存未正式提交的输入，不计作尝试或完成 |
| `NodeAttempt` | 学生存在正式提交或确认 | 每次正式业务提交追加一条；重复消息必须幂等 |
| `NodeOutcome` | 节点有可观察终止状态 | 保存当前状态、完成依据和最后一次尝试引用 |
| `Progress` | 节点参与课节/课程进度 | 由当前发布范围和节点结果重新计算 |

本地记录必须绑定本机学习标识、课程、课节、发布版本和节点 ID。新增节点不应把回答、尝试、反馈、
学习位置或本机标识发送到服务端；如果确实需要上传或服务端统计，必须另行打开隐私、数据保留和报告需求。

## 5. 节点完整生命周期

```text
教学需求
  -> 节点定义卡
  -> 类型/字段/返回值/本地记录评审
  -> 前端注册与编辑
  -> 后端 Schema 校验
  -> 草稿保存与读取
  -> 真实预览
  -> 课程发布快照
  -> 课程包校验与安装
  -> 学生端触发与交互
  -> 本机尝试/结果/进度
  -> 新版本兼容迁移
```

每一阶段的职责如下：

| 阶段 | 必须完成的事情 | 失败时的要求 |
| --- | --- | --- |
| 设计 | 完成定义卡，明确所有开放问题 | 保持“设计中”，不进入发布 |
| 编辑 | 注册类型、展示字段、默认值和字段校验 | 不创建半成品节点 |
| 草稿 | 整体校验并保存完整节点集合 | 保留最近一次有效草稿 |
| 预览 | 使用学生正式运行路径验证真实行为 | 不把静态示意标记为通过 |
| 发布 | 生成不可变课程快照并记录类型版本 | 不产生部分发布版本 |
| 安装 | 插件独立校验课程包并原子安装 | 保留原课程和本机状态 |
| 运行 | 按公共时间线、窗口、提交和恢复规则执行 | 不支持时显式降级，不伪造完成 |
| 更新 | 按节点身份和兼容键迁移本机状态 | 不把状态挂到相邻或同名节点 |

## 6. 前后端接口边界

### 6.1 通用节点使用现有生命周期接口

只要节点的内容能够随课节草稿和课程发布包传输，节点不新增专用 HTTP API。

| 能力 | 当前承载边界 | 节点必须遵守 |
| --- | --- | --- |
| 草稿读取 | `GET /api/v1/teacher/lessons/{lesson_id}/draft` | 返回经服务端校验的完整节点集合 |
| 草稿保存 | `PUT /api/v1/teacher/lessons/{lesson_id}/draft` | 以整份草稿校验和保存，不接受局部旁路写入 |
| 真实预览 | 教师预览握手与学生运行路径 | 预览内容必须绑定已确认草稿版本 |
| 正式发布 | 课程发布接口 | 节点进入不可变课程发布快照 |
| 学生交付 | 兑换/更新返回课程发布包 | 学生端从本机课程包读取节点，不临时拉取草稿 |
| 学习记录 | Chrome 本机存储 | 当前 v1 不通过 HTTP 上传节点回答和结果 |

草稿接口的成功响应至少让客户端知道已确认的草稿内容、节点数量和更新时间；失败时不能把页面临时内容
标记为已保存。接口路径、信封、错误码和版本规则以
[`06-interface-contracts.md`](06-interface-contracts.md) 和实际 OpenAPI 为准。

### 6.2 何时允许新增节点专用接口

只有下列情况之一成立时，才可以为节点设计专用接口：

- 节点需要服务端持久化独立业务事实；
- 节点需要服务端访问教师或平台权限范围内的数据；
- 节点需要服务端执行客户端不能信任的计算；
- 节点需要异步任务、外部服务或可审计的服务端结果；
- 节点返回值必须跨设备、跨会话或供教师后续查看。

专用接口必须在定义卡中写明：

- 方法、路径和参与角色；
- 请求字段、响应字段和 Schema 版本；
- 服务端重新校验的权限、范围和节点身份；
- 幂等键、重复请求和结果未知时的处理；
- 错误码、是否可重试和原状态保护；
- 日志字段和禁止记录的节点正文、学生输入或凭证；
- 与课程发布版本、本机学习状态和删除保留策略的关系。

节点专用接口不能用来绕过草稿保存、课程发布、学生授权或本机学习状态边界。

### 6.3 服务端返回值的边界

服务端返回的对象应区分：

- **编辑返回**：已确认草稿和服务端修订信息；
- **发布返回**：不可变发布版本和课程包摘要；
- **运行返回**：当前 v1 不从服务端取得节点运行结果；
- **专用能力返回**：只有在专用接口获批后，返回服务端确实负责的业务结果。

服务端不得因方便调试而返回教师草稿中的完整字幕、学生本机回答、完整本机学习状态或敏感凭证。

## 7. 版本、兼容和未知类型

节点版本至少受以下三层共同约束：

1. 草稿 Schema 版本；
2. 课程包 Schema 版本；
3. 学生运行时支持矩阵。

发布时必须记录节点类型版本和 `stateCompatibilityKey`。更新时：

- 身份相同且兼容键相同：可以迁移可验证的输入草稿、尝试和结果；
- 身份相同但兼容键改变：按定义卡要求重置或标记不兼容；
- 节点新增：从未开始状态开始；
- 节点删除或超出授权范围：不把旧状态迁移到其它节点；
- 运行时未知类型：显示明确不支持状态并安全退出，不当作其它类型、不伪造完成；
- 非核心视觉增强不支持时可以省略，但不得改变题目、输入、反馈和完成语义。

## 8. 现有四类基线节点对照

下表是当前 v1 四类基线的最小对照。类型专属字段和精确 Schema 仍以实现契约为准。

| 节点 | 学生显示和动作 | 返回/判断 | 完成条件 | 本地记录 | 当前后端职责 |
| --- | --- | --- | --- | --- | --- |
| 重点内容 `notice` | 展示重点信息，学生确认继续 | 无题目判断；返回确认动作 | 学生明确确认 | `NodeOutcome`；通常无正式尝试 | 校验显示字段和公共节点结构 |
| 选择题 `choice` | 展示题干和多个选项，学生提交选择 | 返回选项 ID、正确/错误和预设解释 | 选择符合发布规则，或学生明确跳过 | 输入草稿、`NodeAttempt`、`NodeOutcome` | 校验选项、答案引用和反馈 |
| 填空题 `blank` | 展示题干，学生输入并提交 | 按发布的规范化规则判断答案 | 输入符合可接受答案，或学生明确跳过 | 输入草稿、`NodeAttempt`、`NodeOutcome` | 校验答案和规范化规则 |
| 问答题 `free_text` | 学生输入自由回答，提交后查看参考反馈 | 返回回答和已展示反馈，不自动判定对错 | 非空回答提交且反馈成功展示 | 输入草稿、`NodeAttempt`、`NodeOutcome` | 校验参考反馈；不保存学生回答 |

新增节点不能只复制其中一个组件的表面样式；必须重新填写定义卡，确认它的教学行为是否真的与现有类型相同。

## 9. 新增节点验收清单

### 9.1 设计与契约

- [ ] 定义卡所有字段已填写，没有未决的显示、返回、本地记录或服务端职责；
- [ ] 类型、Schema、`stateCompatibilityKey` 和课程包字段已定义；
- [ ] 公共字段和类型专属字段边界明确；
- [ ] 若有专用 API，已记录权限、请求、响应、幂等、错误和保留规则。

### 9.2 教师端与后端

- [ ] 节点可以创建、编辑、移动、复制和删除；
- [ ] 前端和后端对同一输入得到一致的结构校验结果；
- [ ] 草稿保存失败、并发冲突和刷新恢复不会丢失最近有效版本；
- [ ] 服务器不会保存不应保存的字幕、学生输入或页面临时状态。

### 9.3 预览、发布与课程包

- [ ] 真实预览使用已确认草稿和学生正式运行路径；
- [ ] 发布前节点字段完整，发布后快照不可变；
- [ ] 课程包包含运行所需字段且通过独立校验；
- [ ] 节点范围裁剪、授权和课程安装不会产生半个节点或越权内容。

### 9.4 学生运行与本地状态

- [ ] 正常触发、前后跳转、刷新、全屏和播放器重建行为明确；
- [ ] 显示、输入、提交、反馈和继续播放顺序正确；
- [ ] 返回值、完成状态和本地记录可以分别观察；
- [ ] 重复提交幂等，保存失败不伪造完成；
- [ ] 学生刷新或重新进入后可恢复定义中允许恢复的本地状态；
- [ ] 未知类型、不支持宿主和异常关闭都有安全退出路径。

### 9.5 版本更新

- [ ] 新增、修改、删除节点的状态迁移结果已测试；
- [ ] 不兼容节点不会把状态迁移到其它节点；
- [ ] 旧运行时对新类型给出明确不支持结果；
- [ ] 课程更新失败时旧课程和旧本地状态保持可用。

## 10. 新增节点工作流

今后新增节点按以下顺序执行：

1. 提出真实课程中的教学需求；
2. 填写本文件第 4 节定义卡；
3. 确认显示、学生动作、返回值、完成规则和本地记录；
4. 判断后端是否只需要通用草稿/发布校验，还是确实需要专用接口；
5. 更新需求、数据模型、接口契约和本文件中的节点对照；
6. 更新前端节点注册、后端 Schema、课程包和学生运行时；
7. 先写契约与生命周期测试，再完成实现；
8. 完成真实预览、课程发布包安装和本地状态恢复验证；
9. 更新版本支持矩阵、追踪矩阵、变更记录和相关决策；
10. 只有所有验收项通过后，才允许把节点放入正式发布课程。
