## 1. 目的与边界

本文件把课程从教师编辑到学生本机使用的主要数据流串成可实现、可测试的生命周期，回答：

1. 教师如何把已发布课程交付给学生；
2. 学生输入授权码后，服务端计算什么、返回什么，插件何时写入本机；
3. 课程发布、授权、兑换、安装、更新、到期、删除和恢复分别如何变化；
4. 失败、重复请求和部分结果如何保持安全的一致状态。

本文件不冻结具体 HTTP 路径、插件消息名称、数据库列类型或页面布局；这些内容分别在 06、07、08
中定义。它也不把当前代码的旧单课程下载链路直接当作目标设计。

## 2. 设计原则

### 2.1 交付对象先于存储表

学生取得的是一次完整的课程发布版本，而不是若干独立课节版本。服务端可以按课节保存快照，
但同一次课程发布必须作为一个整体生成、校验和安装。

### 2.2 三套生命周期分离

授权码负责在领取窗口内建立授权来源；有效资格由当前机器的全部有效来源合并；已安装课程是本机
已经完成的安装结果。任何一套状态变化都不能静默改写另外两套状态。

### 2.3 服务端裁剪，客户端确认

服务端只返回当前兑换关系允许取得的最新发布内容。插件仍须独立校验课程包，并在写入前向学生
展示课程、版本、范围和本机影响，由学生确认后原子安装。

### 2.4 失败保持原状态

授权失败、网络中断、响应畸形、校验失败或写入失败，都不能产生半个兑换关系、半个课程包或覆盖已有
课程。重试必须能够区分“未开始”“已成功”“结果未知”三种状态。

## 3. 总体数据流

```mermaid
flowchart LR
  T[教师编辑草稿] --> P[发布 CourseRelease]
  P --> A[创建 AccessCode 与 GrantItem]
  A --> C[教师交付原始授权码]
  C --> S[学生插件输入授权码]
  S --> V[服务端验证凭证与领取窗口]
  V --> R[建立 Redemption]
  R --> E[合并 EffectiveEntitlement]
  E --> F[从授权绑定的课程版本裁剪课程包]
  F --> Q[插件校验与展示安装摘要]
  Q -->|学生确认| I[原子安装 InstalledCourse]
  I --> L[本机离线学习]
  L --> U[后续检查升级关系/更新资格]
  U --> E
```

一条授权码不等于一个学生账号，也不把学生加入教师工作空间。一次成功兑换只在当前浏览器配置的
`LocalIdentity` 下建立一个可追溯的 `Redemption` 关系。

## 4. 教师发布与交付流

### 4.1 编辑到课程发布

1. 教师在自己的工作空间编辑一份课程草稿、按顺序维护多个课节和节点。
2. 保存的是可继续修改的 `ScriptDraft` 聚合；草稿保存不改变已经存在的已发布课程版本。
3. 教师确认发布时，服务端只校验课程至少有一节课节及必要的课程状态；测试预览、互动节点草稿和字幕不是当前发布前置条件。
4. 系统在一个事务中创建当前课程的不可变 `CourseRelease`，并为每个课节创建对应的
   `ReleaseLessonSnapshot`。
5. 发布成功后，新的 `release_id`、版本标识、课节顺序和内容摘要成为该课程的交付事实；课程从草稿区移入已发布区，课程级授权仍按 `course_id` 自动解析最新可交付版本。

发布失败时不得出现只有部分课节的新发布版本；当前草稿和此前其它已发布课程保持不变。

已发布课程的“修改本版本”和“增加版本”调用同一个后端版本操作端点：前者移除源发布并在原课程重建草稿，后者保留源发布并创建新课程草稿。失败或幂等重试不产生半份草稿，前端不通过多次普通端点模拟。

节点展示设置与正文遵循同一保存边界：

```text
打开/创建节点
  -> dialogNode（浏览器临时编辑状态）
  -> 保存节点（更新 LessonPage 内存中的 nodes，标记 dirty）
  -> 保存草稿（整节原子写入 v1_script_drafts.content）
  -> 发布（复制到 ReleaseLessonSnapshot / 课程包）
```

窗口大小、位置和样式位于对应 `nodes[].presentationHints`；结构化正文位于 `nodes[].content`。
创建课程只保存课程基础记录，创建课节只保存课节和 B 站 `videoRef`，两者都不会自动产生节点或草稿。
教师预览修改只先改变临时状态，不能绕过“保存节点”和“保存草稿”。

### 4.2 创建授权码

1. 教师选择一个已经发布的课程，配置课程、课节级或节点级 `GrantItem`。
2. 系统分别记录授权码领取窗口和授权项的现实有效时间；二者不混为一个过期字段。
3. 系统生成不可预测的原始授权码，在成功创建结果中只显示一次。
4. 服务端只保存授权码安全摘要、非敏感尾号、范围、时间、创建者和状态，不保存原文。
5. 只有授权码、范围和审计写入均成功后，教师才能复制原始授权码并交给学生。

教师可以把原始授权码通过人工认可的渠道转交。v1 不要求生成公开下载链接、学生云端账号或课程
文件附件；这些均不是授权码的隐含能力。

## 5. 学生首次兑换与安装流

### 5.1 输入与服务端处理

1. 插件首次运行时在当前 Chrome 配置中生成随机 `LocalIdentity`。
2. 学生输入授权码并提交；插件附带识别当前机器领取关系所需的最小本机证明。
3. 服务端按顺序检查：授权码摘要、领取窗口、来源状态、授权项时间、工作空间边界，并按授权 `course_id` 解析最新可交付
   `CourseRelease`。
4. 验证通过后，服务端在授权码使用上限检查与写入事务中创建或复用 `Redemption`。重复提交同一授权码和同一
   `LocalIdentity` 不制造第二条关系；默认已经存在 20 个不同标识时拒绝第 21 个新标识。
5. 服务端把当前机器的全部有效来源合并为 `EffectiveEntitlement`，再按有效范围裁剪课程包。

`LocalIdentity` 是插件本地生成的随机浏览器安装标识，不是硬件指纹，也不应单独充当长期授权秘密。用于后续免输授权码更新的本机证明必须由
06 接口契约和 08 安全设计明确其生成、保存、传输、轮换和丢失处理；当前建议使用本机保存的高强度
凭证，服务端只保存其不可反推摘要。

### 5.2 服务端返回内容

首次兑换的响应包含一个结果信封和零个或多个课程包：

- 协议/课程包 Schema 版本和请求关联标识；
- 安全的兑换结果引用和状态，不回显原始授权码或其摘要；
- 每门课程的课程标识、名称、`release_id`、发布版本、授权范围和安装类型；
- 当前授权范围内的完整课程发布包，包括有序课节、视频引用、节点、运行规则和内容摘要；
- 不包含密码、会话、授权码原文、完整字幕、教师私有页面状态、学生回答或学习状态。

如果授权有效但当前没有可交付课程，返回可解释的空结果，不返回课程正文。授权无效、过期或跨工作空间
时，不返回任何课程内容。

### 5.3 插件确认与原子安装

插件收到响应后按以下顺序处理：

1. 校验响应大小、Schema、课程与发布标识、课节顺序、视频引用、节点类型和禁止字段；
2. 对每门课程生成安装摘要，展示课程名、范围、版本、首次安装/更新状态和本机存储影响；
3. 等待学生明确确认；取消只丢弃候选包，不改变现有课程库；
4. 将候选包写入临时位置，完成摘要校验和结构校验；
5. 原子替换目标课程记录，保留其它课程和已有学习状态；
6. 写入成功后再更新 `AuthorizationSourceCache` 和安装提示。

同一 `course_id` 只保留一个当前安装版本。课程级授权可以自动取得该课程最新可交付发布版本；独立课程身份和跨独立课程版本升级待课程族
和升级关系能力完成后再处理。更新失败时已有课程仍可使用，不能留下新旧课节混合的课程。

## 6. 后续下载、更新与离线学习

### 6.1 免输授权码的在线更新

当本机仍保存有效的授权来源证明时，插件可以不要求学生再次输入原始授权码：

1. 插件发送本机证明和课程/版本查询意图；
2. 服务端重新合并全部有效来源，并在后续版本中检查课程族与课程升级关系；
3. 当前服务端按授权码绑定的 `course_id` 返回该课程最新可交付 `CourseRelease`，或明确的“无需更新”；跨独立课程升级只有后续课程族关系生效后才允许；
4. 插件先展示版本、范围和本机学习状态迁移影响；
5. 学生确认后，以一次原子操作完成课程包和可安全迁移的学习状态更新。

如果本机证明丢失、换机或被清除，当前机器不自动恢复为原机器身份；学生需要在仍可领取时重新输入
授权码。跨设备同步不属于 v1 承诺。

### 6.2 离线运行

安装成功后的课程结构、节点和学习状态保存在当前浏览器本机。网络不可用时：

- 已安装且已确认的课程仍可按本机规则学习；
- 不创建新的服务端授权关系；
- 不声称已取得最新发布版本；
- 在线更新失败不删除或锁死已有课程。

### 6.3 资格失效

授权码使用数量达到上限、领取窗口结束、授权项到期、授权来源被终止、课程归档或服务暂时不可用，只影响未来在线兑换、
重新下载和更新。系统不远程删除学生已经安装的课程和学习状态。

## 7. 学习运行时数据流

1. 学生从本机课程库选择课程和课节，建立锁定课程、课节和 `release_id` 的学习会话。
2. 插件根据当前发布快照加载有序节点和视频引用；不从服务端临时拼接运行内容。
3. 同一视频存在多个合法课节候选时，先让学生选择，再由会话锁定选择结果；不能静默取第一条。
4. 播放位置、草稿、正式尝试、节点结果和聚合进度分别写入本机学习状态。
5. 课程库更新时，只迁移能够通过稳定节点标识和兼容规则对应的状态；不能安全对应的状态保留在旧
   版本历史或明确标记为未迁移。

服务端不接收完整字幕、学生回答或运行时学习状态。教师在 v1 只能看到其工作空间中的课程、发布快照和授权操作
结果，不能据此读取学生本机学习记录。

## 8. 状态、幂等与失败恢复

### 8.1 关键状态变化

| 对象 | 正常状态 | 允许的主要变化 | 不允许的隐含变化 |
| --- | --- | --- | --- |
| 已发布课程/`CourseRelease` | 草稿校验后已发布 | 创建、按教师选择移除、归档或建立升级关系（后续） | 原地修改已发布正文；自动把版本级授权转给其它课程 |
| `AccessCode` | 可领取、已失效、已终止 | 创建、领取窗口结束、终止；所属教师可在管理页重新显示完整码 | 数据库或普通日志保存原文；向非所属教师返回完整码 |
| `GrantItem` | 未生效、有效、到期 | 随授权来源创建并按时间生效/结束 | 已领取后静默扩大或缩小范围 |
| `Redemption` | 成功关系 | 首次创建、重复请求复用 | 失败请求留下半条关系 |
| `InstalledCourse` | 候选、当前、被新课程替代、明确删除 | 原子安装、后续升级、学生主动删除 | 在线失效远程删除；把不同课程身份合并为一个版本 |
| 学习会话 | 未开始、进行中、暂停、结束 | 由学生操作和运行事实推进 | 课程更新热切换当前会话 |

### 8.2 重试规则

- 教师发布和授权码创建使用服务端幂等键；网络超时后重试不创建重复发布或重复来源。
- 学生兑换使用“本机身份 + 授权来源”的唯一关系；重复提交返回同一有效关系和当前结果。
- 授权码设备/浏览器数量限制使用同一事务内的计数和登记；超限请求不创建关系，也不返回课程包。
- 插件安装使用临时区、校验、提交标记和恢复点；进程中断后启动时清理未提交候选或恢复旧版本。
- 任何失败响应都不把“请求已发送”显示成“课程已安装”。

### 8.3 删除与保留

- 教师归档课程、终止授权来源和删除草稿，分别只影响各自领域状态。
- 学生明确删除本机课程时，同时删除该课程的本机学习状态和授权来源缓存；不影响服务端授权来源，
  仍具资格时可再次下载。
- 服务端不保存学生课程正文和学习状态；授权来源、兑换关系和操作审计按 08 的最小保留策略保存。
- 任何恢复都以完整发布包和摘要校验为前提，不能从普通日志拼回授权码、课程正文或学生回答。

## 9. 当前实现与目标流的关系

当前 v0.9.1 已验证“输入授权码—服务端验证—返回 `courses`—插件本机安装”的最小链路，但它仍是
一次性下载近似授权关系：请求主要只有 `access_code`，响应缺少正式兑换关系、有效资格并集、安装前确认
和免输授权码更新所需的本机证明。

因此迁移时应复用已验证的课程包结构校验、下载失败不覆盖和本机多课程存储经验；不得把旧的单课程优先级、
按课节发布版本、静默安装或“最后一次授权覆盖此前资格”带入 v1。当前课程级授权自动解析最新可交付版本，独立课程身份、草稿消费、
版本操作和版本级授权后置；以 `D-V1-018`、`D-V1-019` 为准。

## 11. 本文件完成条件

本文件通过人工审核前，至少应确认：

1. “课程发布—授权码交付—学生兑换—确认安装—更新/离线”主链路没有未定义的业务跳转；
2. 授权码、有效资格、本机课程和学习状态的生命周期互不混淆；
3. 失败、重复、超时、中断和删除都保持原状态或有明确恢复点；
4. 课程包返回字段、安装前确认和本机证明的接口细节可由 06 继续冻结；
5. 当前代码只作为迁移证据，不被误写成已完成的 v1 能力；
6. 本文件中的 `SRC-*` 承接与 02 的全量登记一致。
