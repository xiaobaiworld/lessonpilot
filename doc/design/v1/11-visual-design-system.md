## 1. 文档目的

本文件是 KnownMap 四个 UI 表面（销售站点、教师端、管理端、学生插件）的视觉真源，回答三个问题：

1. 视觉语言是什么：色彩、字体、间距、圆角、阴影、动效的唯一取值集合；
2. 四个端如何收敛到同一套语言：各端改什么、不改什么；
3. 如何防止再次漂移：token 单一真源、消费链路与自动门禁。

本方案只做视觉与样式工程规划。它不改变 [`07-product-interaction-state.md`](07-product-interaction-state.md)
冻结的页面职责、交互状态机、确认时机和状态含义；该文件已明确不冻结颜色、字体、组件库与逐像素布局，
本文件承接的正是这一层。

## 2. 设计记忆点

一句话记忆点（2026-09-01 人工确认）：

> 学生在 B 站视频里上课，不是在网页里看课。

所有视觉决策向它对齐：界面应当感觉像「长在视频里的一节课」，而不是「一个套着视频的管理后台」。
教师端是备课的纸，学生端是课堂本身。

视觉主张：一张铺开的备课纸——暖纸为底、墨色写字、品牌绿行事、粉笔黄做记号。

### 2.1 方向决策（2026-09-01 定稿）

同一品牌的三种处理强度经示意图对比后评审（对比页：`tmp/ui-direction-sketches.html`，方向定稿后可删）：

| 方案 | 处理 | 结论 |
| --- | --- | --- |
| A · 纸绿收敛 | 纸底纸顶栏，绿只给行动，黄只做记号 | **选定**。暖纸底即差异化；教师每天长时间使用，舒适度达标；现有 token 大多已在用，实施风险最低 |
| B · 深绿框景 | 深绿顶栏与框架，内容区纸底 | 排除。品牌存在感最强，但深色框架长期压顶，备课场景压感重，管理后台感偏强 |
| C · 白纸淡墨 | 近白底细线、绿色极少 | 排除。最冷静但丢掉纸的温度后，与效率工具趋同，差异化变弱 |

选定 A 的细化规则：**深绿 `--brand-deep` 降级为「瞬时场景色」**——只出现在站点 hero、插件学习窗标题条、
完成态等出场率低但记忆最强的位置；日常界面（教师端、管理端、popup）的顶栏与框架一律纸底，
不用深绿做常驻框架。决定性标准是教师端的长时间使用舒适度。

## 3. 现状诊断

结论先行：问题不在视觉品味，纸感墨绿的品牌语言成立且符合当前教育科技产品的设计趋势；
问题在于缺少单一真源，同一套品牌被四个端各自抄写、各自漂移。本方案的核心动作是收敛，不是换皮。

### 3.1 四端事实（2026-09-01 对 main 分支的源码审计）

| 端 | 技术形态 | 页面/表面 | 核心问题 |
| --- | --- | --- | --- |
| 教师端 `v1/web/teacher/` | React 18 + Vite + 纯 CSS，无组件库，query 参数路由 | 登录、课程总览、课程详情、课节编辑器、授权码管理共 5 页 | 样式三层叠加；含旧工作台死样式；`--muted` 等变量未定义即在用；发布与授权码入口分散在列表页和详情页两处 |
| 管理端 `v1/web/admin/` | 同栈，仅登录 + 教师/试用管理 2 个视图 | 2 视图 | 与教师端强共享 `@v1/web-shared`，随共享样式治理自动受益，几乎零独立成本 |

### 3.3 外部参照（2026-09-01 调研摘要）

- 课程 SaaS 后台（小鹅通等）以蓝色系、高信息密度为通病，视觉同质化严重；纸绿方向是天然差异化。
- Linear / Notion 的系统性做法值得借用：token 按角色命名而非按颜色名；层级靠表面分层加细线而非
  阴影堆叠；单一字族、字重与字距承担层级；4px 间距基准；强调色克制、一屏一个主行动。
- 暖纸质感是当前教育科技产品的正向趋势：降低屏幕眩光、利于长时间阅读、传递人的温度。
  KnownMap 的现有方向与之同频，应当收好而不是改掉。

## 4. 设计原则

| 原则 | 做法 | 参照 |
| --- | --- | --- |
| Token 按角色命名 | `canvas / surface / ink / brand / accent`，禁止按颜色名命名（green-500 式） | Linear、Notion |
| 层级靠分层不靠阴影 | 纸面分 canvas → surface → sunken 三级 + 1px 细线；阴影只留给弹窗浮层一档 | Linear 表面阶梯 |
| 单一字族 | 四端统一 `"Avenir Next", "PingFang SC", "Microsoft YaHei", sans-serif`；层级靠字重与字距，不靠字号跳跃 | Notion 单字族 |
| 4px 间距基准 | 4 / 8 / 12 / 16 / 24 / 32 / 48 共七档，其余数值视为违规 | Notion 间距纪律 |
| 强调色克制 | 品牌绿只给主行动与品牌件；粉笔黄只给「起点/待处理」记号；一屏一个主 CTA | Linear 单色克制 |

插件弃用 B 站青蓝的理由：青蓝是宿主平台色，不是品牌色。学生的学习场景就在 B 站蓝色页面里，
KnownMap 的墨绿浮层反而能跳出来——与宿主页面拉开才是识别度。学习窗（`content/window.css`）
早已向 web 色板对齐，说明方向本身已定，缺的只是收口。

## 5. 设计 token 系统

### 5.1 真源与消费链路

- 上游唯一真源：[`../../../v1/assets/brand/knownmap-tokens.json`](../../../v1/assets/brand/knownmap-tokens.json)
  的颜色与几何定义继续有效，其「页面和插件禁止另写一套色」规则不变。
- 新增工程产物：`tokens.css`，由 tokens.json 单向生成（脚本生成，禁止手改），定义下文全部 CSS 变量。
- 四端消费方式：web 端（教师/管理）经 shared 样式 `@import`；站点在发布流程中拷贝；插件构建期
  `?inline` 注入 Shadow DOM。任何端不得再手抄 hex。
- 防漂移门禁：`tools/` 新增样式检查，`tokens.css` 之外出现不在阶段 0 历史基线中的裸 hex 即失败，
  并入 `npm run check`；历史基线按 `D-V1-031` 在阶段 1–4 逐端清零。

### 5.2 色彩角色

| 变量 | 值 | 角色 | 来源 |
| --- | --- | --- | --- |
| `--canvas` | `#F5F1E7` | 页面底 | 现 `--paper`，归位站点漂移 |
| `--surface` | `#FFFDF8` | 卡片/浮层 | = 品牌 `pathStroke` 色 |
| `--sunken` | `#EDE8DA`（新） | 凹陷区、时间轴轨道 | 新值，阶段 0 校准后冻结 |
| `--ink` | `#16251F` | 主文字 | = 品牌 `wordmarkInk` |
| `--ink-2` | `#43544C`（新） | 次级文字 | 新值，阶段 0 校准后冻结 |
| `--ink-3` | `#6E9180` | 辅助文字 | = 品牌 `foldStrokeOnLight`，直接复用 |
| `--line` | `#D8D2C2`（新） | 浅底细线 | 新值，阶段 0 校准后冻结 |
| `--line-on-dark` | `#CFE4D8` | 深底细线 | = 品牌 `mapStroke` |
| `--brand` | `#1D5C43` | 主行动、品牌件 | = 品牌 `brandGreen` |
| `--brand-deep` | `#103B2B` | 瞬时场景：站点 hero、学习窗标题条、完成态；不作日常界面框架色（见 2.1） | = 品牌 `containerGreen`；`base.css` 的 `--green-deep #123b2c` 归位到此值 |
| `--accent` | `#D9A51E` | 记号、待处理 | 现 `--chalk` |
| `--end` | `#C56E52` | 完成态、终点 | = 品牌 `pathEnd` |

语义色映射：成功用 `--brand` 系，警告/待处理用 `--accent` 系，危险在 `--end` 赭红方向校准（阶段 0
与对比度一起定），信息用 `--ink-2`。编辑器节点语义色（`--voice`、`--activity`、`--ai` 等）保留，
但按 tokens.json 的规则它们不是 Logo 端点色，阶段 2 统一校准到相同明度/饱和度带。

### 5.3 字阶梯

单一字族六档，数字一律 `tabular-nums`（表格、时间轴、授权码列表）：

| 档位 | 字号/行高 | 字重 | 字距 | 用途 |
| --- | --- | --- | --- | --- |
| display | 28 / 1.25 | 650 | -0.01em | 页面级标题；销售页 hero 可放大至 40–48 |
| title | 22 / 1.3 | 650 | -0.01em | 页面标题、区块大标 |
| head | 17 / 1.4 | 590 | 0 | 分组标题、卡片标题 |
| body | 15 / 1.6 | 400 | 0 | 正文、表单、表格主体 |
| small | 13 / 1.5 | 400 | 0 | 辅助说明、元信息 |
| micro | 11 / 1.4 | 590 | +0.02em | 标签、徽标、表格辅助列 |

字重只用 400 / 590 / 650 三档；层级靠字重与墨色深浅（`--ink` → `--ink-2` → `--ink-3`）组合，
不再新增字号。

### 5.4 间距、圆角、阴影、动效

- 间距：4px 基准，取 4 / 8 / 12 / 16 / 24 / 32 / 48 七档。
- 圆角：控件 6px、卡片 8px、标签与徽标全圆。现 `--radius: 6px` 保留为控件档。
- 阴影：仅浮层一档（弹窗、popover）：`0 18px 48px` 墨色 12%；卡片与分区一律用表面分层加细线。
- 动效：150–200ms ease-out；状态变化用颜色与位置，不用弹跳；必须尊重 `prefers-reduced-motion`。

## 6. 四端方案

### 6.1 教师端（重点投入）

1. 新增标准 PageHead：页面标题 + 状态徽标 + 唯一主 CTA 右置。把分散在课程列表与课程详情两处的
   「发布」「授权码」入口收拢到对应页面的 PageHead；页面职责边界不变。
2. 课程总览：草稿卡片网格突出「继续制作」，已发布课程表格化；分组标题带计数徽标；统计条 token 化。
3. 课程详情：课节表格化，操作收进 PageHead 与行内操作，返回链样式统一。
4. 授权码管理：创建面板、表格、详情侧栏全部并入 token 体系，`teacher/index.css` 补丁层清零。
5. 课节编辑器（体量最大，最后做）：时间轴与字幕轨视觉重做（`--sunken` 轨道 + 校准后的节点语义色），
   节点属性弹窗、节点插件条、预览画布 token 化；弹窗交互与两步保存流程不变。

### 6.2 管理端

零独立设计：随 shared 样式治理自动升级。仅有的 `.trial-applications` 补丁样式迁入页面层并 token 化。

### 6.3 销售站点

1. 三个 HTML 页接入 tokens.css（发布流程从真源拷贝，站点不做构建改造）。
2. 字体从系统栈切回统一字族；纸色 `#f4f0e6` 归位 `--canvas`。
3. Logo 统一引用品牌 SVG 并同步 favicon，不再使用 PNG 副本；`student-guide.html` 的文字 KM 方块
   替换为正式字标。
4. Hero 应用 `--brand-deep` 深绿容器 + 纸面内容，呼应 Logo 的地图折线几何；四步机制与嵌入式
   工作台示例的信息结构不变。

### 6.4 学生插件

1. popup、options、伙伴浮层的青蓝体系整体换为纸绿 token（构建期 `?inline` 注入 Shadow DOM）。
2. 学习窗 `window.css` 从手抄 hex 改为引用 token，与 web 同源。
3. 伙伴设置双实现合并：popup 内屏为唯一设置入口；options 页复用同一渲染或降级为引导说明页。
4. 清理遗留 `VideoModeControl` 死代码，降低认知成本。
5. 角色包视觉资源继续走 `D-V1-026` 的网站目录与按需下载边界，本方案不改变资源交付方式。

## 7. 实施路线

六个阶段，每阶段独立可验收；阶段 0 与 1 是地基（真源先行，否则重做还会漂移），
阶段 2/3/4 在三端上可并行，站点放最后是因为它直接承担转化，值得用前两阶段沉淀的成熟 token。

| 阶段 | 内容 | 产出 | 验收门禁 |
| --- | --- | --- | --- |
| 0 | tokens.json → tokens.css 生成脚本；定义全部角色变量；新值（`--sunken`、`--ink-2`、`--line` 与危险色）做对比度校准后冻结；`tools/` 新增样式 lint | tokens.css + 生成脚本 + `check:style` | `npm run check` 拦截新增裸 hex，历史基线按 `D-V1-031` 过渡；四端构建消费同一文件 |
| 1 | Web 共享样式收敛：审计 base/supplement 共 4224 行，标记活/死样式（旧工作台、三栏 timeline、copilot 残留），三层合并为 tokens → base → 页面；修未定义变量 | 收敛后的 shared 样式 + 死样式清单入档 | 页面截图对比无回归；web CSS 总量降到 3000 行内 |
| 2 | 教师端按页重做：登录 → 课程总览 → 课程详情 → 授权码 → 课节编辑器；只动样式与布局，不动路由、状态机与保存流程 | 5 页新视觉；teacher 补丁层清零 | 逐页人工走查；现有 vitest 与人工验收流程全绿 |
| 3 | 插件统一：青蓝退役、window.css 改 token、伙伴设置单实现、清理遗留控件 | 插件单一视觉语言 | 插件版本按规则升级；B 站页面实机走查 |
| 4 | 站点接入：tokens.css、字体归位、Logo 换 SVG、hero 深绿容器 | 站点与产品同源 | 三页与教师端并排一致性走查 |
| 5 | 沉淀与防复发：本文件状态转冻结；`check:style` 并入 CI；实施中的取舍登记为决策 | 冻结的视觉真源 + CI 门禁 | 后续 PR 由 lint 自动拦截漂移 |

## 8. 边界

本方案明确不做以下事情：

1. 不改变 [`07-product-interaction-state.md`](07-product-interaction-state.md) 冻结的页面职责、
   交互状态机、确认时机、状态文案含义与失败恢复路径；
2. 不修改品牌真源 tokens.json 的颜色与几何；新增的工程 token 只引用或校准，不另立品牌色；
3. 不引入 UI 组件库或 CSS 框架（维持纯 CSS，治理结构而非换工具）；
4. 不改变插件功能、权限、资源交付方式与发布流程；
5. 不为销售站点引入构建链。

### 10.3 量化验收标准

- 对比度：正文文字 ≥ 4.5:1，大标题与图标 ≥ 3:1（WCAG AA）；新 token 校准以此判定合格。
- 截图基线：阶段 1 动手删改之前，先对教师端 5 页 + 管理端 2 视图各截一张基线图存档
  （放 `tmp/` 或本机目录，不入库）；阶段 1/2 的「无回归」以与基线对比为准。
- CSS 总量：阶段 1 完成后 web 端 ≤ 3000 行（当前 5724）；阶段 3 完成后插件 CSS 中零裸 hex。
