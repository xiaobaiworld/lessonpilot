## 1. 目的与迁移原则

v1 的迁移源不是抽象的“旧系统”，而是三类不同事实：

1. `main@0e503a4` 及之后可能已经进入生产的服务端账号、工作空间、课程、课节、草稿、发布和授权；
2. 已分发的插件 `v0.9.1`、其固定 ZIP 内容，以及学生机器上可能存在的课程和学习状态；
3. 历史原型、测试数据、旧页面路径、旧存储键和已被否决的单课程契约。

迁移设计遵循：

- 先清点精确提交、产物摘要、数据库版本、存储版本和真实用户路径，再决定是否转换；
- 真实服务端权威数据默认保护，不因重构方便直接清库；
- 只有稳定身份、版本语义和内容完整性都能证明兼容时，才自动迁移；
- 无法证明兼容的内容进入隔离/重新领取路径，不猜测身份、不伪造历史、不静默丢弃；
- 切换前必须有可识别恢复点，切换失败可停止、回退或恢复，不制造新旧结构混合；
- 旧入口只有在没有活跃生产、用户、插件、数据或追溯责任后才能退役。

## 2. 迁移对象处理分类

每一个旧对象、文件、接口、存储键和页面入口必须归入一个处理结论：

| 结论 | 含义 | 允许的动作 |
| --- | --- | --- |
| 保留 | 结构和语义可直接由 v1 使用 | 原样保留或只做无损包装，记录身份映射 |
| 转换 | 内容有价值且兼容规则可证明 | 在 staging 转换，校验、对账后原子提交 |
| 重新生成 | 旧事实不能安全携带，但可从权威源重建 | 保留来源关联，生成新的 v1 身份/版本，不伪造旧历史 |
| 明确拒绝 | 与 v1 目标或安全边界冲突 | 不进入运行路径，给出重新创建/重新领取说明 |
| 弃用 | 暂时保留追溯或兼容责任，但不再扩展 | 标记消费者、替代项、删除条件和验证证据 |

“代码存在”“文档说已完成”“版本号相同”都不是迁移成功证据。

## 3. 迁移源清点

正式迁移前建立一份带时间戳的清单，至少包含：

| 对象 | 必须记录 | 未知时的处理 |
| --- | --- | --- |
| 服务端数据库 | schema/migration 版本、表轮廓、对象数量、工作空间归属、凭证/授权摘要来源 | 停止对应范围迁移，不从标题或顺序猜身份 |
| Web/API 构建 | Git 提交、构建时间、依赖锁、OpenAPI/Schema 版本、产物摘要 | 不把工作区未推送代码当作已发布来源 |
| 插件分发物 | ZIP 文件内容、SHA-256、扩展版本、manifest、课程库存储版本 | 不能用版本号推断本机结构兼容 |
| 学生本机样例 | 存储根、`storage_schema_version`、课程包 Schema、课程/课节/节点稳定身份 | 复制为只读样例并标记未知，不自动改写原存储 |
| 旧入口/链接 | 生产路由、用户书签、插件调用、文档引用和重定向责任 | 暂不删除，先建立替代或明确拒绝页 |
| 旧文档/证据 | `SRC-*`、验证时间、独有内容和新真源回链 | 留在审计/证据区，不能继续作为目标指导 |

清单本身必须是只读证据；实际转换另生成带来源、目标、执行者、时间、结果和摘要的迁移记录。

## 4. 服务端迁移

### 4.1 身份与归属

保留或建立旧新映射：管理员、教师、唯一工作空间、课程、课节、草稿、发布、授权和审计目标均使用稳定 ID。
不得使用课程标题、课节顺序、BVID、创建时间或数组位置推导身份。一个旧对象出现多个候选映射时，隔离该对象
并要求人工处理，不自动合并或换工作空间。

迁移后必须对账：

- 教师与唯一工作空间关系；
- 课程—课节层级和顺序；
- 草稿来源与修订；
- 旧发布与新 `CourseRelease` 的来源关系；
- 授权码摘要、授权项范围、状态和领取关系；
- 操作审计与目标对象的弱关联。

### 4.2 发布模型转换

当前按课节保存的 `PublishedScript` 不能直接成为 v1 用户可见发布版本。只有在一次课程发布的课节集合、顺序、
视频引用、节点内容、权利确认和摘要都能确认时，才转换为一个 `CourseRelease + ReleaseLessonSnapshot × N`。

无法确认整门课程原子边界的旧发布：

- 保留为迁移来源和只读证据；
- 不拼成伪造的课程级发布；
- 不作为新的可交付版本；
- 由教师重新预览/发布，或明确标记需要重新制作。

### 4.3 授权与凭证

- 密码验证值只有在目标系统能按原算法和必要参数安全验证时才保留；否则进入受控重置流程，不导出明文。
- 授权码摘要只有在验证密钥、摘要算法、授权来源、范围和时间都能对账时才继续有效；否则不生成新密钥冒充迁移成功，
  由教师重新发放授权码。
- 已成功领取的关系不能被重复迁移成多条；迁移后的 `Redemption` 必须能回溯来源和本机学习标识摘要。
- 未能证明的授权关系不贡献有效资格，也不删除已有已安装本机内容。

## 5. 学生本机迁移

### 5.1 可兼容迁移门禁

自动迁移前必须同时确认：

1. 本机存储版本可识别；
2. 课程包 Schema 能由 v1 校验器完整读取；
3. `courseId`、`lessonId`、`nodeId` 和 `releaseId` 等稳定身份存在且不冲突；
4. 课节顺序、节点类型和完成语义与 v1 一致；
5. 继续位置、草稿、正式尝试和节点结果可以逐项映射；
6. 摘要和结构校验通过，且迁移失败可以恢复旧根。

只要一项无法证明，就不自动迁移受影响对象。

### 5.2 旧单课程键

历史 `{ "course": ... }`、`installedCourse`、`learningState` 等无稳定多课程身份的键不自动转换。发现它们时：

- 以只读方式识别并记录存储版本和最小摘要；
- 不从 BVID、标题、安装时间或节点顺序生成伪身份；
- 不在未确认前删除原键；
- 向学生说明当前版本不支持直接迁移，并提供重新输入仍有效授权码重新下载的路径；
- 若未来决定提供人工转换，必须单独建立转换工具、映射证据和回滚点。

### 5.3 新旧插件并存

插件更新前先识别 manifest、扩展版本、课程包 Schema 和本机存储版本。不支持的组合显示“需要升级/重新领取”，
不静默清空旧课程或把旧响应写进 v1 课程库。新插件只有在新课程包完整校验并安装成功后，才能标记 v1 课程可用。

## 6. 契约与用户升级路径

### 6.1 组件切换顺序

```text
清点与恢复点
    ↓
候选 API/课程包/消息 Schema 与数据库迁移
    ↓
代表性副本迁移 + 对账 + 自动化/手工核心路径
    ↓
先部署能安全拒绝旧版本的服务端
    ↓
发布匹配的教师 Web/API/插件构建
    ↓
小范围人工验证：登录 → 制作 → 发布 → 兑换 → 安装 → B 站运行
    ↓
扩大使用或回退
```

新旧组件不能在未声明支持矩阵时混用。服务端先具备版本识别和安全拒绝能力，避免旧插件把新响应当作旧结构；
插件升级需要固定 ZIP、摘要校验和明确手动刷新步骤，不能把下载成功等同于课程迁移成功。

### 6.2 用户可见迁移

- 教师：登录后看到原有可确认课程/草稿及需要重新发布的对象；发布模型变化必须显示“需要重新预览/发布”，不伪装成旧版本已转成新版本。
- 学生：可继续使用已验证兼容的本机课程；不兼容旧存储显示重新领取路径；重新领取不要求注册学生账号。
- 管理员/支持：可看到迁移批次、对象数量、失败原因和恢复点摘要，但不看到密码、授权码原文、学生回答或完整课程正文。
- 公开用户：旧销售页、表单和产品入口在切换期间必须保持真实状态；不可访问或未批准的旧入口显示明确替代/人工联系信息。

## 7. 演练、对账与切换门禁

### 7.1 演练数据集

代表性副本至少包含：多教师/多工作空间、多个课程和重复课节、多个发布版本、多个授权来源、有效/失效授权、
损坏或不完整课程包、旧单课程键、学生本机多课程库、节点状态和正在进行的学习会话。

测试数据必须匿名，不使用真实密码、授权码、联系方式或学生回答。副本访问受限，演练后清理或隔离。

### 7.2 对账项目

迁移前后对账：对象数量、稳定 ID、工作空间归属、课程/课节顺序、发布版本、视频引用、授权范围、凭证可验证性、
审计关联、本机课程摘要和可迁移学习状态。任何数量变化都必须有固定原因码：转换、重新生成、拒绝、重复合并或人工隔离。

### 7.3 切换门禁

只有以下结果全部通过才切换：

1. 服务端恢复点已建立并能读取；
2. 数据库迁移在代表性副本可重复执行，重试不重复写入；
3. Web/API/插件/课程包版本支持矩阵一致；
4. 管理员登录、教师登录、课程保存、课程级发布、授权创建、学生兑换、安装和 B 站运行均通过；
5. 旧版本被拒绝时不产生半写入、不清空原数据；
6. 真实目标环境版本、健康状态、日志和回退目标可识别。

## 8. 回退与恢复

### 8.1 代码/版本回退

发布候选失败时回退到上一份已验证的 Web/API/插件发布组合，而不是只回退单个文件。回退后重新检查数据库 Schema、
课程包契约和插件兼容性；不能让旧代码连接已不可逆的新结构。

### 8.2 数据迁移回退

数据库迁移必须优先设计可逆步骤；不可逆转换必须在恢复点和副本对账通过后执行。发现归属、版本或授权关系错误时，
停止受影响范围，恢复到迁移前恢复点或使用明确的补偿迁移，不从日志猜测原始正文。

### 8.3 本机回退

插件课程安装/迁移只替换当前课程的原子根；失败保留旧根和隔离候选。旧存储无法读取时，不自动清除整个扩展存储；
用户可以重新领取课程，支持人员只处理最小版本/错误摘要。

## 9. 旧入口、旧文档与退役

旧页面、API 路径、存储键、品牌名称、插件消息和文档只有在以下条件全部满足后才可删除：

- 已识别所有生产、用户、插件、数据、书签和文档消费者；
- 已有替代路径或明确拒绝/重新领取路径；
- 已完成迁移与回归验收；
- 旧入口不再承担恢复、追溯或安全处置责任；
- `SRC-*` 来源、当前索引和发布记录已更新。

在此之前，旧入口可以只读、重定向或返回版本不兼容提示，但不再增加新功能。旧文档在对应新真源和链接收口前保留；
归档不等于删除证据。

## 10. 已接受的迁移决策

根据 `D-V1-012`：

1. 当前服务端没有具有保留价值的正式业务数据，也没有正式课程发布；v1 从新的初始化数据开始，不迁移旧账号、工作空间、
   课程、草稿、发布或授权；
2. 当前没有需要保留的学生本机课程或学习数据；v1 不提供旧学生本机数据迁移，新的插件存储从新的 Schema 开始；
3. 旧数据库、插件产物和本机存储只保留为只读历史证据，不被 v1 运行时读取或覆盖，物理清理另按保留策略执行。

这意味着迁移工作的重点从“转换旧业务数据”变为“建立干净初始化、拒绝旧数据误入、保留可追溯证据和验证切换安全”。
