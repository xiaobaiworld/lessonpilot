## 1. 目的

本文件在需求阶段来源登记基础上，进一步判断每份旧资料对 v1 设计和整版重构的实际价值。
所有 `SRC-001` 至 `SRC-082` 都必须取得最终结论，但不要求所有旧内容进入新的活跃文档。

## 2. 内容分类与最终处理

一份文件中的不同片段可以使用不同分类：

| 分类 | 含义 | 处理方式 |
| --- | --- | --- |
| 目标输入 | 与冻结需求一致，能够支持 v1 目标设计 | 提炼结论并回链来源 |
| 验证经验 | 经过测试、生产或明确技术验证的方法 | 提炼为设计约束、测试门禁或 lessons |
| 迁移证据 | 只描述当前代码、数据或用户路径 | 进入现状—目标差距和迁移设计 |
| 运行证据 | 特定版本的测试、发布、安全或故障记录 | 保留可追溯证据，不升级为目标设计 |
| 未来候选 | 已明确不进入 v1，但未来可能重开 | 移出当前指导链并保留候选入口 |
| 历史说明 | 只解释阶段背景、过程或已结束计划 | 归档，不进入当前实施指令 |
| 重复内容 | 已由其它来源完整承接且没有独有价值 | 记录替代关系后归档 |
| 已否决内容 | 与冻结需求、已接受决策或验证事实冲突 | 明确拒绝，不进入兼容或实现范围 |

最终文件动作使用以下五类：

1. **新真源完成后归档**：仍需等待对应 v1 文档承接；
2. **转入证据归档**：研究、历史计划和版本化验收仍需追溯，但不应留在活跃指导区；
3. **保留为运行证据**：当前测试、发布和生产操作仍需原位使用；
4. **更新为当前入口**：固定入口文件在权威切换后原位改写；
5. **已归档保留**：不恢复为当前指导，也不重复搬移。

### 5.3 本批次确认的可继承经验

1. 宿主页面、插件、服务端和本机存储之间必须保持显式信任边界；
2. 数据库模型、API、课程包和 Chrome 存储是不同契约，不能共用一个模糊对象；
3. UUID 身份不随名称、视频和版本变化，课程发布版本必须另有稳定身份；
4. 外部包和旧存储每次读取都要复验，失败不得破坏最近有效状态；
5. 密码、会话 token 和授权码原文使用不同生命周期，日志只记录固定摘要字段；
6. 发布应从精确提交构建，使用白名单、校验和、不可变目录、原子切换和可恢复探针；
7. 当前生产部署和数据库是迁移对象，不能因计划重写而忽略真实数据与回滚责任。

### 6.3 本批次确认的可继承经验

1. 销售说明、预置示例和真实工作台承担不同职责，不能用示例数据伪装真实产品状态；
2. 教师编辑围绕课程、课节、时间依据和节点组织，字幕先提供本机制作上下文；明确保存后是教师侧草稿/发布快照正文，不是课程包正文；
3. 预览和学生运行时必须消费同一份已发布节点语义，展示面差异不能产生第二套内容；
4. 节点创建、拖放和键盘入口应汇入同一个领域动作，保存失败保留老师的当前内容；
5. 学习窗口需要显式生命周期、单例/排队、焦点恢复、尺寸上限和宿主能力降级；
6. 跨源播放器不可读时不能伪造同步状态；技术探针必须和正式兼容承诺分开；
7. 用户可见品牌与内部兼容标识分别治理，历史名称不做破坏性机械替换；
8. 示例字幕和固定课程即使能运行，也必须通过内容权利和测试数据门禁后才能发布。
