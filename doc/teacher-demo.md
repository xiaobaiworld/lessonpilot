# 老师端 Demo 设计

版本：0.3
更新时间：2026-08-11
状态：设计已确认，等待按 D0 / D1 实现

## 0. 文档定位

本文件是老师端 Demo 的单一入口。详细功能与验收仍以 `doc/requirements.md` 的 T01–T04 为准，技术组件以 `doc/design.md` 第 3 节为准，实施顺序以 `doc/dev-plan.md` 为准。

老师端 Demo 的任务不是证明已经拥有完整 SaaS 后台，而是用最短路径证明：

> 老师能够看到一份已经改造好的互动课程，修改其中一个预置节点，并立即在真实视频中看到修改后的学生体验。

## 1. 两个连续场景

### 1.1 体验完整成品

老师安装插件后打开固定 B 站视频，直接体验平台预先制作好的完整互动课程。

这一步回答：

- 改造后的课程是什么效果；
- 视频如何暂停、练习、反馈和继续；
- 学生最终会留下什么学习结果。

### 1.2 修改并预览

老师从插件中的链接打开本地老师网站，修改预置模板中的少量关键字段，点击「保存并预览」，然后在同一个视频中看到新配置。

这一步回答：

- 这不是一次性定制动画；
- 老师可以复用模板修改自己的课程；
- 配置与学生运行时来自同一份数据。

**预览不要求重新安装插件。** 最多刷新或重新打开视频页。要求重新安装会错误地暗示每次改课都要重新发布软件。

## 2. 老师端基础网站

D0 的老师端是仓库内的静态网站，通过本地开发服务器运行。插件只保留「打开老师后台」链接，不把编辑器做成扩展页面。

网站当前没有账号、后端和远程数据库，但页面结构应能继续演进为正式老师平台。

### 2.1 首页

只提供两个主入口：

1. **体验完整成品**
2. **修改课程模板**

首页显示扩展连接状态，以及固定视频的标题、封面占位、时长和三个互动节点摘要，但不展示账号、课程目录、支付、班级或统计看板。

### 2.2 受限编辑页

固定展示一个视频和三个预置节点：

- 选择题；
- 填空题；
- 自由回答题。

老师可以修改：

- 节点启用状态；
- 触发时间；
- 题目；
- 选择题选项与正确答案；
- 填空题接受答案；
- 解释文字；
- 自由回答评价标准。

第一版题型固定，只读展示，不允许：

- 新增、删除或排序节点；
- 切换节点题型；
- 导入多个视频；
- 配置四个组件族的所有属性；
- 插入自定义 HTML、CSS 或 JavaScript。

### 2.3 页面操作

只保留四个动作：

- **恢复默认模板**
- **保存**
- **保存并预览**
- **查看最新学习报告**（D1）

存在未保存修改时，切换节点、恢复模板或离开页面必须提示。

## 3. 演示闭环

```text
老师点击「体验完整成品」
  -> 在固定视频中看到预置互动效果
  -> 从插件链接返回本地老师网站
  -> 修改一个选择题的题目或触发时间
  -> 点击「保存并预览」
  -> 网站通过受限消息桥把配置发送给扩展
  -> 扩展校验后写入 chrome.storage.local
  -> 打开固定视频并创建独立预览会话
  -> 视频按新时间暂停并显示新题目
  -> 完成作答并记录结果
  -> D1 中返回老师端查看同一会话生成的报告
```

每次「保存并预览」创建新的预览会话。预览会话与正式学生会话分开，不覆盖正式报告。

## 4. 两个交付里程碑

### 4.1 D0：可配置互动 Demo

目标是尽快证明「老师能改，学生端会变」。

包含：

- 固定视频和预置模板；
- localhost 基础老师网站；
- 网站与扩展之间的受限消息桥；
- 至少一个内容匹配的选择题或填空题；
- 可复用的暂停 → 作答 → 反馈 → 继续闭环；
- 老师修改一个预置节点；
- 本地保存；
- 保存并预览；
- 本地学习会话记录。

不包含：

- AI 自由回答反馈；
- 完整学生总结与老师报告；
- 后端、账号和网络同步；
- 账号、支付和远程后端。

D0 是内部验证和早期沟通版本，不能冒充完整销售 Demo。

### 4.2 D1：完整销售 Demo

目标是完成 `doc/requirements.md` 第 5 节的三分钟销售闭环。

在 D0 基础上增加：

- 选择题、填空题、自由回答三种节点；
- 真实 AI 自由回答反馈；
- 学生总结；
- 老师单人学习报告；
- AI 失败时的诚实降级；
- 三分钟演示脚本与人工验收。

不得使用固定模板冒充个性化 AI 反馈。

### 4.3 推广视频

D1 人工验收通过后，用真实产品录屏制作一支 60–90 秒中文推广视频。视频面向已经拥有录播课的老师，只推动「提交一节真实录播课，申请互动课程改造演示」这一项行动。

脚本、镜头清单和表述边界见 `doc/promo-video.md`。D0 可以录制内部素材，但不得把尚未实现的 AI 和报告包装成正式推广效果。

## 5. 数据与状态

### 5.1 课程配置

预置模板随插件提供。老师网站通过 `GET_LESSON` 读取当前配置，通过 `SAVE_LESSON` 请求扩展保存。扩展校验后写入 `chrome.storage.local`。学生运行时通过单一读取入口优先读取已保存配置，没有保存配置时回退到预置模板。

保存前必须校验：

- 时间属于视频时长范围；
- 启用节点按时间有序；
- 题目不为空；
- 选择题有有效选项和正确答案；
- 填空题有接受答案；
- 自由回答有评价标准。

校验失败不能覆盖上一份有效配置。

### 5.2 会话

会话至少区分：

- `student`：正式学生体验；
- `preview`：老师预览。

每次预览生成新会话编号。报告必须明确显示数据来自哪一次会话。

## 6. 网站与扩展桥接

### 6.1 消息路径

```text
localhost 老师网站
  -> window.postMessage
  -> 仅匹配老师网站的 content script
  -> chrome.runtime.sendMessage
  -> Service Worker
  -> schema 校验与 chrome.storage.local
  -> 原路返回带 requestId 的结果
```

桥接只允许五种固定操作：

- `GET_BRIDGE_STATUS`
- `GET_LESSON`
- `SAVE_LESSON`
- `RESET_LESSON`
- `OPEN_PREVIEW`

每条消息包含 `requestId` 和协议版本。不得设计通用命令执行、任意存储读写或脚本转发能力。

### 6.2 两层校验

老师网站桥接 content script：

- 只接受当前窗口发出的消息；
- 只在 `location.origin` 等于构建时配置的 `teacherWebOrigin`（包含端口）时启用；
- 只接受该精确来源的消息，不信任任意 localhost 页面；
- 只接受固定消息类型和协议版本。

Service Worker：

- 再次校验消息结构；
- 只允许固定 Demo 视频；
- 只允许封闭节点类型和字段；
- 拒绝 HTML、CSS、JavaScript 与未知字段；
- 校验失败时不覆盖上一份有效配置。

老师网站不能获得扩展 token、AI 密钥、其他课程缓存或 B 站页面数据。

### 6.3 演进边界

当前学生运行时从本地 `lessonRepository` 读取配置。产品化后把实现替换为远程仓库：

```text
local lessonRepository
  -> remote draftRepository
  -> publish validation
  -> versioned published lesson pack
  -> student cache and conditional fetch
```

页面表单和课程 schema 尽量保持不变，桥接层只服务 D0，不应扩展成自建后端协议。

## 7. 行为记录

D0 从本地记录最小事件，用于判断老师是否理解和完成核心流程：

```text
teacher_demo_opened
finished_demo_opened
teacher_editor_opened
node_edited
lesson_saved
preview_started
preview_node_triggered
preview_completed
report_opened
```

事件只记录结构化操作和结果，不记录无关页面、完整浏览历史或个人资料。当前由测试者主动导出，不建设远程统计后台。

## 8. 验收标准

### D0

- 新安装插件后，可以一键打开固定成品视频；
- 插件可以打开 localhost 老师网站，并明确显示桥接连接状态；
- 老师一分钟内找到并修改一个节点；
- 无效配置不会破坏上一份有效模板；
- 点击「保存并预览」后无需重装插件；
- 修改后的题目或时间在学生端生效；
- 预览会话不会覆盖正式学生会话；
- 整个流程不依赖远程后端和 AI。

### D1

- 三种题型全部按真实视频内容触发；
- AI 反馈引用学生实际回答和老师评价标准；
- 学生总结与老师报告来自同一会话；
- AI 失败不阻断视频，也不伪造反馈；
- 完整销售演示可以在三分钟内讲清楚；
- 合格老师愿意提供真实课程、进入试用或讨论付费。

## 9. 后续网站接口边界

正式老师网站后端至少需要以下模块，但 D0 只记录边界，不创建空接口、数据库表或模拟支付：

| 模块 | 后续职责 |
|---|---|
| `/auth` | 老师登录、租户与团队身份 |
| `/lessons` | 课程草稿、校验、预览、发布与版本 |
| `/licenses` | 学生授权码与设备解绑 |
| `/billing` | 套餐、订阅、订单、支付回调、退款与发票 |
| `/ai-credits` | 老师定向额度采购与用量 |
| `/reports` | 学生学习证据与老师报告 |

支付只发生在老师网站和后端。插件未来只读取授权状态、已发布课程包和 AI 额度结果，不处理订单、支付回调或财务数据。

## 10. 明确不做

第一阶段老师端不做：

- 带账号、数据库和远程后端的完整 SaaS 平台；
- 老师账号和团队协作；
- 多课程、多视频和批量导入；
- 任意新增、删除和排序节点；
- 自动字幕分析和自动生成课程；
- 学生名单、班级和聚合统计；
- 支付、订阅和发布审核；
- 多创作者授权管理；
- YouTube 或其他非 B 站平台支持；
- 多语言界面、课程翻译或多地区合规与支付。

YouTube 排在 D1 之后，作为第二个播放器适配器单独立项。多语言和多地区等真实海外客户出现后再设计。

这些能力是否进入产品化，应由 D1 后的老师行动和真实课程交付证据决定。
