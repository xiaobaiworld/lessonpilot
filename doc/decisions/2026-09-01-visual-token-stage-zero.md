# 阶段 0 样式门禁暂存历史裸色值

- 日期：2026-09-01
- 状态：已接受
- 范围：视觉设计系统阶段 0 的 token 生成与样式漂移门禁

## 要解决的问题

阶段 0 需要先建立 `tokens.json → tokens.css` 的生成链路和防漂移检查，但当前四端仍有一批历史页面样式直接写入色值。若在建立地基的同时一次性重做所有页面，会把阶段 1–4 的视觉收敛、插件改色和站点改版混入同一切片，难以区分行为回归与样式迁移回归。

## 已确认事实与约束

- `v1/assets/brand/knownmap-tokens.json` 是品牌颜色与几何真源。
- 视觉方案 11.1.0 要求 `tokens.css` 由 Node 标准库脚本生成，不增加依赖。
- 当前 CSS/HTML 中存在 352 个按文件和值去重后的历史裸色值；这些值来自阶段 0 开始前的页面基线。
- 阶段 1–4 已明确负责 Web 样式收敛、教师端页面、插件统一和销售站点接入。

## 考虑过的方案

1. **立即全量迁移**：当前阶段清除所有裸色值。优点是门禁立即最严格；成本是扩大阶段 0 范围，并同时改变四端现有视觉，回归难以归因。
2. **暂不建立门禁**：等页面迁移完成后再检查。成本最低，但无法阻止阶段 0 之后继续引入新的漂移。
3. **历史基线 + 新值阻断**：登记阶段 0 前已存在的文件和值，新增裸色值失败；后续收敛阶段逐步删除基线。保留了新代码的约束，也保持阶段边界清晰。

## 决定

采用方案 3。`tools/style-check.mjs` 扫描 `v1/web`、`v1/site` 和 `v1/extension` 的 CSS/HTML；`tokens.css` 是唯一允许直接定义新色值的文件。历史值暂存在 `tools/style-check-baseline.json`，任何不在基线中的新裸色值立即使 `check:style` 失败。阶段 1–4 删除对应遗留样式后，基线必须收敛为空，最终门禁恢复为除 `tokens.css` 外零裸色值。

## 仍待验证与重开条件

- 阶段 1 开始前需要重新确认基线是否仍完整，避免页面文件新增后被误登记。
- 阶段 1–4 每完成一个端，删除该端对应基线并执行截图/构建回归。
- 如果新增 token 在真实页面中出现对比度不足，必须回到 `tools/build-tokens.mjs` 和设计文档重新校准。

## 影响

- 新增 `tools/build-tokens.mjs`、`v1/web/shared/src/styles/tokens.css`、`tools/style-check.mjs` 和阶段 0 基线测试。
- Web、站点、插件建立共享 token 的消费入口；本切片不改变现有页面的语义、路由、保存流程或资源交付方式。
- 视觉方案 11.1.0 的阶段 0 通过“新增值阻断、历史值可见”的门禁执行；阶段 1–4 负责历史值清零。
