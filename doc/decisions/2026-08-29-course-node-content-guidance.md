# D-V1-025：互动节点优先采用课程化编辑引导，不新增内容字段

- 日期：2026-08-29
- 状态：已接受；实现与人工验收完成，后端既有格式基线另行处理
- 决策编号：`D-V1-025`
- 关联设计：[`课程互动节点课程化编辑引导设计`](../../docs/superpowers/specs/2026-08-29-course-node-content-guidance-design.md)

## 1. 背景

教师端已有重点提示、选择题、填空题和问答题四种互动节点，并使用统一的节点编辑弹窗。现有字段已经足以保存课程内容，但字段名称和组织方式偏向实现细节：例如“页面正文”“解析”“参考答案”。这会让老师难以快速判断当前字段的教学目的，也容易把节点配置成“功能参数”而不是课程内容。

## 2. 决策

第一阶段采用方案 A：保留现有 `title`、`content`、`interactionData` 和 `presentationHints` 数据结构，只改造教师端的课程化编辑引导：

1. 继续使用统一的节点类型、触发时间、左侧编辑、右侧预览和底部保存结构。
2. 按四种节点分别提供课程任务标题、字段名称、完整占位示例和简短填写提示。
3. 重点提示使用现有 `RichPageDocument` 的标题、列表和引用表达层次，不新增独立“提醒”字段。
4. 选择题明确展示“题目主干 → 手工填写选项 → 标记正确答案 → 学生作答后的解释”。
5. 填空题明确展示题干、标准答案/可接受说法和提交后的解释。
6. 问答题明确区分问题和学生提交后的参考反馈，并保留“不自动判分”的边界。
7. 更新新建节点默认标题和本地错误提示，使其贴近学生学习体验和课程设计语言。
8. 不新增接口、不修改课程包 schema、不改变学生端作答、判分、完成和播放行为。

## 3. 方案比较

### 方案 A：课程化编辑引导（当前选择）

- 收益：改动集中在教师端，能立即验证老师是否更容易填写；不引入契约和迁移成本；可随时继续迭代文案和布局。
- 成本：重点提示的不同内容层次仍保存在同一份富文本中，暂时不能独立查询或程序化消费。
- 风险：如果提示语不足以指导真实课程制作，后续仍需要结构化字段设计。
- 可逆性：高；主要影响编辑文案和默认值，公共数据结构保持不变。

### 方案 B：新增独立结构化字段

- 收益：重点主题、提醒、题干和反馈等内容可以单独保存、查询和程序化排版。
- 成本：需要同步修改前后端 schema、草稿校验、课程包、插件运行时、迁移和跨层测试。
- 风险：在尚未验证老师真实需求前扩大公共契约，增加字段兼容和内容重复的风险。
- 可逆性：低；一旦发布新字段，需要长期维护兼容和迁移边界。

选择方案 A 的原因是当前问题已经可以通过教师端表达和引导改善，现有数据结构也能承载确认的课程内容；只有出现独立查询、独立渲染或真实反馈不足等重开条件时，才重新评估方案 B。

## 4. 影响

- 需求：增强教师快速理解和正确填写节点的可验收标准，不改变四种节点的产品范围。
- 设计：教师弹窗的区块标题、字段文案、占位示例、错误提示和学生端预览标签需要同步。
- 数据：`title`、`content`、`interactionData` 和 `presentationHints` 的结构不变。
- 测试：增加教师端课程化文案和默认值验证，并继续执行现有学生端行为和契约回归。
- 文档：设计说明和当前文档索引需要登记本决策；实现验证通过后再写入变更记录。

## 5. 重开条件

出现以下任一事实时，可以重新讨论方案 B：

- 老师需要独立查询、排序或复用重点主题/提醒；
- 学生端需要按内容区块应用不同程序行为；
- 课程包或其它客户端需要独立消费这些区块；
- 真实试用仍证明方案 A 无法让老师正确完成节点配置。
