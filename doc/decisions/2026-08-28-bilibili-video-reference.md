# D-V1-021：课程绑定使用 B 站视频与分 P 的精确引用

- 日期：2026-08-28
- 状态：已接受；进入实现
- 决策编号：`D-V1-021`
- 关联设计：[`B 站课程视频引用与分 P 精确匹配设计`](../../docs/superpowers/specs/2026-08-28-bilibili-video-reference-design.md)

## 1. 背景

当前教师、课程包和插件只保存 BVID。B 站一个 BVID 可以包含多个分 P，当前运行时又只从 pathname 读取 BVID，因此绑定第 4 P 的课程会错误地在第 1 P 或同视频其它分 P 上出现。查询参数中的 `vd_source` 是来源追踪信息，不是课程身份。

## 2. 决策

课程视频引用统一为 `platform + video_id + page + cid?`：

- `video_id` 必须是合法 BVID；
- `page` 为从 1 开始的分 P，缺省 URL 规范化为 `1`；
- `cid` 可选，已知时作为比 `page` 更强的精确身份；
- `vd_source`、`spm_id_from`、`from_spmid` 和其它追踪参数不进入业务对象，不参与匹配。

匹配必须精确：BVID 不同不匹配；双方都有 CID 时按 CID；一方有 CID、一方没有时不匹配；双方没有 CID 时按 `page`。不同分 P 不得共享课程 UI。

## 3. 兼容与范围

旧课程数据迁移为 `page = 1`、`cid = null`。第一阶段只接受直接 B 站视频页中的 BVID；AV、短链、番剧、合集和直播链接没有经过解析时拒绝保存或保持插件静默，不做猜测。

manifest 的宽匹配只负责让内容脚本有机会检查当前页面，不能作为 UI 显示条件。内容脚本必须在没有精确候选时不挂载或立即清理陪伴 UI；SPA 切换也必须执行同样的精确检查。

## 4. 后续防漏检门槛

涉及外部 URL 的新字段时，必须同时提交参数分类表、共享规范化值对象、跨层契约测试和真实页面正反例矩阵。只测试 BVID 或只测试模块内部函数，不得作为完成证据。
