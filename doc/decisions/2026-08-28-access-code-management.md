# D-V1-020：授权码记录与教师侧管理状态

- 日期：2026-09-03
- 状态：已接受并验证；授权码管理功能已部署到生产环境
- 决策编号：`D-V1-020`
- 关联决策：[`D-V1-019`](2026-08-27-course-access-latest-release.md)、[`D-V1-015`](2026-08-27-access-code-browser-identity-limit.md)

## 1. 要解决的问题

当前授权码页面主要承担单课程、快速生成和终止授权，无法表达批量交付、接收人记录、临时冻结和批量管理。教师需要能够管理“给了谁”、当前是否继续使用，以及停止使用后如何保留历史。

## 2. 已确认事实

1. 一条授权码可以包含多门当前教师自己的已发布课程授权项；从单门课程进入时，该课程作为默认范围。
2. 教师需要设置批量生成数量，当前范围为 1–100。
3. 接收人不是学生账号或浏览器用户名，而是教师自己维护的信息；可以为空，生成后可以补记或修改。
4. “冻结”与“作废”语义不同：冻结可恢复，作废不可恢复。
5. 教师界面中的“删除”不能执行物理删除；数据库保留授权码、授权项、接收人、领取关系和审计记录。
6. 授权码原文仍属于秘密。数据库保存安全摘要和生成意图，不保存可直接读取的授权码明文。
7. 当前实现使用默认生成方式；后续希望支持规则模板，例如课程名称、序列号和随机片段的组合。生成方式本身不是业务身份，唯一性和可验证性才是业务不变量。

## 3. 决策

### 3.1 管理入口

沿用现有教师工作台的课程卡片和 `AccessCodesPage`，不新增全局授权中心。创建、列表、详情和批量管理集中在该页面。

创建区通过“添加授权课程”添加其它已发布课程；生成后的列表记录提供“复制”和“授权码 + 指南”两个并列的轻量描边按钮。后者只复制已有记录整理出的学生转发文案，不生成新授权码。

### 3.2 状态

`AccessCode.status` 使用三种手工管理状态：

- `active`：有效；
- `frozen`：冻结，可恢复为有效；
- `terminated`：作废，永久停止未来在线资格，不可恢复。

领取窗口和授权项现实有效时间是独立的派生状态，不把时间到期混写成教师手工作废。已安装课程不因任一状态失效被远程删除。

### 3.3 接收人记录

在授权码记录上保存可为空的教师侧接收人和备注字段。该信息只返回给拥有该授权码的教师，不进入学生兑换响应、课程包、本机标识或学生账号。

### 3.4 批量状态操作

列表提供复选框、全选和批量冻结/恢复/作废。批量动作使用一个带幂等键的服务端事务；目标归属、状态适用性或任一写入失败时整体拒绝，不由前端循环单条请求替代。

### 3.5 生成规则边界

本轮只保留默认生成，并冻结以下不变量：

1. 授权码满足最小长度和输入校验规则；
2. 授权码标准化后全局唯一；
3. 数据库可安全验证，不保存明文；
4. 生成候选失败或冲突时不产生半条授权记录。

后续自定义生成规则另立设计。规则可改变码的外观和构成，但不能改变以上不变量。

## 4. 方案取舍

### 采用：管理页内创建栏 + 列表详情 + 原子批量状态操作

- 收益：复用现有入口和课程上下文；单个生成、批量生成和后续管理在同一处完成；教师能同时看到码和分发记录。
- 成本：页面状态比当前单按钮生成复杂；需要新增状态端点、审计记录和迁移。
- 风险：如果未来授权码数量显著增长，前端本地筛选和无分页列表需要升级。
- 可逆性：可以在不改变授权数据模型的情况下后续增加分页或独立总览。

### 未采用：全局授权中心

放弃原因：当前产品只有教师单一工作空间和课程卡片入口；提前建立全局中心会增加导航和权限投影，但不增加本轮必要能力。

### 未采用：前端循环调用单条状态接口

放弃原因：批量操作可能部分成功，无法满足状态和审计的一致性；服务端已有明确事务边界，应提供批量业务动作。

### 未采用：直接删除授权码

放弃原因：会丢失教师分发记录、领取事实和审计关联，也无法解释学生已经安装的课程；与在线资格和本机内容分离原则冲突。

## 5. 假设与未知项

1. 初期授权码数量规模适合教师端一次加载并在浏览器侧筛选；达到分页阈值时需要重新设计查询契约。
2. 当前课程列表接口可以提供教师自己的课程摘要；服务端仍必须重新校验已发布状态和工作空间归属。
3. 当前审计表可以承载授权码状态变更摘要；如果已有审计应用服务不足，则增加服务层而不改变表归属。
4. 自定义生成规则的字符集、模板语法、序列号并发分配和冲突重试策略尚未决定。

## 6. 影响

- 设计：同步 v1 03–08 号设计中的授权码页面、数据模型、数据流、接口、安全和交互。
- 代码：扩展教师 Web 授权页、API 类型/调用、授权应用服务、路由、数据库迁移和测试。
- 数据：保留现有授权与领取记录；新增教师侧接收人字段；状态变更只更新状态并追加审计。
- 学生端：不改兑换和更新请求；冻结/作废由现有资格计算阻止未来在线动作。
- 文档：需求、设计、实现、测试和生产发布记录已同步；后续分页、服务端筛选和权限查询优化仍放在下一阶段。

## 7. 重新讨论条件

出现以下情况时重新审核：

- 产品要求恢复已作废授权码；
- 授权码数量需要分页、导出或全工作空间聚合；
- 需要给学生发送通知或建立学生身份；
- 需要允许已领取授权修改范围/时间；
- 需要实现课程版本级授权、升级关系或自定义生成规则。
