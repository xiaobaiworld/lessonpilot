# D-V1-019：当前阶段授权码按课程绑定并自动解析最新可交付版本

- 日期：2026-08-27
- 状态：已接受；替代 `D-V1-018` 中当前阶段的版本级授权码口径
- 决策编号：`D-V1-019`
- 关联决策：[`D-V1-018`](2026-08-27-course-version-and-access-code-management.md)

## 1. 决策背景

为先复用当前已经通过测试的后端授权链路，本阶段不立即引入“授权码绑定 `release_id`”和独立课程版本授权模型。
前一次决策中关于版本级授权码、版本操作和独立课程身份的内容保留为后续演进方向；当前授权采用现有 `course_id` 模型。

## 2. 当前有效规则

1. 教师生成授权码时，授权项绑定一个 `course_id`，不要求教师选择 `release_id`。
2. 学生兑换授权码或检查更新时，服务端按该 `course_id` 自动解析当前最新的可交付发布版本。
3. 同一课程后续成功发布新版本后，仍有效的课程级授权可以取得该课程最新可交付版本；当前不把这称为跨独立课程升级。
4. 课程包和现有 `courseId`/`releaseId` 字段继续保留，`releaseId` 表示本次实际返回的最新可交付快照。
5. 授权码原文只在创建成功结果中显示一次、范围校验、领取数量限制、终止和有效期规则均不变。

## 3. 本阶段明确不做

以下能力继续后置，不因本决定提前实现：

- 每个独立课程版本单独生成版本级授权码；
- “修改本版本”和“增加版本”的正式版本操作；
- 把每个发布版本作为独立课程身份展示和管理；
- 课程族、跨独立课程升级关系及本机学习状态迁移；
- 旧授权码在独立课程之间的兼容判定。

## 4. 端点与前后端边界

当前授权直接复用：

- `POST /api/v1/teacher/access-codes`：请求仍以 `course_id` 为授权根对象；
- `POST /api/v1/student/redemptions`：兑换后按课程获取最新可交付发布版本；
- `POST /api/v1/student/course-updates`：按课程检查并返回更新后的最新可交付发布版本。

前端只负责选择课程、提交授权参数和展示服务端返回的版本摘要；“最新版本”的判定、课程归属、授权范围、权限、幂等和事务由后端负责。
前端不得自行比较时间、拼接课程包或决定授权是否覆盖新版本。

## 5. 后续重开条件

当需要独立版本授权、版本操作、课程族升级、跨独立课程更新或版本级授权审计时，重新评审本决定，并先冻结新的数据模型、
OpenAPI、兼容规则和迁移方案，再替换当前 `course_id -> latest deliverable release` 逻辑。
