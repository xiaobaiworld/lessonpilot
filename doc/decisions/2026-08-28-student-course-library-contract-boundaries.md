# D-V1-022：学生课程库升级契约边界与存储版本策略

- 日期：2026-08-28
- 状态：已接受
- 决策编号：D-V1-022

## 背景

学生课程库、课程升级和资源交付设计进入实现前审核。审核发现课程包字幕边界与
`D-V1-014` 冲突，新增 HTTP 端点尚未登记到 06 号接口清单，存储根增加可选字段的
兼容策略也没有明确写入版本清单。

## 决策

1. 字幕原文继续止步于教师侧 `ScriptDraft` 和 `ReleaseLessonSnapshot`，不进入
   `CoursePackage` 或学生插件本机存储。课程包 Schema 保持 v3.1.0；本轮不修改课程包
   的字幕字段。
2. 学生课程升级使用独立的 `check` 与 `apply` 两阶段接口；现有
   `POST /api/v1/student/course-updates` 保留为兼容路径，明确它不是轻量检查接口。
   四个新端点必须先登记在 `doc/design/v1/06-interface-contracts.md` 第 4.5 节。
3. 扩展存储根保持主版本 2，不隔离或删除现有 v1 存储。新增设置和升级队列字段属于
   向后兼容的可选扩展，契约版本升为 2.1.0；读取器接受受支持的 2.x 根版本并为缺失
   字段补默认值，未知主版本和无法解释的结构仍隔离。`versions.json`、TypeScript
   版本定义、Schema、读取器和契约测试必须同步。
4. 插件消息和 HTTP API 的新增能力按同一兼容规则升为 2.1.0；不把新增端点误写成
   课程包版本变化。
5. 本轮不新增需求编号。实现和验收沿用已有 `FR-LIB-*`、`FR-LEARN-013`、
   `DATA-LOCAL-*`、`INT-PACKAGE-*`、`INT-EXT-*`、`INT-BILI-*`、`SEC-TRUST-003`
   和 `DEV-STRUCT-002`，并在追踪矩阵中补齐设计、实现和测试证据。

## 影响

- 课程包资源清单仍只描述资源元数据；学生资源二进制通过独立的授权资源接口取得。
- 存储升级不会因为新增可选设置或队列字段而让现有课程库整根失效。
- 新增端点、契约版本和追踪矩阵成为 Task 1、Task 4、Task 5A–5D 的前置交付物，
  不能推迟到最后一次全量检查才补。

## 依据

- `D-V1-014` 明确字幕不进入课程包或插件。
- `ARCH-DEC-02` 和 `doc/dev-rules.md` 第 4、7、8 节要求契约清单、版本、消费端和
  验证同步。
- 现有 `extension-storage.schema.json` 使用 `additionalProperties: false`，但根字段
  可选扩展不会破坏缺失字段的旧数据；真正需要拒绝的是未知主版本和无法验证的结构。
