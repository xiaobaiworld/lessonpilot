# 教师端首屏性能优化决策

- 日期：2026-08-27
- 状态：已验证
- 决策范围：`/teacher/` 默认登录入口及其静态资源传输

## 要解决的问题

默认教师登录页结构很小，但冷加载时长明显过长。目标是让未登录教师先看到可用的登录表单，减少不必要的首包传输，并让带 hash 的静态资源可压缩、可长期缓存；不改变认证协议、Cookie 安全属性和教师业务流程。

## 已确认事实

1. 线上 `/teacher` 会先 301 到 `/teacher/`。
2. 线上最新发布 `20260826T060559Z-64a98aeea3fd` 的教师 JS 为 402041 字节，响应没有 `Content-Encoding`；CSS 为 109302 字节，也未压缩。
3. 线上浏览器冷加载时 JS 传输约 11–17 秒，`/api/v1/teacher/auth/me` 在 JS 执行后才发起，响应约 0.22–0.24 秒。
4. 当前工作树已移除 Quill；本机构建教师 JS 为约 203 KB，gzip 后约 65 KB。
5. `TeacherApp` 在 `me()` 完成前返回 `null`，所以浏览器会显示空白页面。
6. `App.tsx` 顶层静态导入课程列表、课程详情和课节编辑页，登录入口会加载受保护编辑器代码。

## 决定

1. 保留会话恢复请求，但未确认会话时立即渲染登录页；认证成功后再切换到工作台。
2. 将已登录后的课程列表、课程详情和课节编辑页改为动态导入，登录首包不再包含编辑器代码。
3. Nginx 对 JS、CSS、JSON 等文本资源启用 gzip，并为 `/teacher/assets/` 设置一年 `immutable` 缓存；HTML 保持可重新验证。
4. 将 Nginx 443 监听升级为 HTTP/2，并将 `/teacher` 规范化到 `/teacher/`，减少额外重定向。
5. 通过现有 `tools/release.sh` 发布完整 Git commit；不在服务器上手工构建或修改发布目录中的静态文件。

## 未采用方案

- 不先优化 `/me` 的 SQL：当前接口只做会话解析和一次查询，实测耗时远小于静态 JS 下载。
- 不把登录页改成另一个独立站点：会增加认证、发布和视觉真源的重复维护。
- 不在本轮拆分所有 CSS：启用压缩后 CSS 体积已较小，优先级低于 JS 首包和空白等待。

## 验收与重开条件

- 冷加载能在资源加载期间显示登录表单，不再出现空白 `#root`。
- 线上 JS/CSS 响应带 `Content-Encoding: gzip`，哈希资源带 `Cache-Control: public, max-age=31536000, immutable`。
- `/teacher` 最多保留一次规范化重定向，`/teacher/` 返回 200。
- 未登录 `/api/v1/teacher/auth/me` 仍返回 401；登录、会话恢复和退出行为不变。
- 若真实用户网络仍主要耗时在 TLS/跨境链路，下一轮再评估 CDN/边缘节点；若首包仍超过目标，再继续拆分首屏 CSS。
