# D-V1-015：授权码按本地浏览器标识限制使用数量

- 日期：2026-08-27
- 状态：已接受；代码实现待开发
- 决策编号：`D-V1-015`
- 替代关系：补充 `FR-GRANT-*` 与 `DATA-DELIVERY-*` 的领取数量规则；不引入硬件识别、Native Messaging 或学生账户。

## 1. 要解决的问题

当前授权码可以建立多条 `Redemption`，但没有明确限制一个授权码能够被多少个不同的学生使用。需要限制滥用，
同时不能因为浏览器升级、更换扩展版本或同一浏览器重复安装/打开而误增使用数量。

## 2. 已确认事实

1. 当前 v1 已有随机生成并保存在插件本机的 `LocalIdentity`；服务端通过 `Redemption` 记录授权码与本机标识的关系。
2. 当前 v1 不建立学生账号，也不提供跨设备账户恢复。
3. 标准浏览器扩展无法可靠取得跨浏览器、跨重装的硬件唯一标识；硬件识别不纳入本次范围。

## 3. 决策

1. 当前使用 `LocalIdentity` 作为授权码使用者标识。它代表一个浏览器安装实例，不代表物理硬件，也不作为学生身份。
2. 同一个授权码和同一个 `LocalIdentity` 只计一个使用者。重复兑换、重新下载和更新不增加数量。
3. 一个授权码默认最多登记 20 个不同的 `LocalIdentity`。第 21 个新的标识请求时，服务端拒绝并且不创建新的
   `Redemption`，不返回课程包。
4. 超限响应使用稳定错误码，并提示“此授权码已被过多用户使用，请回到原浏览器，或联系教师重新申请授权码”。
   原浏览器仍保留原 `LocalIdentity` 时，继续使用该标识不占用新名额。
5. 数量判断、登记和课程包返回必须在同一个可控事务中完成，防止并发请求突破上限。
6. 学生账户、Google 登录和跨设备下载作为后续独立决策；未来账户模式不直接复用当前匿名浏览器标识规则。

## 4. 未采用的方案

- 硬件/CPU/主板指纹：不稳定、不可由标准扩展可靠取得，并且带来额外隐私和兼容成本。
- Native Messaging 本机辅助程序：可以提供系统级密钥，但会增加安装、发布和多平台维护成本，当前阶段不引入。
- 当前阶段直接接入学生账户：会同时改变身份、认证、跨设备、数据保留和恢复边界，超出本次授权数量限制。

## 5. 影响范围

- 需求：新增授权码的不同本机标识数量限制、超限失败和幂等规则。
- 设计：`AccessCode` 增加设备/浏览器使用上限语义；`Redemption` 继续作为授权码与本机标识的登记事实。
- 接口：新增稳定的授权码使用数量超限错误。
- 测试：覆盖 20 个不同标识成功、第 21 个拒绝、同标识重复成功、并发边界和拒绝时不返回课程包。
- 代码：本决策只记录设计，尚未实现。

## 6. 重新讨论条件

出现以下情况时重新评估：匿名标识可被大量清除或伪造并导致限制失效；正常用户频繁更换浏览器造成名额误伤；
或产品正式需要跨设备恢复和学生账户登录。
