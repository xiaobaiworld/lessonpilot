## 1. 这份文档解决什么

学生插件 ZIP 只装运行时框架。课程正文、配图、短音频等大资源在兑换后下载到**这台 Chrome 的插件源**上，不打进每次更新的 ZIP。

学生会在两处看到同一份本机文件：

1. **插件自己的页面**（工具栏弹窗，以后也可以是独立索引页）：浏览已下载内容、确认装好了什么。
2. **B 站视频上的中间学习窗**：到点弹出的题目/提示里，直接显示这些文件。视频仍是 B 站的；图和音频是本机的。

当前代码把课程 JSON 和学习状态全部写入 `chrome.storage.local` 的单一根 `knownmapV1`。默认配额 10MB。继续把二进制塞进这份 JSON 会很快撑满，也不该用 base64。本文件给出拆分方案。

## 2. 已锁定方向

| 项 | 决定 |
| --- | --- |
| 插件 ZIP | 只含框架：manifest、后台、弹窗、B 站适配、很小的内置资源（图标、小人）。课程专用文件不进 ZIP。 |
| 课程 JSON / 进度 | 继续 `chrome.storage.local['knownmapV1']`。节点只引用 `assetId`，不内嵌文件。 |
| 二进制文件 | IndexedDB，`assetId` 当钥匙，值是 `Blob`。 |
| 读写边界 | 只有 background 碰网络和本机库。popup 与 content script 只 `sendMessage`。 |
| 两个入口 | 弹窗和学习窗共用一份库，不拷成两份。 |
| Cache API / OPFS | v1 资源方案不采用。理由见第 5 节。 |
| B 站播放视频 | 不下载、不托管、不重新分发；`videoRef` 只作为播放宿主和时间触发来源。 |
| 互动节点视频 | 作为课程内容资源，按 `assetId` 管理；源文件由服务端保存，学生端后续经后台下载并放入 IndexedDB。 |

旧设计已写过同一方向（课程身份与 `assetId` 分离），当时范围明确不做图片/音频、不申请大容量权限。现在重开的是**资源落地**，不是推翻课程身份模型。

## 3. 10MB 到底限制什么

**10MB 是 `chrome.storage.local` 的默认配额，不是插件 ZIP 能装多少文件。**

Chrome 文档：`storage.local` 上限 10,485,760 字节（Chrome 113 及更早为 5MB）。声明 `"unlimitedStorage"` 后这条硬顶取消。`QUOTA_BYTES` 按 JSON 序列化后的键+值计算。

| 放哪里 | 有没有 10MB 硬顶 | 适合放什么 |
| --- | --- | --- |
| 插件 ZIP / 解压目录 | 没有。学生下载体积才是约束 | 运行时代码、很小的随插件版本走的资源 |
| `chrome.storage.local` | **有，默认 10MB** | 课程结构、授权来源缓存、学习状态 |
| IndexedDB / Cache / OPFS | 按源配额，通常远大于 10MB | 互动节点的图片、音频、视频本体 |

本项目按 [D-V1-004](decisions/2026-08-21-v1-plugin-distribution.md) 用固定 ZIP 手动安装，不走 Chrome Web Store。商店侧旧日的 10MB 上传限制已经过时（现行包上限为 2GB），与本机课程资源无关。

课程包 Schema 允许最多 500 课节、正文最长 4000 字。纯文本也有可能顶满 `chrome.storage.local`。资源开发时把「JSON 索引」和「文件本体」分开，不要把容量问题拖到配额报错才拆。

## 4. 插件是瘦框架

```text
插件 ZIP（随 D-V1-004 手动替换）
  ├─ 运行时：background / popup / content / host/bilibili
  ├─ 内置：图标、小人、必要时一份很小的示例课 JSON
  └─ 不含：老师课里的图、音频、附件

兑换 / 下载按钮
  → knownmap.com（host_permissions 已有）
  → JSON 索引 → chrome.storage.local
  → 文件本体 → IndexedDB
```

课程更新走「再兑/在线更新课程包」，不走「换插件 ZIP」。插件更新只升级框架。两件事绑死会导致改一张配图也要学生手动刷新扩展。

内置资源（`chrome.runtime.getURL`）只给真正随运行时版本走的东西。老师课的 `assetId` 一律兑换后下载。

## 5. 三套本机库怎么选

三者都在 **插件源** `chrome-extension://<id>` 上，后台、弹窗、独立扩展页共用。卸载插件会清掉。用户清浏览记录一般清不掉扩展存储。磁盘紧张时 Chrome 仍可能回收；正式课资源应在落地时申请 `unlimitedStorage`，避免被挤掉。

注入 B 站的 content script **不在这个源上**。它用的是 `bilibili.com` 的 IndexedDB/Cache/OPFS。在学习窗里直接 `indexedDB.open(...)` 会打开空库，看起来像「下载成功但点开没有」。见第 8 节。

| | IndexedDB（采用） | Cache API（不用） | OPFS（不用） |
| --- | --- | --- | --- |
| 像什么 | 本机数据库，一条记录一个文件 | 按 URL 记住某次 HTTP 响应 | 浏览器里的私有文件夹 |
| 适合 | `assetId → Blob` + 校验元数据 | 「这个公开 URL 离线再取一遍」 | 超大文件、按目录导出 |
| MV3 后台 | 能用 | 能用 | 能用，大文件写入更别扭 |
| 和课程模型 | 正好对上 `assetId` | 资源按授权包下发，不是公开 URL 缓存 | v1 没有文件夹/导出目录需求 |

Cache 适合拦截 `fetch(url)` 做离线镜像。KnownMap 是授权包 + `assetId`，用 Cache 会把身份做成 URL，反而别扭。

OPFS 适合以后「整课导出成目录」或本地超大文件。KnownMap 不托管第三方 B 站播放视频；互动节点视频属于课程资源，若单文件大到消息传递吃力时再重开第 13 节。

IndexedDB 直接存 `Blob`，不要 base64（大约胀 33%，还占 JSON 配额）。

## 6. 一份库、两个入口

学生看到的是两块界面，不是两份文件。

**入口 A：插件自己的页面**

点浏览器右上角 KnownMap 图标弹出的课程列表（`v1/extension/popup/`）。以后若做完整索引页，仍是 `chrome-extension://...`，和仓库同一源，但按现有规矩仍经 background 读，popup 自己不碰存储。

**入口 B：盖在 B 站上的学习窗**

`bilibili.com/video/BVxxxx` 上，到点弹出的中间互动窗（`LearningWindow`，Shadow DOM）。户口在 B 站页面里，进不了插件仓库，必须让后台代取再递过来。

同一张电路图：目录里能预览，上课窗里题目旁边也能显示。`assetId` 相同。

B 站播放视频本身不进本机库；节点内的图片、音频和视频按 `assetId` 进入资源缓存流程。

## 7. 下载、安装与点开

所有步骤走后台。与当前兑换顺序一致：取回 → 全部复验 → 再提交；失败保留上一份有效数据。

```text
学生点「兑换 / 下载」
  → 后台向 apiOrigin 拉课程包 JSON（继续很小）
  → Schema、摘要、禁止字段复验
  → 按资源清单逐个 fetch（仅 host_permissions 内的源）
  → 校验 Content-Type、大小上限、checksum
  → JSON 索引写入 chrome.storage.local（原子替换该课）
  → Blob 写入 IndexedDB（key = assetId）
  → 索引页：有清单且有文件才显示「可学」
```

点开某一项：

1. 调用方带 `assetId` 问后台；
2. 后台读 IndexedDB，核对 checksum / MIME；
3. 返回 `ArrayBuffer` + MIME（不要 data URL）；
4. 调用方在**自己的世界**里做成 `blob:` 地址，赋给 `<img>` / `<audio>`；
5. 窗口关掉后 `URL.revokeObjectURL`。文件仍在 IndexedDB。

弱网/离线：已下完的能用；缺文件就明确说缺，不假装整课可离线。这与 [05 第 6.2 节](design/v1/05-data-flow-lifecycle.md)「已安装课程可离线学习、不声称已是最新版」一致。

安装前应能估算本机增量（`getBytesInUse()` + 资源清单），给学生看「本机存储影响」再确认。写失败不留下半安装。

## 8. 学习窗如何拿到文件

现有消息方向已经是：popup / content → background → 存储或网络。资源读取只是多一种请求类型，不新开通道。

```text
学习窗：后台，把 assetId=电路图 给我
后台：打开 IndexedDB，取出 Blob，按结构化克隆递回 ArrayBuffer
学习窗：在 Shadow DOM 里用 <img> / <audio> 显示
B 站页面 JS：进不了 Shadow DOM，也拿不到插件仓库
```

v1 不在 B 站页里嵌 `chrome-extension://` iframe 来读库。那样也能工作，但必须把页面列入 `web_accessible_resources`，B 站页可以自己 iframe 它。题目里的示意图和短音频，走现有 `sendMessage` 足够。单文件大到消息传递成为瓶颈时，再评估 iframe 或 OPFS，见第 13 节。

`blob:` 必须在学习窗所在的隔离世界创建。后台创建的 blob URL 学习窗用不了。

建议消息形状（实施时写入插件消息 Schema，未列出的 type 必须拒绝）：

```text
请求  { type: "asset", assetId }
成功  { ok: true, data: { mimeType, bytes } }   // bytes 为 ArrayBuffer
失败  { ok: false, code: ASSET_MISSING | ASSET_CORRUPT | STORAGE, message }
```

不要把下载来的 HTML/SVG 当脚本插入 DOM。图用 `<img>`，音频用 `<audio>`。未知 MIME 拒绝显示。

## 9. 安全、权限与失败

- 下载源只允许已声明的 `host_permissions`（当前生产为 `https://knownmap.com/*`，本机目标另有 `127.0.0.1`）。禁止学生或课程包指定任意 URL。
- 落盘前校验大小、MIME 白名单、checksum；与课程包 `packageDigest` 一样，写进去之后运行时才相信。
- 课程包、资源字节、页面消息都是不可信输入。后台不因「是自己的 content script 要的」而跳过校验。
- 资源不是秘密：插件是明文，本机库在 DevTools 里可读。不要把授权码原文、会话 Cookie 放进 IndexedDB 或课程 JSON。
- 申请 `unlimitedStorage` 会在安装/更新时多一条权限说明。在第一次落地二进制资源时加上，不要等配额报错。
- 空间不足、校验失败、中途断网：保留旧课与旧资源，错误用稳定 `code` + 给学生看的一句话。不出现「显示成功但文件不在」。
- 学生删除本机课程时，同时删该课的 JSON、学习状态和 IndexedDB 中对应 `assetId`。不远程删除。

## 10. 和现有代码怎么接

| 现有位置 | 现在做什么 | 资源落地时改什么 |
| --- | --- | --- |
| `v1/extension/manifest/targets.ts` | `permissions: ['storage', 'downloads']` | 增加 `unlimitedStorage` |
| `v1/extension/storage/` | 单一根 `knownmapV1` | JSON 继续在这里；增加 `assetId` 引用，不存 Blob |
| `v1/extension/background/redeem.ts` | 拉课程包 JSON，复验后写入课程库 | 复验通过后再拉资源清单，写入 IndexedDB |
| `v1/extension/background/service-worker.ts` | 消息入口 | 增加 `asset`（名称以 Schema 为准） |
| `v1/contracts` 课程包 Schema | 节点结构化 `content` | 节点可引用 `assetId`；包内带资源清单（id / mime / size / checksum） |
| 插件消息 Schema | `library` `redeem` `lesson` … | 增加取资源请求；未列出的 type 仍拒绝 |
| `v1/extension/popup/` | 课程目录，打开 B 站链接 | 目录可预览已下载资源；仍经 background |
| `v1/extension/content/window.ts` | 四类节点的学习窗 | 题目里按 `assetId` 向后台要文件，Shadow DOM 内显示 |
| `host_permissions` | B 站 + API origin | 资源 URL 必须落在同一 API origin 或明确增加的静态资源 origin |

课程核心与大资源分离的逻辑形状（实施时以 Schema 为准）：

```text
课程 JSON（chrome.storage.local）
  courseId / releaseId / lessons[] / nodes[]
  node.content 只引用 assetId

资源记录（IndexedDB）
  assetId
  mimeType
  size
  checksum
  blob
```

## 11. 明确不做

- 不把课程资源打进插件 ZIP，不靠换插件来更新一张图。
- 不把二进制 base64 进 `knownmapV1`。
- 不在 content script 里直接开 IndexedDB/Cache/OPFS。
- 不下载、不代理、不重新分发 B 站视频文件。
- 不把下载来的 HTML 当代码执行；不做通用「本机浏览器随便打开任意文件类型」。
- v1 第一批不把 PDF / 大附件嵌进学习窗。若以后要，用「点一下交给浏览器打开」，不塞进题目卡片。
- 不为此新建 Chrome Web Store、自动升级或跨设备同步。
- 本文件升格为正式 `D-V1-*` 或改冻结设计 01–09 之前，不把这里的字段名当成已发布契约。

文件类型默认假设（未另开产品决定前）：

- 学习窗第一批：**图片**、**短音频**。
- PDF / 较长附件：不嵌进题目窗。
- 视频文件：永不进本机库。

## 13. 重开条件

出现以下任一情况时，回到第 5、8 节重选存储或传递方式，不要在实现里偷偷改：

1. 单文件大到 `sendMessage` 传 `ArrayBuffer` 明显卡住学习窗；
2. 需要学生导出「真实文件夹」或老师交付离线目录包；
3. 纯 JSON 课程库在申请 `unlimitedStorage` 之后仍然因整根 `knownmapV1` 读写成为瓶颈；
4. 必须在 B 站页里稳定播放本机大媒体，消息拷贝无法接受；
5. 正式冻结为 `D-V1-*` 或改写设计 04/05/06：那时以新真源为准，并更新本文件状态。

## 14. 现状对照（实施前）

以下是 2026-08-25 的代码事实，不是目标：

- 本机课程库只有 `chrome.storage.local`，键 `knownmapV1`，Schema `2.0.0`。
- manifest 权限：`storage`、`downloads`。没有 `unlimitedStorage`。
- 插件消息没有取资源类型。
- 学习窗只渲染四类节点的文本/选项，没有 `assetId`。
- 弹窗点课节是打开 B 站 URL，不在插件页内播放资源。

开始 R1 前把这一节改成「已实施对照」，避免后人把现状当成方案。
