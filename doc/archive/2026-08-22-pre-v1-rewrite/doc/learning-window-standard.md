# 学习窗口标准

> 第一阶段使用说明（2026-08-15）：本标准继续作为窗口参考，但当前只实现四种节点完成真实 B 站预览所需的生命周期、展示、提交、跳过和反馈子集。习题本、AI 问答、报告等不在第一阶段。

版本：0.1
更新时间：2026-08-14
状态：目标契约。学生看到的一切课堂内容都在这个一级窗口里。任何新端（插件、网页、本地视频 App、以后的其它 App）实现这份标准即可获得一致的展示与交互。

范围分两块，见第 2 节：**窗口展示与交互强制统一；播放控制与画面增强只是平台建议，不强制。** 窗口里填什么内容由 `doc/node-content-standard.md` 定义。

## 1. 为什么窗口是一级对象

之前的标准从「节点类型」往下拆，结果是提醒、补充、问答各自决定自己长什么样、多大、出现在哪。换一个端就要重新决定一次，统一无从谈起。

现在改成：**先有一个一级窗口，所有内容都装进它。**

```text
一级窗口          尺寸、位置、出现与关闭、键盘、主题
  └─ 窗口内应用    提醒 / 补充 / 练习 / 追问 / AI 问答 / 习题本
       └─ 内容     标题、题目、选项、解释、评价方向
            └─ 去向  是否存进习题本、是否进入 AI 问答、写入哪份学习证据
```

换端只换宿主（谁读时间、谁暂停、窗口挂在哪）。换节点类型只换窗口内的应用。两者都不改窗口本身。

一个端要接入，只需要读这份标准的第 16 节清单。

## 2. 两个范围：强制统一 与 平台建议

这份标准分成性质完全不同的两块，不能混着要求。

### 2.1 强制统一：窗口展示与交互

窗口里的一切必须一致。这是各端接入的合规基线，不达标就不算实现了本标准。

- 窗口骨架与分区（第 4 节）；
- 尺寸档位与内容长度上限（第 5 节）；
- 单例与排队（第 7 节）；
- 打开来源与关闭语义、节点状态（第 8 节）；
- 键盘、焦点、无障碍（第 9 节）；
- 草稿与恢复（第 10 节）；
- 窗口内应用与内容块（第 11 节，字段见节点标准第 5 节）；
- 习题本与归属（第 12 节）；
- AI 问答边界（第 13 节）；
- 证据形状（第 14 节）；
- 未知类型降级（第 15 节）。

同一份课程包在任何端打开，窗口里的标题、题目、选项、解释、评价方向、按钮、状态必须一样。

### 2.2 平台建议：播放控制与画面增强

下面这些取决于宿主平台能做到什么，**只给建议，不强制**。做不到不算不合规，也不需要声明理由。

| 能力 | 说明 | 建议做法 |
|---|---|---|
| 暂停 / 续播 | 跨源 iframe 通常做不到 | 能控就在节点处暂停，不能控就让学生自己停 |
| 跳转与区间重播 | 依赖播放器接口 | 有就提供「重看这一段」并自动回到原处，没有就只在窗口里给回看原文 |
| 画面高亮 | 需要能覆盖画面 | 有就画，没有就只在窗口里给关键词 |
| 字幕遮挡 | 需要知道字幕带位置 | 位置不可靠时不做，不要盲猜坐标 |
| 降低原声 / 播老师音频 | 依赖音频控制权 | 没有就展示文稿 |
| 时间线标记 | 依赖宿主自己的界面 | 可选 |

课程包里的 `effects` 是**老师的期望，不是对宿主的要求**。宿主按自身能力尽力实现，做不到的记进 `unsupportedEffects` 即可，不影响节点完成。

### 2.3 两块的连接点：窗口内自足

平台能力之所以可以只给建议，是因为有这条约束兜底：

**一个节点要表达的内容，必须在窗口内能完整表达。**

- 重点提醒的关键词必须出现在窗口内容区，画面高亮只是增强；
- 老师补充必须有文稿，音频只是增强；
- 练习的题干、选项、解释全部在窗口内；
- 要学生回看的片段，窗口内必须有原文，跳回去重播只是增强。

判断方法只有一句：**把窗口外的东西全部关掉，学生还能不能完成这个节点。** 能，平台差异就只影响体验，不影响学习；不能，就是内容设计错了。

这也是为什么高亮、遮挡、降原声不必强制——它们本来就不承载不可替代的内容。

## 3. 窗口不承担什么

- 不替代播放器控件，不做进度条、音量、清晰度。
- 不做通用聊天窗口。AI 问答是窗口里的一个受限应用，见第 13 节。
- 不做课程目录、账号、设置、营销位。
- 不允许课程包决定窗口的尺寸、颜色、位置或动效。课程包只提供内容。

## 4. 窗口骨架

窗口内部是固定分区。应用只填内容区，不能自己排整窗。这样切换应用时按钮不会跳位置。

```text
┌─────────────────────────────────────────┐
│ header   02 互动练习 · 02:16      2/3  ✕ │
├─────────────────────────────────────────┤
│                                         │
│ content  应用自己的内容块                │
│          （唯一可变区域，可滚动）         │
│                                         │
├─────────────────────────────────────────┤
│ feedback 判定结果 / 解释 / AI 反馈       │
├─────────────────────────────────────────┤
│ status   额度、失败、离线等统一状态       │
├─────────────────────────────────────────┤
│ actions  ⊕ 收藏      [跳过] [提交]      │
└─────────────────────────────────────────┘
```

规则：

- `header` 全应用共用：编号、类型名、时间、进度、关闭。
- `content` 是唯一可变区域。超长时内部滚动，窗口本身不无限长高。
- `feedback` 未产生结果时不占位，出现时从下方推入，不顶掉 `content`。
- `status` 只由窗口写，应用不得自己弹提示。所有失败、额度、离线信息集中在这里。
- `actions` 靠右主操作、靠左次操作；收藏入口固定在左端。按钮只能取自封闭集合：`acknowledge`、`submit`、`retry`、`skip`、`continue`、`revise`、`ask`、`save`。
- 应用切换时 `header` 与 `actions` 高度不变。

窗口渲染模型（各端读同一份，再自己画像素）：

```js
{
  window: {
    app: 'practice',            // 见第 11 节
    sizeTier: 'standard',
    surface: 'overlay',
    theme: 'dark-player',
    dismissible: true
  },
  header: {
    number: '02',
    familyLabel: '互动练习',
    timeLabel: '02:16',
    progress: { current: 2, total: 3 }
  },
  content: { /* 由应用决定，结构见 node-content-standard.md 第 5 节 */ },
  feedback: null,
  status: null,                 // { kind: 'ai_unavailable', text: '...' }
  actions: ['save', 'skip', 'submit']
}
```

## 5. 尺寸档位与内容上限

尺寸只能选档位，不能给自由像素或 CSS。开放自由尺寸等于把自定义样式从后门放回来，也会让老师填的内容在别的端放不下。

| 档位 | 用途 | 相对播放区 | 最小 / 最大 |
|---|---|---|---|
| `compact` | 一句提醒、一次确认 | 宽 ≤ 40%，高 ≤ 30% | 最小 280×120，最大 420×220 |
| `standard` | 练习、追问，默认 | 宽 ≤ 60%，高 ≤ 55% | 最小 320×240，最大 560×460 |
| `expanded` | 习题本、AI 多轮 | 宽 ≤ 80%，高 ≤ 80% | 最小 360×320，最大 720×640 |

档位由应用类型决定，不由老师填写。窗口在小屏改用 `sheet`（见第 6 节），此时档位只影响初始高度。

档位反过来约束老师能填多少字。超出必须在保存时报错，而不是让别的端截断：

| 字段 | 上限 |
|---|---|
| 标题 | 24 字 |
| 提醒正文 / 题干 | `compact` 60 字，其余 120 字 |
| 老师补充文稿 | 200 字 |
| 选项 | 2–6 个，每个 ≤ 40 字 |
| 排序项 | 3–6 项，每项 ≤ 40 字 |
| 高亮词 | ≤ 6 个，每个 ≤ 24 字 |
| 评价方向 / 结构提示 | ≤ 6 条，每条 ≤ 20 字 |
| 解释 | 160 字 |

老师工作台按同一上限校验，预览必须使用与学生端相同的档位。预览换了尺寸，老师看到的就不是真的效果。

## 6. 呈现方式与挂载

`surface` 描述窗口画在哪里，不改变内容。

| surface | 用于 | 说明 |
|---|---|---|
| `overlay` | 插件、本地视频 App | 盖在播放区内，靠近画面但不压住原生控件与字幕带 |
| `docked` | 网页课程壳 | 停在视频旁或视频下方，宽屏靠右、窄屏在下 |
| `sheet` | 手机 | 底部抽屉，可上滑展开、下滑收起 |
| `preview` | 老师工作台 | 静态呈现节点完成后的典型画面 |
| `report` | 完成情况、学生总结 | 只保留编号、类型、最终状态和一句结果 |

挂载规则，几条都来自已经踩到或必然踩到的问题：

- **全屏。** 挂载点取 `document.fullscreenElement`，其次是播放器容器，最后才是 `document.documentElement`，并监听 `fullscreenchange` 重挂。当前 `src/content/subtitle/subtitle-blocker.js` 挂在 `document.documentElement` 上并用视口坐标定位，学生一进全屏，覆盖内容就不再渲染。窗口不能重复这个问题。
- **样式隔离。** `overlay` 必须挂在 Shadow DOM 内，自带全部样式。宿主页面的 CSS 不得渗入，窗口的样式也不得外泄。主题通过 CSS 自定义属性传入。
- **层级。** 窗口高于播放器控件，低于宿主自身的模态弹层；不与 B 站原生弹窗抢焦点。
- **画中画。** 进入 PiP 后画面脱离页面，`overlay` 自动降级为 `docked`，并在窗口内说明当前不覆盖画面。
- **布局跟随。** 播放区尺寸变化、窗口缩放、页面滚动都要重算位置；不可见时不计算。
- **SPA 跳转。** 离开课程页立即卸载窗口、监听器和草稿计时器，不留残余节点。

不得遮挡：原生播放控件、字幕带、宿主的关闭/全屏按钮。与字幕遮挡功能同时存在时，窗口让位，不叠加。

## 7. 单例与排队

**同一时刻只允许一个一级窗口。** 各端复用同一个窗口实例，切换应用只换内容。

会撞车的情况必须有确定规则：

| 情况 | 规则 |
|---|---|
| 两个节点时间挨得很近 | 先到的先显示，后到的进队列，当前窗口关闭后立即接上 |
| 学生正在作答，下一个节点到点 | 不打断。进队列。若宿主能暂停，保持暂停直到队列清空 |
| 学生拖动进度跨过多个未完成节点 | 只显示时间最早的一个，其余保持未完成，不排队 |
| 学生主动打开回看，此时节点到点 | 节点优先，学生的回看退回队列 |
| 学生正在 AI 问答，节点到点 | 不打断问答；节点排队。宿主不能暂停时，该节点改记为手动触发 |
| 队列中的节点因为学生跳到更后面已经失去意义 | 出队，记为未完成，不补弹 |

优先级：节点自动触发 > 学生主动打开 > AI 问答 > 习题本。

队列深度上限为 3。超出的丢弃并记录，避免学生连续被弹五次。

## 8. 生命周期与关闭语义

打开来源有三种，必须分开记录：

| openSource | 含义 |
|---|---|
| `auto` | 播放到点自动触发 |
| `learner` | 学生主动打开某个节点、习题本或 AI 问答 |
| `teacher_preview` | 老师在工作台预览，不写学生证据 |

关闭方式不同，含义完全不同。这是老师报告里「学生卡在哪」的唯一来源：

| closeReason | 含义 | 节点状态 |
|---|---|---|
| `continue` | 学生确认结果后继续 | `completed` |
| `skip` | 学生明确点跳过 | `skipped` |
| `dismiss` | 学生直接关掉窗口，没作答 | `dismissed` |
| `navigate` | 切走、切 P、刷新 | 保持 `drafted` 或 `opened` |
| `teardown` | 宿主卸载 | 同上 |
| `unsupported` | 宿主不认识这个应用 | `unsupported` |

节点状态机：

```text
pending
  -> opened      窗口打开
  -> drafted     有输入但未提交
  -> answered    已提交，等待反馈或重试
  -> completed | skipped | dismissed | unsupported
```

`dismissed` 不等于 `skipped`，`skipped` 不等于 `unsupported`。三者混成「未完成」，老师就分不清是学生放弃、还是产品没显示出来。

`teacher_preview` 全程不写学生证据，也不进习题本。

### 8.1 最小态

窗口有两种可见形态：`normal` 和 `minimized`。最小态只保留一行标题和一个回到窗口的按钮。

最小态用于窗口需要让出画面、但绝不能关闭的场合，目前只有一种：学生在做节点回看（节点标准 4.6 第二层）。视频跳回前面重播时，窗口收成最小态并显示「重看中 · 回到练习」。

规则：

- 最小态不改变节点状态，不写 `closeReason`，草稿与已选答案原样保留；
- 最小态期间不触发其它节点，队列照第 7 节处理；
- 恢复 `normal` 后，内容区回到进入最小态前的样子；
- 最小态不是关闭的替代品。学生点关闭仍然记 `dismiss`。

## 9. 键盘、焦点与无障碍

窗口打开后会和宿主抢按键，必须明确：

- 窗口获得焦点期间，拦截并阻止冒泡宿主的播放快捷键，至少包括空格、方向键、`F`、`[`、`]`。学生在输入框里打字时按空格，不能把视频暂停或播放。
- `Esc` 收起窗口，记为 `dismiss`；必须阻止冒泡，避免同时退出全屏。
- 单行输入按 `Enter` 提交；多行输入不提交。中文输入法组合期间（`isComposing`）一律不提交。
- 打开时焦点移到窗口标题，`Tab` 在窗口内循环，关闭后焦点归还原位置。
- 窗口是 `role="dialog"` 且 `aria-modal`，标题与内容有关联；`status` 区用 `aria-live="polite"` 播报判定结果和失败提示。
- 内容变化只用推入，不用会打断读屏的整块替换。

主题只有两套，由宿主按背景选，不由课程包配置：

| theme | 用于 | 要求 |
|---|---|---|
| `light-paper` | 网页、浅色背景 | 沿用暖纸白与墨绿，正文对比度 ≥ 4.5:1 |
| `dark-player` | 覆盖在播放器上 | 深色半透明底加实色内容层，正文对比度 ≥ 4.5:1 |

`dark-player` 不能只靠透明度压暗画面，否则亮画面上文字不可读。

## 10. 草稿与恢复

学生写到一半离开是常态，不能默默丢。

- 每次输入变化按 `(sessionId, nodeId)` 本地存草稿，节流写入。
- 窗口重新打开时恢复草稿，并在 `status` 区说明这是上次未提交的内容。
- 提交成功后清除草稿。
- 草稿只存本地，不进老师报告，不算作答。
- 会话结束或课程包版本变化时清理草稿。

## 11. 窗口内应用

应用是封闭枚举，只有平台能新增。

| app | 来源 | 默认档位 | 主操作 |
|---|---|---|---|
| `notice` | 重点提醒节点 | `compact` | `acknowledge` |
| `voice` | 老师补充节点 | `compact` | `continue` |
| `practice` | 互动练习节点 | `standard` | `submit` |
| `followup` | 点评追问节点 | `standard` | `submit` |
| `ask` | 学生主动发起的 AI 问答 | `standard` | `submit` |
| `notebook` | 学生打开课程习题本 | `expanded` | `continue` |
| `unsupported` | 宿主不认识的类型 | `compact` | `continue` |

前四个的内容字段见 `doc/node-content-standard.md` 第 5 节。同一次打开内可以从练习切到追问、再切到 AI 问答或收藏，窗口不重开，`header` 编号保持指向当前节点。

## 12. 课程习题本

习题本是窗口里的一个应用，不是另一个页面。学生的界面始终只有这一个窗口。

### 12.1 存什么

保存内容快照，同时保留节点引用。条目内部按**作者**分成两块：

```js
{
  savedAt: 'ISO-8601',
  source: {
    lessonId: 'english-interview-demo',
    lessonVersion: 3,
    nodeId: 'node-2',
    timeSeconds: 136
  },

  // 老师 / 系统提供的内容。不是学生数据，不涉及隐私。
  snapshot: {                   // 保存当时的内容，之后不随课程变化
    app: 'practice',
    title: '排出处理同事冲突的四个步骤',
    prompt: '把四步排成视频中的顺序。',
    items: [ /* ... */ ],
    explanation: '先反思自己，再私下沟通，听对方，最后一起找办法。'
  },

  // 学生产生的内容。归属由学生决定。
  learner: {
    submittedAnswer: ['private', 'reflect', 'listen', 'solve'],
    correct: false,
    note: '第二步我一开始想成先找对方谈。',
    tags: ['错题'],
    askedQuestions: [],
    visibility: 'submitted'     // submitted | private | shared
  },

  feedback: { text: '...', origin: 'ai' }
}
```

快照保证老师改课不会让学生已存的题变样或消失；引用保证还能跳回原课的那个时间点。

课程更新后，引用失效或内容已改的条目标注「原课已更新」，并提供跳到最新节点。快照本身不改写。

### 12.2 保存粒度

窗口 `actions` 左端固定一个收藏入口，可保存：

- 整个节点（题目 + 解释）；
- 单句（字幕原句、某个选项、某条评价方向）；
- 我的答案；
- 收到的反馈，包括 AI 反馈，标记 `origin: 'ai'`；
- 学生自己写的笔记与标签。

同一节点重复保存时合并，不产生重复条目。

### 12.3 归属按作者划分

题目、提醒、解释、评价方向都是老师或系统提供的内容，不是学生数据，可见性不构成隐私问题。需要学生决定归属的，只有学生自己产生的内容。

| 内容 | 作者 | 归属 | 老师可见 |
|---|---|---|---|
| 题目、提醒、文稿、解释、评价方向 | 老师 / 系统 | 课程内容 | 是，与隐私无关 |
| 在窗口里提交的作答 | 学生 | 学生 | 是。提交本身就是交给老师的动作 |
| 学生写的笔记、标签、批注 | 学生 | 学生 | 默认否，可主动分享 |
| 学生向 AI 提的问题 | 学生 | 学生 | 默认否，可主动分享 |
| 学生自选的书签、复听片段、跨课程收藏 | 学生 | 学生 | 否 |

`learner.visibility` 三个取值：

- `submitted`：学生按老师设计的节点提交的作答。这是课程交付的一部分，提交时窗口明示「提交后老师可见」。
- `private`：学生自己写的内容，默认值。
- `shared`：学生主动把某条私有内容分享给老师。

规则：

- 默认值按作者判断，不按存储位置判断。同一条习题本条目里，题目可见、笔记不可见，是正常状态。
- 学生可以随时把 `private` 改成 `shared`，也可以撤回。撤回后老师侧不再展示。
- 老师看到的永远是内容条目，不是学生的浏览行为、停留时长明细或收藏动作流水。
- 学生对自己产生的内容可以导出和删除；删除自己的笔记不影响节点作答这类已交付的学习证据。

保存失败时在 `status` 区说明并允许重试，不能静默丢失。

## 13. AI 实时问答

`ask` 是窗口里的受限应用，不是聊天窗口。

### 13.1 边界

绑定当前节点。上下文只包含：

- 课程标题与当前节点的 `display`；
- 学生在本节点的作答与判定结果；
- 本次问答最近若干轮。

不包含：其它节点、其它课程、学生身份、观看历史。

超出当前节点范围的问题，明确说明并引导回课程，不改造成通用助手。不承诺考试、面试或招聘结果。

### 13.2 与学习进度的关系

- AI 问答**不计入节点完成度**。学生问过五个问题，节点仍可能是未作答。
- 但要记录发生过：问答轮次、时间、是否失败。老师能看到「这里有人反复提问」，这是改课的信号。
- 学生问了什么属于学生自己写的内容，默认不给老师看，可主动分享。老师默认只看到某个节点上发生过多少次提问，看不到问题原文。
- AI 的回答由系统产生，随所属条目一起处理；存进习题本时标记 `origin: 'ai'`。

### 13.3 失败与降级

- 额度不足、超时、服务不可用，全部显示在 `status` 区，保留学生已输入的问题。
- 不用固定模板冒充回答。
- AI 不可用不影响节点本身的确定性作答和继续播放。
- 没有 AI 能力的宿主不显示 `ask` 入口，而不是显示一个点了没反应的按钮。

### 13.4 待定

老师能否按课程开关 `ask`、额度由谁承担，尚未决定。标准先预留 `aiAsk: { enabled }` 与 `status` 区的额度位置，实现等自由回答的 AI 链路跑通后再定。见第 17 节。

## 14. 学习证据

证据分两层，都按节点 id 对齐。

窗口层记录交互事实：

```js
{
  nodeId: 'node-2',
  openSource: 'auto',
  surface: 'overlay',
  sizeTier: 'standard',
  openedAt: 'ISO-8601',
  closedAt: 'ISO-8601',
  dwellMs: 42100,
  closeReason: 'continue',
  askRounds: 0,
  recapPlayed: 1,
  savedToNotebook: true,
  unsupportedEffects: ['duckOriginal']
}
```

`recapPlayed` 只统计学生重看了几次，不产生第二条节点证据。反复重看同一段是老师需要看到的信号。

节点层记录作答事实，形状见 `doc/node-content-standard.md` 第 8 节。

`teacher_preview` 来源的窗口不写入这两层。

## 15. 版本与未知类型

窗口标准自带版本号，与课程包 `schemaVersion` 分开。宿主启动时声明自己实现到哪个窗口版本。

遇到不认识的 `app`、`family` 或 `interaction`：

- 显示 `unsupported` 应用：一句「这个内容需要更新到新版本」加一个继续按钮；
- 绝不白屏、绝不崩溃、绝不静默跳过；
- 记为 `unsupported`，不得记成学生跳过或已完成；
- 老师侧提示「本课使用了较新内容，部分学生的客户端版本可能过低」。

窗口按钮文案属于宿主，不属于课程包。课程包不携带界面文案。

## 16. 其它端接入清单

一个新端要接进来，不需要理解 B 站或任何具体页面。

必做，四件事：

```text
1. 渲染窗口      按第 4 节骨架和第 5 节档位渲染，或直接复用平台渲染器
2. 提供挂载点    支持 overlay / docked / sheet 中至少一种，处理全屏与卸载
3. 回传事件      submit / skip / continue / dismiss / ask / save
4. 写入证据      窗口层与节点层两份，按第 14 节形状
```

按平台能力选做：

```text
5. 声明能力      canObserveTime / canPause / canSeek /
                canOverlayVideo / canDuckAudio / canPlayTeacherAudio
6. 提供时间源    能读时间就推 onTime，支持自动触发
                不能读就只支持学生手动打开，同样合规
7. 画面增强      高亮、字幕遮挡、降原声，能做则做
```

只做前四件、完全不控播的端也是合规实现。它的学生打开的是同一个窗口、同一份内容，只是需要自己点开节点。

调用面：

```js
mount({ lesson, adapter, capabilities, surface, theme, sessionStore })
onTime(seconds)
openWindow({ nodeId, app, openSource })
present(state) -> 第 4 节渲染模型
submit(nodeId, response)
ask(nodeId, question)
save(nodeId, selection)
closeWindow(reason)
teardown()
```

`adapter` 沿用 `doc/design.md` 的 `PlayerAdapter`。不能读时间的端不实现 `onTime`，其余完全一致。

验收一个新端是否合规，把同一份课程包分别交给它和插件：

- **必须一致**：窗口里的标题、题目、选项、解释、评价方向、按钮、状态语义、证据形状。
- **允许不同**：窗口画在哪、能不能自动暂停、能不能跳转、有没有画面高亮、有没有字幕遮挡、有没有老师音频。

第二组的差异不算缺陷，不需要在学生界面解释成「功能不可用」。

## 17. 待定问题

- `ask` 的老师开关与额度归属未定，等自由回答 AI 链路跑通后决定。
- 学生能否拖动或缩放窗口、偏好是否跨课程记忆，尚未决定；默认不可自由缩放，只能选档位。
- 同一学生在两个端同时打开同一课时的习题本与草稿冲突处理，第一版不做，需先确认是否真实发生。
- 窗口动效时长与减少动效偏好，待视觉阶段确认。

这些都不阻塞按本标准实现第一个宿主。
