# 学生插件课程库、课程升级与设置设计

状态：已确认并按 2026-08-28 审核修订；依据 2026-08-28 第十二版视觉草稿；进入开发计划阶段。

视觉资产：[`../assets/2026-08-28-course-library-sync-layout.html`](../assets/2026-08-28-course-library-sync-layout.html)

本次修订依据：[`D-V1-022`](../../../doc/decisions/2026-08-28-student-course-library-contract-boundaries.md)。

## 1. 产品目标

学生插件首页要能管理多门课程，同时让学生清楚地区分三件事：领取新课程、升级已有课程、打开并继续学习课程。课程列表不能因为课程增加而无限变长，插件设置要能控制首页入口和同步行为。

## 2. 已确认的交互规则

### 2.1 课程列表

- “全部课程”就是学生本机已经安装的课程总列表。
- “需要升级”是已安装课程中服务端存在更新版本的课程。
- 每个列表区最多直接显示 3 门课程。
- 列表总数不超过 3 门时，显示全部课程，不显示更多入口。
- 列表总数超过 3 门时，只显示 3 门，下方显示“更多课程”或“打开更多待升级课程”。
- 更多列表按每页 10 门分页。
- 课程卡片可直接打开；卡片内保留明确的“打开课程”按钮。
- 课程升级动作统一使用“升级”，不再使用“同步”。

### 2.2 更新提示

- 更新提示是小型浮窗，不占课程列表的固定位置。
- 文案为“有 X 门课程可以升级，当前学习不会被打断”。
- 浮窗使用低饱和淡红色，只做状态提示，不把升级按钮染成红色。
- 小箭头用于收起浮窗，叉号用于关闭本次浮窗。
- 关闭提示不等于拒绝升级，课程仍可从“需要升级”区域手工升级。

### 2.3 课程身份、版本和检查触发

- 每门课程有一个长期不变的 `courseId`，表示逻辑上的同一门课程。
- 每次发布都会生成一个不可变的 `releaseId`，并在该课程内递增 `releaseNumber`。`releaseId` 用于精确判断版本，`releaseNumber` 用于展示和审计，不能只比较课程标题、更新时间或数组位置。
- 插件本地保存 `courseId`、已安装 `releaseId` 和 `releaseNumber`。旧版本本地数据没有 `releaseId` 时视为版本未知，下一次检查必须返回一次更新候选。
- 本轮不通过升级检查发现新课程；“课程升级”只表示本机已有同一 `courseId`，但本地 `releaseId` 与后端当前可交付 `releaseId` 不一致。新课程必须通过授权码领取，也不等于“推荐课程”。
- 自动检查有两个受控触发点：学生点击插件小图标打开主 popup/插件设置页，或打开并精确匹配到已安装课程的 B 站课程页面。插件界面关闭且没有匹配课程页时不启动定时器、不在后台轮询。
- 主 popup 或设置页打开后，由 background 读取本机已安装课程的 `courseId + releaseId`，向后端提交全量检查请求。后端先核对这些课程是否仍在本机有效授权范围内，再只返回这些已安装课程的版本摘要，并为每门课程标记 `unchanged`、`update` 或 `unauthorized`；检查阶段只返回摘要，不下载完整课程包。
- B 站页面触发时，content script 必须先通过现有的 BVID + `page`/`cid` 精确匹配得到课程 `courseId`，再由 background 对该 `courseId` 发起课程级检查。课程级检查比较整门课程的当前 `CourseRelease`，不能只检查当前视频分 P、当前课节或当前节点；匹配不到课程时不请求后端。
- 打开主 popup 或设置页的检查是必要行为，不受升级模式关闭影响；升级模式只决定发现版本后的处理方式。学生仍可点击“检查更新”重新发起检查。

### 2.4 升级模式

设置提供三种模式：

1. 自动升级：打开插件发现新版本后，在安全时机自动替换；当前课节正在学习时延后。
2. 提示升级：打开插件发现新版本后提示学生，学生确认后替换。
3. 手动升级：打开插件、设置页或匹配课程页时照常检查，但不自动替换；只有学生点击“升级”才安装。

默认模式为“提示升级”。检查只发生在打开插件主界面/设置页、精确匹配到课程的 B 站页面或手工点击检查更新时；不能在当前课节会话中热切换课程内容。

检查结果和处理动作分为两阶段：

1. 检查阶段返回本机已安装课程的身份、当前发布版本和 `status`（`unchanged`/`update`/`unauthorized`），用于显示“需要升级”或授权状态；不返回本机未安装课程。
2. 学生点击升级，或自动升级模式确认当前没有活跃学习会话后，background 再按选中的课程请求完整课程包；服务端必须再次核对授权和期望版本，不能信任 popup 缓存的检查结果。

升级过程中显示“正在准备课程内容和资源 X/Y”，只有课程 JSON、节点引用和全部必需资源都完成校验后才显示成功。成功后显示“课程已升级到第 X 版”；资源下载失败时显示失败提示并继续使用旧版本，不把课程卡片标成已升级。

当前本机授权体系下，“拥有的课程”是服务端根据 `LocalIdentity + Redemption + GrantItem` 算出的有效授权课程，不是公开课程目录。跨设备发现课程需要后续学生账户和设备绑定能力，本轮不假定已经存在。

### 2.5 升级后的学习记录

- 相同课节、相同节点且节点内容没有变化：保留完成状态和历史作答。
- 相同课节、相同节点但内容发生变化：清除完成状态，保留历史作答。
- 新增节点：未完成。
- 删除节点：不再显示，历史作答保留在本机。
- 课程升级失败：继续使用旧课程，不产生新旧内容混合状态。

节点身份由 `lessonId + node.id` 确定。节点内容比较时排除 `id`、学生学习状态和 `captionId`，比较标题、互动类型、正文、互动数据、触发时间、效果和展示提示。教师编辑器已经在编辑、移动和切换题型时保留节点 `id`；删除后重新创建的节点会得到新身份，不猜测为旧节点。

## 3. 已安装课程升级判定

后端只检查客户端提交的本机已安装课程清单。全量检查时检查这台机器的全部已安装课程，课程页检查时只返回指定 `courseId` 的结果，但仍以整门课程版本做比较。返回的是授权校验后的版本元数据，不是课程包：

| 本机状态 | 后端授权/版本状态 | 结果 | 首页区域 |
| --- | --- | --- | --- |
| 有该 `courseId` | `releaseId` 不同 | 已安装课程有新版本 | 需要升级 |
| 有该 `courseId` | `releaseId` 相同 | 无变化 | 全部课程 |
| 有该 `courseId` | 无有效授权 | `unauthorized`，不下发课程包 | 保留本机旧课程，提示授权状态 |

版本判定以服务端当前可交付的 `releaseId` 为准；`releaseNumber` 只作为一致性校验和 UI 展示。后端不得把未授权课程的标题、版本或课程包泄露给本机。

升级申请必须带上检查时看到的期望 `releaseId`。如果服务端在申请时已经发布了更高版本，服务端应拒绝旧候选并要求重新检查，避免把过期课程包安装到本机。

## 4. 首页组成

首页自上而下包含：

1. 标准 KnownMap 图标与 K/M 彩色字标；真实实现复用 `v1/site/assets/knownmap-icon.png` 和 `v1/extension/assets/icon-48.png`。
2. 可收起/关闭的升级浮窗。
3. “领取新课程”入口，默认显示，进入授权码输入窗口。
4. “需要升级”课程区。
5. “全部课程”课程区。
6. “为你推荐”区域，默认显示。
7. 设置入口。

已安装课程的 `update` 结果显示在“需要升级”。新课程不由升级检查发现，只通过“领取新课程”输入授权码。“领取新课程”和“为你推荐”分别由设置页的开关控制。关闭只隐藏首页入口，不删除课程、授权来源或学习记录。

需要明确：如果学生要领取新课程，仍然通过首页“领取新课程”输入授权码；课程升级检查不负责发现或展示未安装课程。

## 5. 设置页

设置页分为：

- 学生入口：显示未登录/已登录状态，提供学生登录入口；登录不阻挡授权码领取和本机课程学习。
- 首页显示：控制“领取新课程”和“为你推荐”，默认开启。
- 课程升级：选择自动升级、提示升级、手动升级，控制自动检查和手工检查。
- 页面陪伴：小人 Logo 选项、默认快捷键和快捷键修改入口。
- 更多功能：为记事本、学习日志、课程推荐等后续功能预留入口。

设置是插件本地偏好，不进入课程包，不影响服务端授权资格。

## 6. 范围边界

本次第一实施单元实现课程库分页、课程升级、学习记录迁移、首页显示设置、授权码入口和标准品牌资源复用。

学生账户登录和真实课程推荐属于独立后端域。当前仓库没有学生账户、会话、跨设备学习记录或推荐目录数据模型，因此先保留设置入口和页面结构，账户认证接口、账户与本机身份绑定、推荐数据接口分别在冻结对应后端契约后实施。不得用静态示例课程冒充真实推荐结果。

## 7. 课程内容与资源生命周期

### 7.1 当前真实资源结构与缺口

- 结构化课程文档当前保存在节点的 `content` JSON 中，课程包只保存文本、标题、互动数据和资源引用。
- 课程包的 `assets` 当前是资源清单，不是文件内容，只包含 `assetId`、`kind`、`mimeType`、`byteSize`、`sha256` 等元数据。
- 服务端已经有教师资源存储：文件位于配置的 `asset-storage` 目录，数据库/版本快照保存资源清单和节点引用；现有读取接口只允许教师访问。
- 插件的 `chrome.storage.local` 当前只适合保存课程 JSON、资源元数据和学习记录，没有独立的学生资源文件存储，也没有学生资源下载接口。
- 当前 content runtime 对富文档只保留 `assetId` 标记，尚未把它解析成可加载的图片、音频或视频地址。因此课程版本升级即使成功，媒体资源也可能显示不出来。
- `ReleaseLessonSnapshot` 已保存字幕数据，但依据 `D-V1-014`，字幕原文止步于教师侧发布快照；课程包和插件不接收字幕，本轮不补字幕交付字段。

### 7.2 资源应该放在哪里

| 内容 | 服务端 | 插件本地 |
| --- | --- | --- |
| 课程、课节、节点、版本号 | 数据库中的课程/发布快照 | `chrome.storage.local` 的课程 JSON |
| 结构化文档正文 | 发布快照中的 `node.content` | 随课程 JSON 原子替换 |
| 字幕/文本文档 | 发布快照中的字幕文档 | 不进入学生课程包或插件本机存储 |
| 图片、音频、视频二进制 | 持久化对象/文件存储；当前为 `asset-storage`，生产环境必须挂载持久卷或对象存储 | IndexedDB/Cache Storage 的 Blob，不放 `chrome.storage.local` |
| B 站原视频 | B 站平台，插件只做播放匹配 | 不下载、不复制到课程资源仓库 |

课程包和本地课程只保存资源引用与校验信息。学生资源下载必须走授权的学生资源接口，不能直接复用教师资源链接，也不能把服务端磁盘路径或永久公开 URL 写进课程包。

### 7.3 升级后的显示与本地更新

1. 检查阶段只显示课程名称、旧版本/新版本和“升级”按钮；不会因为检查而替换当前课程或当前页面内容。
2. 用户点击升级后，background 创建按 `courseId + targetReleaseId` 隔离的 staging 区，先取得课程包和该版本引用到的全部资源；字幕原文不在学生交付链路中。
3. 已有本地资源按内容哈希复用；缺少或哈希不同的资源下载到 staging，并校验 `sha256`、`byteSize`、`mimeType` 和资源类型。
4. 所有节点引用、资源清单和资源文件都验证通过后，才在一次串行写操作中切换到新课程版本；正在学习的 B 站页面继续使用旧课程直到当前会话安全结束。
5. 切换成功后，popup 显示“已升级到第 X 版”，课程卡片更新版本信息；升级失败显示失败原因并继续使用旧课程，不出现新旧资源混合。

### 7.4 重复资源、新资源和删除资源

- `assetId` 是课程内容里的引用标识，`sha256 + mimeType` 是二进制内容的去重身份。
- 同一 `assetId` 且哈希相同：不重新下载，继续引用本地 Blob。
- 同一 `assetId` 但哈希不同：视为资源内容被替换，先写入新的哈希 Blob；旧 Blob 在旧课程版本不再引用且回滚保护结束后再垃圾回收，禁止原地覆盖。
- 不同 `assetId` 但哈希相同：复用同一份本地 Blob，保留两个逻辑引用。
- 新版本删除资源：从新课程的活动资源清单移除，但不立即删除物理 Blob；由引用计数/最后访问时间的 GC 任务清理无引用资源。
- 资源下载、校验或配额失败：整个课程版本不切换，staging 可清理，旧课程和旧资源保持可用。

### 7.5 文件类型边界

- 图片、音频、MP4/WebM/OGG 视频沿用现有资源类型，但必须补齐学生授权下载、缓存和运行时解析。
- 结构化课程文档和字幕属于 JSON/文本内容，不应伪装成媒体文件。
- 当前资源白名单没有 PDF、DOCX 等可下载文档类型，也没有插件端文档阅读器；如果业务要求上传这类文件，需要另行增加 `document`/`pdf` 资源契约、下载策略和阅读组件，不能把它们当作普通音频或视频处理。
- 外部 B 站视频仍是课程的播放载体，不作为可下载课程资源；课程自己的视频文件才进入资源仓库。

## 8. 多课程升级队列与中断恢复

### 8.1 排队规则

- 每门课程同一时间只允许一个升级任务，任务键为 `courseId + targetReleaseId`；同一课程重复点击不能产生重复任务。
- 多门课程按学生明确点击的顺序进入队列；自动升级按检查结果的稳定顺序入队，并以 `courseId` 作为并列时的稳定排序键。
- 同一课程在排队期间再次检查到更高版本时，更新该任务的目标版本，不排第二个同课程任务。
- 队列一次只执行一个课程的资源下载和提交。当前 B 站课程正在学习时，该课程升级标记为“等待当前学习结束”，调度器可以继续处理其他安全课程。
- popup 关闭不会删除队列；学生可以在下次打开插件时继续查看、暂停、继续或取消任务。

### 8.2 任务状态

任务状态持久化在本机：`queued`、`downloading`、`verifying`、`ready_to_commit`、`committed`、`paused`、`failed`、`cancelled`。记录至少包括 `courseId`、旧/目标 `releaseId`、创建时间、当前资源、已完成资源哈希、重试次数和最后错误。

### 8.3 中断和“升级一半”

- 目标课程内容和资源始终先写入 `courseId + targetReleaseId` 的 staging 区，不能直接覆盖当前活动课程或当前活动资源。
- 下载中断、popup 关闭、浏览器重启、网络错误或 service worker 被回收时，任务保留检查点；下次受控触发时从已验证资源继续，无法续传的单个资源可以从头下载。
- 只有课程包、节点引用和所有必需资源全部校验通过，才执行一次“提交”：先写入新课程和新资源引用，再更新活动 `releaseId`；提交完成后才把任务标记为 `committed`。
- 如果进程在提交前停止，旧课程继续可用，staging 可恢复或清理；如果进程在提交后、清理前停止，新课程继续可用，清理任务下次恢复。
- 任何失败都不能出现“课程 JSON 已换成新版但媒体仍是旧版”或“媒体已替换但课程仍引用旧清单”的半更新状态。
- 旧版本至少保留到新版本提交成功且当前学习会话安全结束；无引用资源只能由后续 GC 清理，不能在升级失败路径中误删。
