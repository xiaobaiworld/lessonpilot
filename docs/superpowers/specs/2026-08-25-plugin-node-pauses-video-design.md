# 互动节点触发时暂停视频设计

状态：已接受，待实现

日期：2026-08-25

## 背景

学生插件按视频时间触发互动节点。当前运行时在节点触发时要求播放器暂停，在窗口关闭时要求播放器继续播放，但关闭逻辑没有记录这次暂停是否由插件造成，可能把用户原本手动暂停的视频重新播放。

## 已确认事实与边界

- 节点只在播放进度推进到触发时间时触发。
- 触发后窗口打开，视频必须暂停。
- 学生提交后先看到反馈；关闭当前窗口后才允许继续播放。
- 如果触发前视频已经暂停，插件不应接管播放状态，关闭窗口后仍保持暂停。
- 不改变节点判分、作答记录、课程模式切换和播放器适配器的职责边界。

## 方案选择

### 方案 A：关闭时无条件播放

实现最简单，但会覆盖用户原本的暂停状态，违反播放控制的最小干预边界。放弃。

### 方案 B：运行时记录插件暂停归属

`CourseRuntime` 在节点触发时读取播放器当前状态，并只在播放器当时处于播放状态时标记本次暂停归属。关闭窗口时，仅当该标记为真才调用 `play()`；完成关闭或课程模式切换后清理标记。选择此方案，因为播放器归属属于运行时与宿主协作的行为，改动小且可测试。

### 方案 C：把播放器归属放进 `LearningSession`

需要让纯状态机接收播放器状态，扩大逻辑边界，且不能减少运行时的协调代码。放弃。

## 设计

在 `CourseRuntime` 增加一次节点暂停的归属状态：

1. `tick()` 得到 `pause` 动作时，先读取 `player.isPlaying()` 或等价的可观察播放状态。
2. 只有播放器当时正在播放，才调用 `pause()` 并记录 `pausedByRuntime = true`。
3. 如果播放器当时已暂停，保持 `pausedByRuntime = false`，窗口仍然显示，但关闭时不调用 `play()`。
4. `close()` 在会话返回 `resume` 时，只有 `pausedByRuntime` 为真才调用 `play()`，随后清除标记。
5. `stop()`、切换原视频模式和播放器生命周期结束时清除该标记，避免旧节点状态影响后续页面。

播放器适配器提供最小的 `isPlaying()` 读取能力，真实实现基于 HTML 视频元素的 `paused` 和 `ended` 状态；测试替身同步实现该接口。

## 测试

- 正常播放到节点：触发时调用一次 `pause()`，关闭窗口后调用一次 `play()`。
- 节点触发前播放器已暂停：窗口仍出现，关闭后不调用 `play()`。
- 现有提交、反馈、seek、课程/原视频模式切换和页面清理测试保持通过。

## 假设与重开条件

- “关闭节点”指当前窗口的最终继续操作，而不是仅提交答案。
- `ended` 视为非播放状态，不由插件重新播放。
- 如果宿主播放器未来不再能可靠读取播放状态，应暂停本功能的自动恢复并重新评估播放器适配协议。
