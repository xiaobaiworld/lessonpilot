# 重点提示结构化排版设计

## 背景

当前学生端重点提示节点只支持 `title + body`。示例课程把学习顺序、题目数量、总结和激励语全部拼在一个长字符串里，学生看到的是一整段连续文字，缺少阅读层级，弹窗也容易显得拥挤。

本次采用视觉比较中的 **C · 重点摘要** 方案：把内容组织成“先理解、再练习、最后巩固”三层摘要，同时保留确认后继续播放的原交互。

## 范围

### 保留

- 重点提示在视频触发时暂停播放。
- 标题“重点提示”。
- “确认并继续”按钮。
- 课程模式、原视频模式、小人和书包等已有功能。
- 旧课程包只提供 `title + body` 时仍能正常显示。

### 修改

- 重点提示支持结构化摘要内容。
- 弹窗使用更清晰的视觉层级：标题、引导语、摘要条目、总结提示、底部操作。
- 长内容在弹窗内部滚动，不撑破视频页面。
- 示例课程的第 2 秒提示改为 C 方案内容。

### 不包含

- 不修改选择题、填空题和问答题的交互。
- 不改变课程节点触发时间和重播逻辑。
- 不新增富文本 HTML 注入；课程内容仍使用安全的文本节点渲染。
- 不做全站视觉重构。

## 内容模型

在 notice 节点的 `display` 中增加可选的结构化字段：

```ts
type NoticeSummary = {
  eyebrow?: string;
  intro?: string;
  sections?: Array<{
    label: string;
    body: string;
  }>;
  summary?: {
    title: string;
    body: string;
  };
};
```

`body` 继续保留并作为旧数据的回退内容。新字段存在时，学生端优先渲染结构化摘要；不存在时沿用原来的单段文字渲染。

示例课程使用：

- `eyebrow`: “把答案说得具体”
- `intro`: 说明本节通过 4 道题练习具体表达
- `sections`: “先理解”“再练习”“最后巩固”
- `summary`: 掌握“情境—行动—结果”，末尾保留“加油”

## 视觉与交互

1. 弹窗保持适中的桌面宽度和最大高度，内容区域可滚动。
2. 顶部使用小图标、标题和副标题，不显示时间戳。
3. 三个摘要条目使用竖向时间线或短色点连接，突出学习顺序。
4. 总结使用浅色提示区域，与正文区分。
5. “确认并继续”固定在底部，点击后关闭提示并恢复视频。
6. 继续使用 Shadow DOM，避免 B 站页面样式污染。
7. 小屏幕下摘要条目改为单列，按钮保持可点击尺寸。

## 数据流

课程包加载后，`RuntimeNode.display` 保持宽松对象类型。`LearningWindow` 在 notice 分支读取可选的 `eyebrow`、`intro`、`sections` 和 `summary`，使用 `textContent` 创建 DOM。

课程合同校验需要允许这些字段，并继续拒绝未知字段、空标题和空摘要条目。旧课程只包含 `title + body` 时，不进入结构化分支。

## 测试

按本次改动范围执行插件相关验证：

- 课程合同：接受结构化 notice display，拒绝缺字段或空字段。
- 窗口渲染：结构化 notice 输出标题、三段摘要、总结和确认按钮。
- 窗口渲染：旧版 `title + body` 仍输出单段内容。
- 回归检查：确认按钮仍为“确认并继续”。
- 插件构建：最终 ZIP 包含更新后的内容脚本。
- 手工冒烟：打开示例视频，在第 2 秒确认窗口暂停；点击确认后恢复播放；重新播放时提示再次出现。

不执行教师端、无关页面和全项目全量测试，因为本次改动只涉及 V1 插件的 notice 数据、窗口渲染和示例课程。

## 验收标准

- 学生不再看到一整段连续的长文本。
- 能快速看懂本节的三个阶段和五个原有节点安排。
- 能看到“4 道题”和“情境—行动—结果”的总结。
- “加油”保留且视觉上不抢主层级。
- 弹窗在常见桌面窗口和较窄页面中都不溢出。
- 旧课程包不因新增格式而无法显示。
