# 授权码创建与管理设计

- 日期：2026-08-28
- 状态：提议中；交互与模块方向已确认，待实现前文档评审
- 关联决策：`D-V1-019`、`D-V1-020`
- 关联需求：`FR-GRANT-001` 至 `FR-GRANT-005`、`FR-GRANT-012`、`FR-GRANT-013`、`DATA-DELIVERY-003`、`DATA-DELIVERY-005`、`SEC-SECRET-003`

## 1. 目标

把当前“基于一门课程快速生成授权码”的入口扩展为可理解、可追溯的教师授权管理：

1. 创建时可选择一门或多门当前教师自己的已发布课程；
2. 每门课程可授权整门课程或指定课节；
3. 可设置批量生成数量；
4. 可设置领取窗口与授权使用有效期；
5. 可记录接收人和教师备注，允许留空并在生成后补记；
6. 生成后可查看完整码、范围、领取摘要和状态；
7. 支持单条及批量冻结、恢复和作废；
8. 作废不是物理删除，所有授权记录和领取事实继续保留。

## 2. 明确不做

1. 本轮不建立单独的全局授权中心；入口仍从已发布课程卡片进入授权码管理页。
2. 本轮不要求学生注册、登录或填写接收人信息；接收人字段只属于教师侧记录。
3. 本轮不改学生兑换和更新端点；冻结、作废由现有资格计算读取授权码状态后自然阻止未来在线资格。
4. 本轮不实现教师自定义授权码生成规则。
5. 后续自定义规则以“生成模板/规则”为方向，例如课程名称、序列号、随机片段的组合；规则输出必须满足长度下限、格式校验和唯一性。
6. 本轮界面先暴露整门课程和课节级授权；节点级数据结构保持兼容，但不扩大本次页面复杂度。

## 3. 页面与用户流程

### 3.1 进入管理页

教师在已发布课程卡片点击“授权码管理”，进入现有
`AccessCodesPage`。URL 继续使用 `?access=<course_id>`，当前课程作为页面上下文和创建表单的默认范围。

管理页包含：

- 页面标题、课程上下文和“新建授权码”；
- 搜索框：授权码、接收人、教师备注；
- 状态筛选：全部、有效、冻结、作废；
- 领取情况筛选：全部、未领取、已领取；
- 授权码列表；
- 当前选中记录的详情栏。

本轮列表数据仍使用教师授权码查询结果在前端筛选，避免为小规模页面增加独立搜索服务；未来记录规模需要分页时再扩展查询契约。

### 3.2 创建授权码

点击“新建授权码”打开右侧创建栏，创建栏按以下顺序呈现：

1. **授权范围**：当前课程默认选中；可添加当前教师自己的已发布课程；每门课程选择整门或指定课节。
2. **新建数量**：`1–100`。数量为 1 时显示单个生成语义，数量大于 1 时显示批量生成语义。
3. **有效时间**：提供常用模板，并可展开高级设置。系统始终分别提交领取窗口和授权项有效时间。
4. **接收人记录**：接收人和教师备注均可为空；批量创建时作为整批默认值。
5. **确认摘要**：显示课程数、课节范围、生成数量、时间规则和接收人记录适用范围。

生成成功后：

- 单个或批量结果进入同一管理列表；
- 教师可复制每条完整授权码；
- 批量结果明确显示每条码的独立状态和领取情况；
- 如果网络结果未知，页面不得重复创建新批次，重试使用原批次幂等键。

### 3.3 查看与修改教师记录

点击列表行打开详情栏，显示：

- 完整授权码；
- 当前状态；
- 接收人和教师备注；
- 授权范围；
- 领取窗口和授权使用有效期；
- 已领取设备数、首次领取和最近领取时间；
- 状态变化和创建/领取等可展示的审计摘要。

授权范围和时间在创建完成后不提供普通编辑；如果范围或时间错误，教师应作废原码并创建新码，避免已经领取的设备资格被静默扩大或缩小。接收人和教师备注属于管理记录，可以单独修改。

### 3.4 单条与批量状态管理

每行左侧有复选框，表头有全选复选框。选中一条或多条后，列表顶部显示：

- 已选数量；
- 冻结；
- 恢复；
- 作废；
- 清除选择。

状态规则：

| 当前状态 | 可执行操作 | 结果 |
| --- | --- | --- |
| 有效 | 冻结、作废 | 冻结可恢复；作废永久停止 |
| 冻结 | 恢复、作废 | 恢复为有效；作废永久停止 |
| 作废 | 无 | 只读，不可恢复 |

批量操作前显示影响数量。批量作废必须再次确认，并说明不会删除记录、范围、接收人或领取历史。选中状态不适合当前动作时，服务端整体拒绝该批次并返回可操作提示，不由前端静默跳过部分记录。

## 5. HTTP 接口设计

现有创建、批量创建、列表、详情和作废端点继续沿用顶级授权码路径。

### 5.1 创建与查询

`POST /api/v1/teacher/access-codes`

- 适用于单个授权码；
- 增加 `recipient_label`、`recipient_note`；
- `grants` 支持多门当前教师自有已发布课程；
- 保留 `redeem_from`、`redeem_until`，并支持每个授权项的 `valid_from`、`valid_until`。

`POST /api/v1/teacher/access-codes/batch`

- 适用于 `count=1–100`；
- 使用批次幂等键；
- 整批共享范围、时间和接收人默认记录；
- 事务失败不留下半批授权码。

`GET /api/v1/teacher/access-codes?course_id=<course_id>`

- 只返回当前会话教师拥有的授权码；
- 课程过滤命中包含该课程的授权码，即使该码还覆盖其它课程；
- 返回完整码、状态、接收人记录、范围、时间和领取摘要；
- 不返回 `code_digest`、本机标识摘要或本机证明。

`GET /api/v1/teacher/access-codes/{access_code_id}`

- 返回单条完整管理详情；
- 包含状态摘要和经过脱敏的状态历史；
- 归属不通过时返回统一的不存在/不可用结果。

### 5.2 接收人记录

`PUT /api/v1/teacher/access-codes/{access_code_id}/recipient`

请求只包含教师侧 `recipient_label` 与 `recipient_note`。该操作不改变授权范围、时间、状态、领取记录或学生资格。

### 5.3 状态操作

`POST /api/v1/teacher/access-codes/{access_code_id}/freeze`

- 只允许有效码进入冻结；
- 重复冻结返回最终冻结状态；
- 冻结后不能建立新的领取关系，也不再贡献未来重新下载/更新资格。

`POST /api/v1/teacher/access-codes/{access_code_id}/restore`

- 只允许冻结码恢复为有效；
- 作废码不可恢复；
- 重复恢复返回最终有效状态。

`POST /api/v1/teacher/access-codes/{access_code_id}/terminate`

- 保留当前端点作为内部/兼容 API；
- 教师界面统一使用“作废授权码”；
- 只将状态转为作废，不删除任何授权记录；
- 只阻止未来首次领取、重新下载和更新，不远程删除学生已安装课程。

`POST /api/v1/teacher/access-codes/batch-actions`

请求包含：

- `access_code_ids`；
- `action: freeze | restore | terminate`；
- `idempotency_key`。

服务端在一个事务中完成归属校验、状态适用性校验、批量状态修改和审计写入。前端不得循环调用单条端点模拟批量原子动作。

### 5.4 学生接口

`POST /api/v1/student/redemptions` 和 `POST /api/v1/student/course-updates` 本轮不改路径和请求结构。它们继续通过 `AccessCode.status` 和时间规则计算未来在线资格：

- 有效码按现有课程级授权规则生效；
- 冻结码和作废码不建立新领取关系，也不贡献未来更新资格；
- 已安装在学生本机的课程不会被远程删除。

## 6. 数据模型与保留

### 6.1 `AccessCode`

保留现有安全字段：

- `code_digest`；
- `display_tail`；
- 生成者和幂等意图；
- 领取窗口；
- 状态与作废时间；
- 创建时间。

新增教师记录字段：

- `recipient_label`：接收人显示信息，可为空；
- `recipient_note`：教师备注，可为空。

状态值采用：

- `active`：有效；
- `frozen`：冻结，可恢复；
- `terminated`：作废，不可恢复。

数据库仍不保存授权码明文。授权码是一个数据库授权记录对应的可验证秘密；生成算法不是业务身份。当前实现可继续使用受保护密钥和生成意图重建完整码，后续规则模板也必须以摘要唯一约束为最终防线。

### 6.2 `GrantItem`

继续保存：

- `course_id`；
- `scope` 和范围数据；
- 授权项的现实有效时间。

创建后不允许普通编辑。一个授权码可以包含多门课程的多个授权项，但每个课程和课节必须由服务端按当前教师工作空间及已发布状态校验。

### 6.3 `Redemption`

继续保存：

- 授权码与本机标识摘要的唯一关系；
- 首次和最近领取时间；
- 成功领取时的范围摘要。

接收人记录不写入学生兑换响应，不与本机标识或学生账号关联。

### 6.4 `OperationAudit`

追加记录以下动作：

- 创建单个/批量授权码；
- 修改接收人记录；
- 冻结；
- 恢复；
- 作废；
- 批量状态操作的结果和数量。

审计只保存对象 ID、动作、操作者、结果、固定原因码、请求 ID、时间和脱敏数量/状态信息，不保存授权码原文、摘要、本机标识、证明或课程正文。

## 7. 数据流与失败恢复

### 7.1 创建

教师表单 -> 前端生成幂等键 -> 服务端根据会话校验课程归属和发布状态 -> 校验范围/时间 -> 生成候选码 -> 写入授权码、授权项、教师记录和审计 -> 提交事务 -> 返回完整码。

任一步失败都不返回可用码，不留下部分授权项或部分批次。网络超时重试同一幂等键时返回已确认结果，不创建重复记录。

### 7.2 状态变化

教师选中记录 -> 前端发起状态动作 -> 服务端重新校验教师归属和当前状态 -> 在同一事务更新状态并写审计 -> 返回更新后的记录 -> 前端刷新列表和详情。

批量操作不能静默跳过不适用状态。批量校验或写入失败时整体回滚，原有状态保持不变。

### 7.3 学生侧影响

学生领取或更新时服务端重新读取授权码状态和授权项时间。冻结/作废只影响未来在线资格；不删除 `Redemption`，不删除学生本机安装内容。

## 8. 验收范围

### 8.1 页面

1. 当前课程进入管理页后被默认选中；
2. 只能添加当前教师自己的已发布课程；
3. 可以选择整门课程或指定课节；
4. 数量可输入 `1–100`，批量结果逐条展示；
5. 接收人和备注可留空、生成后可修改；
6. 列表有逐条复选框、表头全选和批量操作条；
7. 详情能看到码、范围、接收人、时间、领取摘要和状态；
8. 作废按钮不使用“删除”语义；
9. 移动端不发生操作条、表格和详情互相覆盖。

### 8.2 后端

1. 跨教师课程、草稿课程、归档课程和不存在的课节整体拒绝；
2. 单个和批量创建都满足幂等和事务原子性；
3. 有效/冻结/作废状态转移符合矩阵，作废不可恢复；
4. 批量状态动作对混合或不适用状态明确失败，不部分执行；
5. 接收人更新不改变授权范围和学生资格；
6. 冻结/作废阻止未来领取、重新下载和更新，但不删除已安装课程；
7. 所有操作记录审计，且不泄露授权码原文或本机隐私；
8. 数据库迁移保留现有授权码和领取记录。

## 9. 后续扩展与重开条件

### 9.1 自定义生成规则

后续另立设计，方向是规则模板而非单次手工输入，例如：

- 课程名称片段；
- 序列号；
- 随机片段；
- 固定分隔符；
- 长度和字符集约束。

规则服务只负责生成候选字符串；最终由统一授权服务验证标准化结果、长度、格式和全局唯一性。规则模板不能把课程标题、接收人或其它可变信息直接当作唯一身份，也不能把原文写入普通日志。

### 9.2 重新讨论条件

- 需要全工作空间的授权码总览和分页；
- 需要恢复已作废授权码；
- 需要编辑已生效授权范围或时间；
- 需要学生账号、跨设备恢复或接收人通知；
- 需要版本级授权、课程族升级或跨独立课程兼容。
