# 节点属性弹窗紧凑布局设计

日期：2026-08-26  
状态：已实现（2026-08-27 同步代码）
范围：教师端节点属性弹窗的布局、信息层级、展示设置、结构化预览和保存交互。

## 1. 目标

把教师端节点属性弹窗从当前纵向长表单调整为桌面端优先的双栏工作区：

- 左侧编辑节点内容；
- 右侧持续显示学生端实时预览；
- 预览下方集中调整学生窗口的大小、位置和样式；
- 在常见桌面视口中尽量首屏看到编辑区、预览区和主要操作，不依赖整页滚动；
- 压缩无效留白，减少重复标题、卡片边界和分散的说明文字；
- 保留移动端可用性，窄屏时退化为上下布局。

本轮沿用已有的结构化富文本和媒体资源输入能力，不新增上传服务或自定义 CSS；重点补齐编辑器对结构化正文、节点媒体和展示设置的预览消费。

## 2. 当前实现与问题

节点弹窗由 `v1/web/teacher/src/pages/LessonPage.tsx` 中的 `NodeDialog` 负责：

- 顶部显示图标、`节点属性`、`添加/编辑交互节点` 和节点类型标签；
- `node-dialog-context` 横向放置节点类型和触发时间；
- `NodeForm` 继续纵向渲染呈现设置、标题、正文、学生端预览和题型字段；
- 弹窗通过 `max-height` 和 `overflow: auto` 处理超高内容。

`v1/web/teacher/src/components/NodeForm.tsx` 当前把以下职责混在一个纵向流中：

- `presentationHints` 的窗口大小和窗口样式；
- 标题和正文编辑；
- 学生端预览；
- 选择题、填空题、问答题的题型字段。

2026-08-27 实际实现已将编辑器与学生端预览放入桌面双栏主体。预览从当前节点草稿读取
`presentationHints`，并以 `student-node-preview-*` class 应用尺寸、位置和样式；结构化
`content` 直接渲染为标题、段落、列表、引用及节点媒体。教师端不再把预览卡片固定在右下角。

样式主要位于 `v1/web/teacher/src/index.css` 的节点弹窗区域。实施前存在较大的顶部间距、多个层级重复的标题和边界，以及预览位于正文之后的问题；实施前预览只支持 `windowSize` 和 `windowStyle`，右下角位置在插件样式中写死。上述问题已在 2026-08-27 的实现中修复，当前预览会消费完整的 `presentationHints`。

## 3. 目标布局

### 3.1 弹窗骨架

桌面端采用三段结构：

1. 紧凑头部：节点图标、节点标题、节点类型和触发时间；
2. 主体双栏：左侧编辑区，右侧预览区；
3. 底部操作栏：取消、删除节点、保存节点。

左侧编辑区包含：

- 节点类型和触发时间的紧凑元信息行；
- 标题；
- 正文内容编辑器；
- 当前节点对应的题型字段。

右侧预览区包含：

- 学生端预览标题和触发时间；
- 预览画布；
- 预览显示设置；
- `预览确认` 按钮。

### 3.2 显示设置

显示设置放在预览画布下方，不再占据弹窗顶部空间。第一版提供：

- 窗口大小：小、中、大、铺开；
- 窗口位置：左下、右下、居中；
- 窗口样式：文档、卡片。

按钮文案由“应用显示设置”改为“预览确认”。

`预览确认` 的职责是确认当前展示参数并刷新预览状态，不替代底部的 `保存节点`。底部 `保存节点` 仍是把整个节点草稿写入当前编辑状态的唯一最终动作。显示设置修改后，只有点击 `保存节点` 才会随节点草稿持久化。

展示设置本身会实时驱动预览画布；`预览确认` 只改变确认状态，不单独写服务器。随后仍需
点击 `保存节点`，再点击课节页面的 `保存草稿`，才会进入 `v1_script_drafts.content.nodes[]`。

### 3.3 信息层级

- `节点属性` 作为小型上下文标签，不与主标题争夺视觉重量；
- 主标题统一使用“添加交互节点”或“编辑交互节点”；
- 节点类型和触发时间放入同一条元信息行，避免重复大块表单；
- `呈现设置`、`核心内容`、`学生端预览` 不再全部使用同等重量的卡片标题；
- 说明文字只保留会影响操作判断的内容；
- 图标沿用现有 `NodeIcon` 和节点类型配色，统一尺寸、间距和对齐；
- 控件使用现有表单样式，避免新增一套视觉语言。

### 3.4 响应式规则

- 桌面端使用左右双栏，右侧预览有稳定的最小宽度；
- 当视口不足以容纳双栏时切换为单栏，编辑区在上、预览区在下；
- 底部操作栏保持可见，必要时在弹窗内部滚动；
- 不以缩小到不可读的字体来强行满足“一屏”；
- 预览画布和编辑器设置固定最小高度，避免内容变化导致布局跳动。

## 4. 数据与运行时变更

实施前的 `PresentationHints` 只有：

- `windowSize`
- `windowStyle`

本轮新增：

- `windowPosition: 'bottom-left' | 'bottom-right' | 'center'`

当前实现的完整展示提示为：

```ts
type PresentationHints = {
  windowSize?: 's' | 'm' | 'l' | 'overlay';
  windowStyle?: 'card' | 'document';
  windowPosition?: 'bottom-left' | 'bottom-right' | 'center';
};
```

尺寸、样式和位置仍是节点级可选提示，不改变节点身份，也不产生独立节点表。缺失或非法值
由共享 `resolvePresentationHints` 解析为安全显示值；教师预览和插件运行时共用这套规则。

默认值采用 `bottom-right`，保持现有插件行为。该字段必须同步到：

- `v1/web/shared/src/portableContent.ts` 的 TypeScript 类型；
- `v1/contracts/schemas/course-package.schema.json`；
- `v1/contracts/schemas/extension-storage.schema.json`；
- `v1/backend/app/modules/authoring_release/application_service.py` 的节点校验；
- `v1/extension/background/validate.ts` 和 `v1/extension/storage/index.ts`；
- `v1/extension/content/richText.ts` 的展示解析；
- `v1/extension/content/window.ts` 的窗口 class 组装；
- `v1/extension/content/window.css` 的位置规则；
- 教师端 `NodeForm`、节点默认值和预览 class。

兼容规则：

- 缺少 `windowPosition` 的旧节点按 `bottom-right` 解释；
- 非法位置值按拒绝处理，不静默写入课程包；
- 现有只包含大小和样式的课程包继续可读；
- `course_package` 版本提升为 `3.1.0`，表示增加向后兼容的可选展示字段；
- `extension_storage` 版本保持 `2.0.0`，因为存储根结构不变，缺少位置字段的已安装课程按右下角兼容；
- 版本清单、后端课程包版本、契约测试和发布门禁中的 `course_package` 版本引用同步更新。

## 5. 组件边界与数据流

建议将当前 `NodeForm` 拆成清晰的内部区域组件，仍由 `NodeDialog` 统一管理节点草稿：

- `NodeDialogHeader`：标题、图标、类型和时间；
- `NodeContentEditor`：标题、正文和题型字段；
- `StudentPreviewPanel`：预览画布和实时内容；
- `PreviewSettings`：大小、位置、样式和 `预览确认`；
- `NodeDialogActions`：取消、删除、保存节点。

不新增全局状态。显示设置仍通过 `onChange` 写入当前 `dialogNode`，预览从同一份节点草稿渲染，避免编辑区和预览区出现两套数据。

数据流：

```text
控件变更
  -> dialogNode.presentationHints
  -> 左侧/右侧从同一节点草稿重渲染
  -> 预览确认刷新预览确认状态
  -> 保存节点写入 LessonPage 的 nodes
  -> 保存草稿提交后端
  -> 后端校验并保存课程草稿
  -> 发布时进入课程包与插件运行时
```

教师预览的内容流也必须保持同一真源：

```text
dialogNode.content + assets
  -> 教师预览结构化渲染
  -> 图片/音频/节点视频通过 assetUrlForId 取得临时显示地址
  -> 保存时仍只写 RichPageDocument + assetId
```

## 6. 验证方案

### 6.1 前端测试

- 节点类型、时间、标题、正文和题型字段仍能正常编辑；
- 大小、位置、样式的默认值和切换值正确写入 `presentationHints`；
- 点击 `预览确认` 不会提前关闭弹窗或绕过 `保存节点`；
- 点击 `保存节点` 后，节点保留完整展示设置；
- 四类节点均能显示预览；
- 桌面端双栏和窄屏单栏均无内容遮挡。

### 6.2 契约与插件测试

- 合法三种位置通过 JSON Schema、后端和插件校验；
- 缺省位置按右下角兼容；
- 非法位置被拒绝；
- 插件实际渲染左下、右下和居中三种位置；
- 大小、位置和样式组合不会破坏铺开模式、全屏挂载和遮罩；
- 旧示例课程和现有课程包仍能读取。

### 6.3 浏览器验收

至少检查：

- 1440 x 900 或同等桌面视口：不滚动即可看到编辑区、预览区、显示设置和底部操作；
- 1024 宽度：双栏仍可读或按规则切换；
- 375 x 900：单栏可滚动，按钮和输入框不溢出；
- 预览内容与编辑内容同步；
- 预览能显示结构化标题、列表、引用、颜色、链接和已登记的图片/音频/节点视频；
- 切换窗口大小、位置和样式时画布几何与视觉状态实际变化，而不是只有按钮摘要变化；
- 点击 `预览确认` 后预览状态明确；
- 保存、取消、删除行为不回归。

## 7. 非目标与风险

本轮不处理：

- 富文本编辑器工具数量和编辑能力；
- 节点时间轴、字幕选择和拖拽交互；
- 预览播放器的真实视频接入；
- 窗口任意像素拖动；
- 移动端专属布局设计。

主要风险：

- 新增窗口位置字段会触及契约、后端和插件多处校验；
- 双栏压缩可能让题型字段变得过窄，需要在桌面端设置最小列宽；
- `overlay` 与 `center` 的语义容易混淆，需要明确：`overlay` 是大小，`center` 是位置；
- 仅更新教师端预览而不更新插件，会造成“所见不所得”，必须以插件渲染和契约测试作为验收条件。
