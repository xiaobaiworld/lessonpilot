# 连续可调互动学习窗口设计

日期：2026-08-29  
状态：已接受，待实现  
相关范围：教师端互动节点编辑器、教师端实时预览、课程包、学生插件运行时

## 1. 背景与目标

当前互动学习窗口使用有限的展示预设：窗口大小只有 `s`、`m`、`l`、`overlay`，位置只有左下、右下和居中。插件默认把缺少展示参数的节点显示为右下角小卡片。教师端虽已有学生端预览，但位置和大小仍然是离散选项。

本设计把窗口展示设置改为节点级、连续可调的配置：

- 教师在编辑互动节点时，通过宽度和高度滑块设置窗口的基础尺寸；
- 教师可以直接拖动实时预览中的窗口设置位置；
- 内容较少时窗口保持教师设定的基础尺寸；
- 内容较多时窗口可以在上限内自然增大；
- 超过上限后窗口内部滚动，不遮挡屏幕外内容；
- 修改只在编辑器内实时反映，不向已经打开的学生窗口推送；
- 保存草稿、发布课程和插件升级仍是学生端获得新展示配置的正式链路。

本轮不实现任意 CSS、窗口旋转、窗口拖动后的学生端实时同步或独立窗口配置表。

## 2. 已确认事实与约束

### 2.1 当前代码事实

- 学生端互动窗口由 `v1/extension/content/window.ts` 的 `LearningWindow` 渲染，样式由 `v1/extension/content/window.css` 提供。
- 教师端预览由 `v1/web/teacher/src/components/NodeForm.tsx` 的 `StudentNodePreview` 渲染，样式位于 `v1/web/teacher/src/index.css`。
- 共享解析函数位于 `v1/web/shared/src/portableContent.ts`，教师预览和插件运行时应继续共享展示配置解析逻辑。
- 当前草稿由 `ScriptDraft.content` 作为整份 JSON 聚合保存；现有最终保存入口为 `PUT /api/v1/teacher/lessons/{lesson_id}/draft`。
- `NodeDialog` 编辑时先维护本地 `dialogNode`，点击“保存节点”只更新页面本地节点，点击“保存草稿”才提交整份草稿。
- 发布课程后，插件通过课程更新流程下载新的不可变发布内容，内容脚本通过 background 读取已安装课程；当前运行时没有展示配置的实时网络通道。

### 2.2 产品约束

- 展示配置是互动节点的一部分，与 `content`、`interactionData` 一起组成节点语义。
- 窗口基础宽度和基础高度都可连续调整，建议范围为屏幕对应方向的 10%–66%。这两个数值是当前设计建议，后续可在人工验收中微调。
- 内容可以使实际窗口在基础尺寸之上增长，但不得突破屏幕尺寸上限；达到上限后使用内部滚动。
- 窗口位置使用连续横纵坐标，坐标值保存为百分比而不是像素。
- 不允许课程包携带任意 CSS 或脚本。

## 3. 展示配置模型

### 3.1 新配置

新版本的节点展示配置采用明确的数值对象，不再使用大小和位置的离散枚举作为新编辑器的写入格式：

```json
{
  "presentationHints": {
    "windowSize": {
      "widthPercent": 40,
      "heightPercent": 30
    },
    "windowPosition": {
      "xPercent": 50,
      "yPercent": 50
    },
    "windowStyle": "document"
  }
}
```

字段含义：

| 字段 | 范围 | 含义 |
| --- | ---: | --- |
| `widthPercent` | 10–66 | 窗口基础宽度，占视口宽度的百分比 |
| `heightPercent` | 10–66 | 窗口基础高度，占视口高度的百分比 |
| `xPercent` | 0–100 | 窗口中心点横坐标，占视口宽度的百分比 |
| `yPercent` | 0–100 | 窗口中心点纵坐标，占视口高度的百分比 |
| `windowStyle` | `card` / `document` | 现有两种视觉样式 |

默认值：

```json
{
  "widthPercent": 40,
  "heightPercent": 30,
  "xPercent": 50,
  "yPercent": 50,
  "windowStyle": "document"
}
```

### 3.2 基础尺寸和内容尺寸

配置尺寸表示窗口的基础尺寸，不是强制裁切尺寸：

```text
实际宽度 >= 基础宽度
实际高度 >= 基础高度
实际宽度 <= 最大宽度
实际高度 <= 最大高度
```

建议的运行时约束：

```text
最大宽度 <= 66vw
最大高度 <= 66vh
```

文本、选项、输入框和媒体内容较少时，窗口保持基础尺寸。内容较多时，窗口可以自然增长；达到最大高度或最大宽度后，窗口内部出现滚动条。长文本默认换行，避免内容通过不可控的最小内容宽度把窗口撑出视口。

第一版允许内容推动实际宽度和高度增长，但普通长文本默认换行，因此通常只会推动高度增长。只有内容存在不可避免的最小宽度时才允许宽度向上增长，且必须经过最大宽度限制。

### 3.3 位置和安全边界

`xPercent`、`yPercent` 表示窗口中心点。窗口尺寸变化后，运行时重新计算实际边界并把窗口限制在安全区域内：

- 左、右、上、下至少保留 16px 边距；
- 拖动或窗口尺寸变化不会使窗口完全或部分不可见；
- 进入全屏时仍以当前全屏元素的视口尺寸计算；
- 窄屏时最大宽度还必须受 `100vw - 24px` 限制，避免小屏横向溢出。

## 4. 教师端交互设计

### 4.1 实时预览

`StudentNodePreview` 继续从当前 `dialogNode` 读取展示设置。用户调整滑块或拖动窗口时：

```text
控件/拖动
  -> 更新 dialogNode.presentationHints
  -> 预览重新计算几何位置和尺寸
  -> 不请求后端
```

预览必须表现真实几何变化，不能只更新“40% / 居中”这类摘要文字。

### 4.2 控件

预览设置区提供：

- 宽度滑块：10%–66%；
- 高度滑块：10%–66%；
- 可拖动的预览窗口；
- X/Y 当前百分比显示；
- 键盘方向键微调位置；
- “重置为居中”按钮；
- 现有卡片/文档样式选择。

滑块使用数值步长实现细粒度连续调整，底层保存数字，不再保存 `s`、`m`、`l` 这类新配置枚举。控件旁同时展示百分比和当前预览区域中的近似像素值，帮助教师理解效果，但像素值不进入课程包。

### 4.3 保存边界

编辑器仍保持现有的两级保存边界：

1. “保存节点”把已验证的节点写入页面本地 `nodes`；
2. “保存草稿”通过现有草稿接口一次性提交节点内容、题型数据、展示配置、资源清单和字幕。

展示配置的控件变化不单独创建服务器历史，也不因拖动产生大量 revision。节点级展示配置接口提供局部更新能力，但当前编辑器不会在每次拖动或每次滑块变化时调用它。

## 5. 后端接口设计

### 5.1 节点展示配置接口

```http
PUT /api/v1/teacher/lessons/{lesson_id}/draft/nodes/{node_id}/presentation
```

请求：

```json
{
  "revision": 7,
  "presentationHints": {
    "windowSize": {
      "widthPercent": 40,
      "heightPercent": 30
    },
    "windowPosition": {
      "xPercent": 50,
      "yPercent": 50
    },
    "windowStyle": "document"
  }
}
```

响应：

```json
{
  "lessonId": "lesson-001",
  "nodeId": "node-001",
  "revision": 8,
  "presentationHints": {
    "windowSize": {
      "widthPercent": 40,
      "heightPercent": 30
    },
    "windowPosition": {
      "xPercent": 50,
      "yPercent": 50
    },
    "windowStyle": "document"
  }
}
```

服务端处理顺序：

```text
教师权限检查
  -> 读取 ScriptDraft
  -> 检查 revision
  -> 查找 node_id
  -> 校验窗口范围和样式
  -> 只替换 presentationHints
  -> draft revision + 1
  -> 原子提交
```

错误边界：

- `401/403`：教师会话无效或无权访问课节；
- `404`：课节、草稿或节点不存在；
- `409 REVISION_CONFLICT`：草稿已被其他页面修改；
- `422 DRAFT_NODE_PRESENTATION_INVALID`：尺寸、坐标或样式超出契约。

接口不接收任意 `width`、`height`、`left`、`top` CSS 字符串，也不接收脚本。

### 5.2 服务层边界

后端增加一个职责单一的方法，例如：

```python
update_node_presentation(
    teacher_id,
    lesson_id,
    node_id,
    revision,
    presentation_hints,
)
```

它与整份 `save_draft()` 复用同一组窗口范围校验和节点定位规则，不新建配置表，不复制发布逻辑。

## 6. 教师预览与插件运行时

### 6.1 共享解析

共享模块提供清晰的解析和限制函数：

```text
normalizePresentationHints()
clampPresentationHints()
resolvePresentationGeometry()
```

这些函数只处理结构化数据，不生成 CSS 字符串。教师端预览和插件端窗口都使用相同的默认值、范围和兼容规则。

### 6.2 教师端预览

教师端使用预览容器的宽高作为视口，按比例计算窗口尺寸：

```text
previewWidth = containerWidth * widthPercent / 100
previewHeight = containerHeight * heightPercent / 100
```

拖动结束后，将预览中的中心点反算为 `xPercent`、`yPercent`，并经过安全边界限制。

### 6.3 插件端窗口

插件端使用当前页面或全屏元素的视口尺寸计算窗口几何。窗口仍然通过 Shadow DOM 隔离 B 站页面样式，`LearningWindow` 只负责把结构化配置交给布局函数并挂载 DOM；尺寸和位置 CSS 保持少量、明确的基础规则。

当前运行中的窗口不会因为教师修改后端草稿而变化。学生必须获得新发布版本并完成课程升级，下一次窗口渲染才会读取新配置。

## 7. 兼容与版本

当前课程包使用字符串枚举，新的数值尺寸和坐标配置会改变课程包结构。需要：

- 为新配置增加课程包契约版本或明确的破坏性版本变更；
- 新插件支持旧枚举和新数值配置；
- 旧课程缺少新字段时通过显式兼容函数读取；
- 新教师编辑器只写新格式；
- 旧的 `s/m/l/overlay` 和 `bottom-left/bottom-right/center` 不在新编辑器中继续作为主要写入格式；
- 不要通过修改旧 CSS 的含义来伪装迁移，否则教师预览、旧插件和新插件会产生不同解释。

旧值的兼容读取应是明确映射，例如：

```text
s              -> 旧小卡片宽度
m              -> 旧中等宽度
l              -> 旧大宽度
bottom-left    -> 左下兼容坐标
bottom-right   -> 右下兼容坐标
center         -> (50%, 50%)
```

具体映射数值在实现和人工验收阶段冻结，不在本设计中伪造一个精确历史像素值。

## 9. 方案比较

### 方案一：宽度/高度滑块 + X/Y 滑块

优点：

- 实现最简单；
- 数据结构直接；
- 键盘和无障碍操作容易；
- 边界和测试容易覆盖。

缺点：

- 教师不如拖动预览直观；
- 需要理解 X/Y 坐标。

### 方案二：预览窗口拖动 + 宽度/高度滑块

优点：

- 所见即所得；
- 位置和尺寸都可以连续调整；
- 与当前教师端实时预览天然结合；
- 坐标百分比可以在不同屏幕适配。

缺点：

- 需要处理拖动边界和窗口尺寸变化；
- 需要补充键盘操作和无障碍说明；
- 需要教师预览和插件运行时各自按容器/视口计算几何。

本设计采用方案二。滑块负责尺寸，拖动负责位置，数字摘要负责校准和可访问性。

### 方案三：直接保存像素宽高和 left/top

优点：

- 实现直观；
- 单个屏幕上精度高。

缺点：

- 不适应不同屏幕和全屏状态；
- 容易溢出视口；
- 课程包携带设备相关数据；
- 教师很难判断不同尺寸屏幕上的效果。

不采用方案三。

## 10. 简单可读的开发原则

- 使用 `WindowSizeConfig`、`WindowPositionConfig` 等表达业务含义的类型名；
- 把范围常量集中定义，不在组件和 CSS 中各写一套；
- 用普通函数完成百分比转像素、边界限制和旧值兼容；
- 不引入通用拖拽框架或通用布局引擎，除非现有依赖无法满足基本拖动；
- 不把后端响应直接拼成 CSS；
- 不通过动态字符串拼接隐藏布局规则；
- 教师预览和插件运行时共享数据解析，但保留各自清晰的渲染 CSS；
- 关键边界写业务注释：为什么有 10%/66% 限制、为什么旧值仍可读取、为什么学生端不实时更新；
- 测试直接描述业务行为，例如“内容超过基础高度后在最大高度内增长并出现滚动”；
- 本轮不提前加入实时推送、多人协作、窗口旋转或自由 CSS。

## 11. 验收标准

### 教师端

- 宽度和高度可以连续调整，而不是只有三档；
- 预览窗口能够直接拖动；
- 拖动后 X/Y 坐标显示正确；
- 调整尺寸后预览窗口真实改变宽高；
- 内容较少时维持设定的基础尺寸；
- 内容较多时窗口在上限内增长，超过上限后内部滚动；
- 重置按钮恢复默认居中和普通尺寸；
- 取消编辑不会保存展示配置。

### 插件端

- 新配置在学生端与教师预览保持一致；
- 默认窗口为居中普通尺寸；
- 窗口不会超出可视区域；
- 全屏和普通页面均可正确计算；
- 窄屏不产生横向溢出；
- 旧课程包仍能读取；
- 发布和课程升级后，新的窗口配置可以生效；
- 已经打开的窗口不会被后端修改强行重排。

### 服务端与契约

- 合法范围通过校验；
- 小于最小值、大于最大值、非法坐标和未知字段被拒绝；
- revision 冲突返回 409，且不产生部分更新；
- 节点不存在时返回明确错误；
- 课程包、插件存储、后端校验和前端类型保持一致。
