# 学生陪伴小猫资源接入插件设计

日期：2026-08-29  
状态：第一版设计确认，进入开发  
关联决策：[`D-V1-023`](../../../doc/decisions/2026-08-29-student-companion-avatar-pack.md)  
关联产品设计：[`07-product-interaction-state.md`](../../../doc/design/v1/07-product-interaction-state.md)  

## 1. 目标与范围

本设计把已经准备好的第一版小猫资源真正接入学生插件。用户在匹配到课程的视频页面后，在右下角看到一只小猫；小猫根据学习节点的生命周期切换图片，并在需要时播放与小猫角色一致的短声音。

本次交付包含：

- 当前小猫角色包的 6 个图像状态：`focus`、`idle`、`prompt`、`correct`、`wrong`、`complete`；
- 除 `idle` 外的 5 个由 CC0 真实家猫录音裁剪出的短声音；
- 完成态独立的小鱼干叠加图和固定提示语“感谢你让我又吃到了一条小鱼。”；
- 插件构建时复制资源、运行时安全读取资源、状态切换和声音失败降级；
- 访问性、自动播放限制、重复渲染和页面销毁处理。

本次不包含：

- 波斯猫、黑猫、英短等额外猫包；
- 毛色/肤色/发色变体选择；
- 自定义头像上传页面和自定义声音上传；
- 远程下载、在线更新或按课程下发角色包。

这些内容继续记录在 `D-V1-023` 和既有开发计划中，下一次升级前必须重新确认是否纳入。

## 2. 当前系统状态

当前 `v1/extension/content/companion.ts` 用 Canvas 绘制一个固定的 `standard` 小人。它只有视频播放态 `idle`、`playing`、`paused`，没有角色资源清单，也没有声音播放接口。

当前 `CourseRuntime` 已经拥有可测试的节点生命周期：

1. 时间轴触发节点并打开学习窗口；
2. 学生提交或跳过，生成 `answered` 结果；
3. 学生关闭反馈窗口，恢复视频；
4. 所有节点通过会话状态机记录完成。

因此，本次不修改课程节点 schema 和判分逻辑，只增加一个观察者式的陪伴状态通知出口。这样角色表现不会成为答题和本地学习记录的依赖。

## 3. 资源模型

### 3.1 资源目录

源文件与运行文件分离：

| 层级 | 路径 | 用途 |
| --- | --- | --- |
| 源文件 | `docs/superpowers/assets/companion/cat-v1/source/` | 人工审稿、重新导出、未来换猫种的设计资产 |
| 插件运行资源 | `v1/extension/assets/companion/cat/v1/` | 随插件构建的 PNG、WAV 和清单 |
| 构建产物 | `v1/extension/dist/{local,production}/assets/companion/` | Chrome 实际加载的扩展资源 |
| 用户自定义资源 | 未来的 IndexedDB `companionAssets` 区域 | 不覆盖内置包，不进入本次插件包 |

角色运行资源不复用课程 `assetId` 和课程媒体 IndexedDB。课程图片/音频是课程内容，角色图片/声音是插件自身 UI，它们的更新、缓存、权限和失败边界不同。

### 3.2 清单作为单一真源

`v1/extension/assets/companion/cat/v1/manifest.json` 记录：

- `packId`、`mascotId`、`appearanceId` 和 schema 版本；
- 每个状态的图片路径、声音路径和时长；
- 每个运行文件的 SHA-256；
- 独立小鱼干叠加图和建议显示尺寸；
- 资源来源、CC0 许可与音频裁剪/标准化处理记录。

代码只通过受控的状态白名单解析清单，不接受用户输入拼接任意扩展路径。清单缺失、字段不合法或文件不可读取时回退到 `idle` 图片并静音。

## 4. 运行时数据流

```text
资源源文件
  -> 运行资源目录 + manifest.json
  -> Vite closeBundle 复制到 dist
  -> MV3 manifest 暴露 assets/companion/**
  -> content 请求受控 companionAsset 消息
  -> background 返回 chrome.runtime.getURL(...) 或拒绝
  -> StudentCompanion 渲染图片、播放一次声音
```

### 4.1 为什么由 background 提供资源 URL

角色资源是内置静态文件，不需要经过课程资源缓存，也不需要把二进制放进消息。由 background 负责把 `packId + state` 解析成扩展内部 URL，content 只得到已经过白名单限制的地址：

- 防止 content 根据任意字符串加载扩展内未知文件；
- 后续切换远程/缓存角色包时保留统一边界；
- 不把课程媒体和角色资源的生命周期混在一起。

资源访问失败只影响小猫表现，不影响 `CourseRuntime` 的暂停、作答、上报和恢复。

### 4.2 状态映射

| 运行事件 | 陪伴状态 | 声音规则 | 额外表现 |
| --- | --- | --- | --- |
| 匹配视频并建立学习会话 | `focus` | 播放一次 | 短暂提醒集中注意 |
| 正常播放/等待 | `idle` | 静音 | 维持安静陪伴 |
| 节点打开 | `prompt` | 播放一次 | 轻微弹跳，可显示提示气泡 |
| 提交后结果为 `correct` | `correct` | 播放一次 | 开心反馈 |
| 提交后结果为 `incorrect` | `wrong` | 播放一次 | 温和引导 |
| 节点完成并关闭反馈 | `complete` | 播放一次老虎庆祝声 | 小鱼干叠加 + 固定提示语 |

`correct` 和 `complete` 不合并。`correct` 是答题结果，`complete` 是节点完成并准备回到视频的生命周期反馈。一次节点只允许一次完成庆祝；同一状态的重复 render 不重新播放声音。

## 5. 陪伴组件设计

`StudentCompanion` 继续拥有右下角 A1 浮动入口、书包和视频模式按钮，但把 Canvas 绘制层替换为资源驱动的图片层：

- 主图使用 `<img>`，`alt` 描述当前学习助手；
- 小鱼干使用独立的绝对定位 `<img>`，建议显示约 32px，源文件为 64×64 RGBA；
- 提示文字使用 `textContent` 写入气泡，不把文案拼接进 HTML；
- 声音用受控的 `HTMLAudioElement`/`Audio` 播放，播放前检查全局声音开关；
- 每次状态进入只触发一次资源加载和声音播放；
- `destroy()` 清理音频、计时器、DOM 和状态，SPA 切页不残留庆祝。

组件保留对现有视频播放按钮的兼容行为；播放态不再决定角色图片，只决定视频控制文案。角色状态与视频播放状态是两个独立维度。

## 6. 设置与失败策略

第一版内置角色固定为 `cat`/当前外观；旧版本的 `standard` 只作为历史实现标识，不会被当作资源路径，当前运行时固定解析为 `cat-v1` 小猫包。声音开关作为本机学生设置，默认开启；关闭后仍显示全部图片、动画、小鱼干和文字。

失败策略：

- 图片清单或图片加载失败：尝试 `idle` 图片，再失败则显示现有安全占位表现；
- 音频清单、解码或播放失败：静音并继续运行；
- 浏览器自动播放限制：捕获 Promise rejection，不在控制台制造未处理 rejection；
- 资源消息失败或 background 重启：保留当前视觉状态或回退 `idle`，不阻断学习窗口；
- 角色资源目录不接受网络 URL；用户上传资源未来另走校验和 IndexedDB 链路。

## 7. 验收标准

自动化验收至少覆盖：

- 构建产物包含 manifest 引用的全部角色 PNG、WAV 和清单；
- manifest 暴露角色资源目录，生产包不新增无关 host permission；
- 6 个状态可以被白名单解析，缺失状态安全回退；
- 节点打开、答对、答错、完成时状态顺序正确；
- `idle` 不播放声音，同一节点重复 render 不重复庆祝；
- 声音关闭、音频播放拒绝、资源读取失败时答题仍可完成；
- 小鱼干为独立叠加图，提示语只出现一次且使用安全文本节点；
- 页面切换、全屏、关闭窗口和插件销毁后无残留监听和音频。

人工验收再确认：小猫 6 个姿态确实有差异、声音听感属于同一只小猫、右下角不遮挡 B 站控制条、小鱼尺寸足够小、答错反馈温和。
