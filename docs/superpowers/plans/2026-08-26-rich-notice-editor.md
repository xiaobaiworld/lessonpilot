# 重点标注富文本编辑器与展示设计

状态：当前实现设计（2026-08-26）

## 目标

重点标注使用一个正文编辑器完成内容编排。教师可以在同一段正文中使用强调、颜色、链接和分组排版；学生端按同一份富文本内容展示。当前产品不提供普通正文回退，也不再展示 C 方案的固定结构提示。

## 数据契约

重点标注的 `display` 只使用以下正文字段：

```ts
{
  title: string;
  richBody: string;
}
```

`richBody` 是编辑器和运行时的唯一正文来源。发布校验要求它是非空字符串，并拒绝 `display.body`，避免产生两套内容真源。

## 教师端编辑器

- 使用受控 `contenteditable` 编辑区，编辑值始终从 `richBody` 读写；
- 工具栏提供粗体、斜体、下划线、清除格式、四种主题色、分组标题、引用、项目列表、编号列表和链接；
- 输入和工具栏操作后先经过有限标签与安全链接协议清洗，再回写节点；
- 节点类型选择器复用上级节点栏的图标、名称和颜色，保持同一视觉语义；
- 空正文只在编辑器内部显示占位提示，不生成额外的兼容字段。

## 学生端展示

- 重点标注继续使用通用互动窗口和“确认并继续”操作；
- `richBody` 通过安全 DOM 构造展示，只允许编辑器支持的排版标签；
- 链接只接受 `http`、`https`、`mailto`，并补充新窗口与 `noopener/noreferrer` 属性；
- 未知标签、事件属性和不安全颜色/协议被丢弃，不执行课程内容中的脚本；
- 不再包含“先理解、再练习、最后巩固”的固定 C 方案渲染分支。

## 类型切换

切换到重点标注时，将当前题目文本作为 `richBody`；切换到题型时，将富文本转为纯文本写入题型的 `prompt`。这是类型切换时的内容迁移，不是重点标注的普通正文回退。

## 验收

- 新建重点标注只生成 `richBody`，不生成 `body`；
- 富文本正文可通过编辑器完成格式、颜色、链接和分组编辑；
- 重点标注只按富文本正文校验，空标签不能保存；
- 带 `body` 的重点标注草稿被后端拒绝；
- 学生端只渲染安全富文本，不渲染旧 C 方案结构或普通正文回退。
